## 고치는 과정에서 **새로 발견한 것 셋**

설계 단계에서 잡은 것 하나, 배선 중에 잡은 것 둘이다. 셋 다 그대로 고쳤으면 새 사고가 됐다.

### ① 코퍼스에 진짜 연락처 유출이 하나 있었다

차단을 실전 경로에 올리기 전에 888청크를 전수 통과시켜 보니 13건이 걸렸다.
12건은 우리가 붙인 `(출처: Pet Poison Helpline, S-084)` 표기 때문인 **오탐**이었다 —
그대로 올렸으면 **에틸렌글리콜·발작·호흡곤란 답변이 통째로 삭제**됐다.

나머지 1건은 오탐이 아니었다.

```
F-021-012.escalation_conditions
  '수의사·응급병원 또는 Pet Poison Helpline (855)-764-7661 에 즉시 연락'
```

`compute` 노드가 붙는 순간 `full_text` 로 나갈 값이었다. `escalation_conditions` 를
문장이 아니라 **항목 단위**로 거르기로 한 이유가 이것이다 — 문장 단위면 같은 리스트의
*"원인 물질에서 떼어놓기"*, *"구토 유도 금지"* 까지 함께 사라진다.

### ② 초콜릿 역치는 **테오브로민** 기준이지 초콜릿 질량이 아니다

`StubEngine` 에 규칙 테이블을 붙이면서 `amount_g` 를 그대로 mg/kg 으로 바꾸려 했는데,
규칙 테이블 12행의 기준이 두 종류였다.

```
양파 15-30 g/kg · 마늘 5 g/kg · 자일리톨 0.03 g/kg · 알리움 0.5%
    → 먹은 음식의 질량이 곧 역치의 단위다. 그대로 쓴다
초콜릿(테오브로민+카페인) 20 mg/kg
    → 테오브로민의 질량이다. 초콜릿 질량이 아니다
```

그대로 곱했으면 **초콜릿을 100% 테오브로민으로 계산**하는 셈이었다 — 약 1만 배 과대평가다.
안전한 쪽 오류라 눈에 안 띄지만, D-51(*"잎 무게는 독소 무게가 아니다"*)이 막은 것과 같다.

코퍼스에 다리가 있었다 — `F-034-023~025` 의 종류별 함량(베이킹 14 · 다크 5 · 밀크 2 mg/g).
그런데 **종류를 모르면 어떤 값을 골라도 우리가 만든 숫자**다. 그래서 되묻는다.
골든셋 `G-047`(*"무슨 초콜릿인지는 모르겠어요"* → `clarify`)이 기대하던 동작이 정확히 이것이다.

```
4kg 개 · 20g 섭취
  밀크   2 mg/g →  10.0 mg/kg → MONITOR
  다크   5 mg/g →  25.0 mg/kg → CALL_NOW    (임상징후 역치 20)
  베이킹 14 mg/g →  70.0 mg/kg → EMERGENCY   (중증 역치 40-50)
```

### ③ 주석이 부정확하면 그것을 강제하는 코드도 부정확해진다

`TriageConfig.max_clarify_turns` 주석에 *"계약과 반드시 일치해야 한다"* 고 적혀 있어
등호로 강제했더니 **`configs/eval.yaml` 이 깨졌다.** 평가 프로파일은 되묻기를 끄려고
일부러 `0` 으로 낮춘다 (되묻기가 섞이면 과소평가율 분모가 흔들린다 — 04 §4.1).

올바른 불변식은 **계약 상수가 천장**이다. 낮추는 것은 의도된 구성이고, 넘기는 것이 위반이다.
주석을 그대로 코드로 옮긴 것이 원인이었고, 그 자리에 정정 기록을 남겼다.

**원문을 읽고 정할 일이라 손대지 않았다.** 어느 출처를 채택할지 결정해 `note` 에 근거를 남기면 된다.
검사기에 `source_id` 를 함께 찍게 해 두었으므로 무엇을 펼쳐 볼지는 바로 보인다.

### `answered` 인데 등급이 없는 케이스 2건 (G-004 · G-021)

둘 다 `prevent` 유형이다 — *"알로에 화분을 들여도 되나"* 는 섭취 사건이 아니라
**축 B(급여·노출 가부)** 질문이고, 축 A(긴급도) 등급이 원래 없다.
계약은 `answered` 에 `triage` 를 요구하므로 셋 중 하나를 정해야 한다.

1. 등급을 적는다 (없는 판정을 만드는 것 — 권하지 않는다)
2. `prevent` 를 `refused`/별도 상태로 옮긴다
3. 계약에서 `prevent` 를 축 B 응답으로 분리한다

**등급을 지어내지 않았다.** 검사기가 이제 두 건을 이름으로 지목한다.

### 골든셋 분포 (검사기 신설)

`VISIT_SOON` 1건 · `symptom` 1건 · `prevent` 2건 — 최소 3건에 미달.
4등급 중 하나가 비면 혼동행렬이 4×4로 안 나온다. 남은 8건에서 채울 것.

### 재인덱싱이 필요하다

`Chunk` 에 `publisher`·`locator`·`fact_ids` 를 넣었으므로 **`make index` 를 다시 돌려야**
검색 결과로 `Citation` 을 만들 수 있다. 지금 인덱스로는 `publisher` 가 빈 문자열이다.
문장화도 함께 바뀌었으니(조사·`|`·기준 표기) 어차피 재구축이 맞다.

## PC 에 직접 해야 하는 것 하나 — `Makefile`

`Makefile` 은 보호 파일이라 원격으로 못 쓴다. **전체를 아래로 교체**한다.
(들여쓰기가 **탭**이어야 한다. VS Code 오른쪽 아래가 `Spaces: 4` 로 보이면 눌러서 `Tab Size` → `Indent Using Tabs` 로 바꾼다.)

바뀐 것은 넷이다 — `initdb` 신설 · `rules` 신설 · **`eval` 신설** · `LINT_PATHS` 에 `eval/` 추가.

```make
.PHONY: help install initdb serve test todo lint fmt verify facts golden eval rules index train up db down docker clean

help:            ## 이 목록
	@grep -E '^[a-z-]+:.*?##' $(MAKEFILE_LIST) | awk 'BEGIN{FS=":.*?## "}{printf "  \033[36m%-10s\033[0m %s\n", $$1, $$2}'

initdb:          ## DB 스키마 생성 (DATABASE_URL 필요). 기동 시 자동 실행하지 않는다
	python -m pettriage.app.database

install:         ## 개발 환경 설치 (GPU 없이 API·테스트까지)
	pip install -e '.[api,rag,ingest,dev]' -c constraints.txt
	@git rev-parse --git-dir >/dev/null 2>&1 \
		&& pre-commit install \
		|| echo "· git 저장소가 아니라 pre-commit 훅은 건너뛴다 (설치는 완료)"

serve:           ## FastAPI + 데모 프론트 → http://127.0.0.1:8000
	uvicorn pettriage.app.main:app --reload --app-dir src

test:            ## 안전 장치 회귀 테스트
	pytest

	ruff check $(LINT_PATHS)
	ruff format --check $(LINT_PATHS)

fmt:             ## 자동 정리
	ruff check --fix $(LINT_PATHS)
	ruff format $(LINT_PATHS)

	python scripts/verify_corpus.py

	python scripts/check_facts.py

	python scripts/check_goldenset.py

rules:           ## 사실 표 → 규칙 테이블 재생성 (생성물이다. 손으로 고치지 않는다)
	python scripts/build_rule_table.py --write

# 산출물 ④의 실행 진입점. 예전에는 Makefile 에 없어서 CI 에 배선할 자리도 없었다.
# 게이트 기본값은 보수적으로 둔다 — 분모가 작으면 비율이 무의미하다.
eval:            ## 골든셋 평가 (정확도 + 지연). 게이트 포함
	python eval/harness/run_eval.py --json eval/reports/latest.json \

	docker compose up --build

	docker compose up -d db

down:            ## 컨테이너 정리
	docker compose down

docker:          ## API 이미지만 빌드
	docker build -t pettriage-api .

clean:           ## 캐시·빌드 산출물 삭제
	find . -type d -name __pycache__ -exec rm -rf {} + 2>/dev/null || true
```
