## 이 폴더가 있는 이유

00~07 은 **무엇을 만들 것인가**를 적는다. 여기는 **만든 것이 실제로 그렇게 도는가**를 적는다.

두 가지가 다르다는 것을 1차 검토가 실증했다. 문서에 *"하향 금지 게이트가 D-09 를 강제한다"* 고
적혀 있었고 `apply_gate()` 의 산술도 옳았지만, **그 결과를 담는 계약이 덮어쓰기를 허용**하고 있었다.
설계 문서만 읽어서는 알 수 없고, 테스트도 269건이 전부 초록이었다.

그래서 이 폴더의 문서는 **전부 재현 코드와 함께** 적는다. 재현하지 못한 것은 그렇게 표시한다.

## 1차 검토가 남긴 것 — 다음 회차에도 쓸 규율

> **1차 검토가 놓친 것 4건**(37~40)은 수정본을 **검증하다** 나왔다 — 마지막 하나는
> **PR 의 CI 가 잡아 줬다.** 검토보고 끝에 따로 붙였다. 검토 문서가 스스로 완전하다고
> 주장하면 그것도 거짓 초록이다. 거기서 **D-58 · D-59 · P5 · P6** 이 나왔다.
>
> 33번 항목은 **틀려서 정정했다** — 없다고 적은 파일 넷이 실재했다.

**수정 원칙 5가지**

| | 원칙 | 이번에 적용된 곳 |
|---|---|---|
| **P1** | **강제는 우회 불가능한 지점에 둔다** — 호출부가 아니라 타입·계약·주입 (D-40) | 연락처 차단 · 게이트 하향 금지 · 다이어리 소유자 |
| **P2** | **한 개념은 한 곳에서만 정의한다** — 두 곳에 적으면 반드시 어긋난다 | 계산 가능 단위 · 등급 배지 · bcrypt 상한 · 고지 문구 |
| **P3** | **모르면 만들지 않는다** — 기본값을 채우는 대신 절을 생략한다 (D-38 · D-51) | 문장화 기준 · 빈 필터 · 초콜릿 종류 |
| **P4** | **고치기 전에 그 동작을 고정한 테스트부터 본다** | 틀린 동작을 정답으로 박아둔 테스트 **5건** |
| **P5** | **검사기는 그 계층이 통제하는 것만 판정한다** (D-58) | 후속 논의에서 추가. 같은 형태가 **네 번** 나왔고 **네 번째는 고치던 중에 만든 것**이었다 |
| **P6** | **환경이 답을 만들고 있으면 그 답은 우리 것이 아니다** | PR CI 에서 추가. 인증 상태 코드를 `HTTPBearer` 가 정하고 있어 **로컬 401 · CI 403** 이었다 (40번) |

**또 오류를 만들지 않기 위한 규율 3가지**

1. 수정마다 **"지금 실패해야 하는 테스트"를 먼저 쓴다.** 통과하면 그 수정은 아무것도 안 한 것이다
2. **원본 CSV 를 건드리지 않는다.** 문장화·검사의 결함은 문장화·검사에서 고친다.
   데이터를 고쳐 맞추면 **출처와 어긋난 표가 남는다**
3. 매 수정 후 **전량**을 돌린다. 실측 숫자가 바뀌면 그 자리에서 안다
