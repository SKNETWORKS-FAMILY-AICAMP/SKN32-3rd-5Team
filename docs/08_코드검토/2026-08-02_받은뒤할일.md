두 가지가 **커밋에 안 들어가기** 때문이다.

| | 무엇 | 왜 |
|---|---|---|
| `.chroma/` | 벡터 인덱스 888청크 | `.gitignore` — 각자 만든다. **D-53: 벡터DB는 원본이 아니라 인덱스다** |
| `.venv/` | 설치된 패키지 | 〃 |

그리고 이번 변경이 **청크의 내용과 메타를 둘 다 바꿨다.**

- `Chunk` 에 `publisher`·`locator`·`fact_ids` 추가 — 없으면 검색 결과로 근거를 만들 수 없다
- 문장화 수정 — `체중 1kg당` 왜곡 2건 · `|` 누출 18건 · 조사 173건

**즉 예전 인덱스를 그대로 쓰면 코드는 새것인데 데이터가 옛것이다.**

## 순서 (3단계 · 처음이면 약 5분 + 모델 내려받기)

### 1. 받고 설치

```cmd
cd /d <저장소 경로>
git checkout main
git pull
.venv\Scripts\pip install -e ".[api,rag,ingest,dev]" -c constraints.txt
```

`-c constraints.txt` 를 **꼭 붙인다.** 이번에 실제로 겪은 일이다 —
버전이 어긋난 환경에서 `ruff` 가 `UP038` 을 못 잡아 **한 사람만 초록**이었다.

DB(회원가입·프로필)까지 쓸 사람은 `[db]` 도 넣는다.

```cmd
.venv\Scripts\pip install -e ".[api,rag,ingest,dev,db]" -c constraints.txt
```

### 2. 인덱스 재구축 — **이걸 빼먹으면 안 된다**

```cmd
.venv\Scripts\python scripts\build_index.py --store chroma
```

- 처음이면 `bge-m3` **약 2.2GB** 를 내려받는다. 적재 자체는 약 **3분**
- 끝에 `✓ 전체 통과` 가 나오면 정상

`✗` 가 나오면 아래 §무엇이 실패인가 를 본다. **모든 `✗` 가 문제인 것은 아니다.**

| `ruff check` | `All checks passed!` | |

## 무엇이 실패인가 — `build_index` 출력 읽는 법

이번에 **판정하는 것과 보고하는 것을 갈랐다** (D-58: *검사기는 그 계층이 통제하는 것만 판정한다*).

### 판정한다 — `✗` 면 고쳐야 한다

| 구역 | 무엇을 본다 |
|---|---|
| `검색 점검` | 기대한 청크가 상위 `top_k` 안에 있는가 (`recall@k`) · 1위가 임계값을 넘는가 |
| `score_threshold` | `0.50` 아래로 내려갔는가 (D-46 이 정한 하한) |

### 판정하지 않는다 — **`✗` 가 아니라 `·` 로 나온다. 읽기만 한다**

| 구역 | 무엇을 말하나 |
|---|---|
| `음성 점검` | 근거 없는 질의의 점수. **높아도 실패가 아니다** |
| `증상 질의 모호도` | 증상만 준 질의가 몇 종으로 흩어지나 (D-49) |
| `물질 서술 질의` | 서술만 준 질의가 물질을 특정하나 (D-49 후속) |

**음성 점검이 왜 판정하지 않나** — D-46 이 실측으로 확인했다.

```
근거 있음   0.547 ~ 0.733
근거 없음   0.494 ~ 0.659      ← 겹친다
```

어떤 임계값도 둘을 가르지 못한다. 거절은 ①`classify_intent`(범위밖)와
④`verify_grounding`(근거없음)이 만들지 **유사도 점수가 만들지 않는다.**
예전에는 이 구역이 판정을 해서 `make index` 가 **상수로 빨간불**이었다.

### `기대 … 후보 안 N건` 줄

```
✓ '앵무새 앞에서 프라이팬을 태웠어요'
    1위 0.531 · 고열(hyperthermia, 과열) (S-092)
    기대 'PTFE' 후보 안 2건  (② 슬롯 확장 **전** 기준)
      3/5위 0.519 · S-071 · PTFE(폴리테트라플루오로에틸렌) 과열 흄
      5/5위 0.502 · S-093 · PTFE(테플론) 흄
      ⚠ 마지막이 5/5위 — 자료가 늘거나 중복이 접히면 후보에서 빠진다
```

**진단용이다. 판정하지 않는다.** 순위는 검색의 계약이 아니다 — `retrieve` 는
후보 집합 전체를 넘기고 그 뒤 노드가 상위 `k` 를 **전부** 읽는다 (D-58).

이 줄이 있는 이유는 **문자열 하나에 걸리는 청크의 내용이 천차만별**이기 때문이다.
`PTFE` 계열 6건 중 3건은 등급도 증상도 없다. `recall@k` 는 아무거나 하나만 들어와도
통과하므로, **위협을 말하는 청크가 들어왔는지는 사람이 봐야 한다.**

`⚠` 는 경고이지 실패가 아니다.

## DB 를 쓰는 사람만

스키마 생성이 **기동 시 자동으로 되지 않는다.** 운영 DB 에 조용히 테이블이 생기면 안 되므로 명시적 조작으로 둔다.

```cmd
.venv\Scripts\python -m pettriage.app.database
```

`DATABASE_URL` 이 없으면 알려주고 종료한다. 예전에는 이 진입점이 아예 없어서
빈 DB 로 서버를 띄우면 회원가입이 **500** 으로 터졌다.

그리고 **D-59 가 새로 정한 것** — 물질 동정은 **생성이 아니라 533종 폐쇄 목록에서의 선택**이다.
