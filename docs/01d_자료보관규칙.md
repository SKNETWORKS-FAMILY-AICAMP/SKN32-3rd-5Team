## 1. 두 가지 원칙

> **① `raw/`·`snapshot/` 안의 파일은 절대 수정하지 않는다.**
> **② 작업용 보관과 제출용 배포를 분리한다.** (D-29)

①은 재현성과 출처 검증의 근거다. 정제·변환 결과는 반드시 다른 디렉터리에 쓴다.
②는 저작권 문제다. 검증·재현을 위해 **팀 내부에 원문을 두는 것**과, 제출물에 원문을 담아 **배포하는 것**은 다른 행위다.

```
data/
├── README.md                ← 이 파일
├── MANIFEST.csv             ← 원본 대장 (팀이 전달한 파일)
├── SNAPSHOT_MANIFEST.csv    ← 스냅샷 대장 (웹·PDF 텍스트 추출본)
├── SOURCES_CITED.csv        ← 제출물에 원문을 담지 않는 출처의 인용 정보
├── DELETION_LOG.csv         ← 삭제 이력 (해시·약관 원문·판정 근거)
├── raw/                     ← 원본 바이너리 (불변)
│   └── S-0xx_<슬러그>/
├── reference/               ← 팀 내부 산출물 (라이선스 확인표 등)
├── snapshot/                ← 웹·PDF 텍스트 추출본 (불변)
│   ├── bird/  cat/  dog/  mammal/  all/
├── extracted/               ← 텍스트 추출 결과
├── structured/              ← 정규화 CSV / JSONL
└── indexed/                 ← 문장화 청크 · 적재 스크립트 입력
```

`raw·snapshot → extracted → structured → indexed` 처리 단계는 `01_데이터-수집및전처리.md`의 방침을 따른다.

## 2. 작업용 / 제출용 분리 (D-29)

| | **작업용** `data_work_*.zip` | **제출용** `data_submit_*.zip` |
|---|---|---|
| 범위 | 전량 (원본 6 + 내부산출물 4 + 스냅샷 42) | 배포 가능분만 |
| 목적 | 검증 · 재현 · 인덱싱 | 과제 제출 |
| 공개 | **팀 내부 한정. 외부 배포 금지** | 제출 가능 |
| 나머지 출처 | — | 원문 대신 `SOURCES_CITED.csv` (출처·URL·접근일·인용 사실) |

### 2.1 제출용 포함 기준

원문을 제출물에 담는 것은 **다음 중 하나에 해당할 때만** 허용한다.

- 원장 `usability` = **A 자유이용**
- 명시적 오픈 라이선스 — **CC BY** 계열
- **정부·공공 간행물** 중 인용·재사용이 명시된 것 (공공누리, 보도자료, 정부 발간 데이터)
- 팀이 직접 만든 **내부 산출물** (`reference/`)

Tier 2·3 기관·상업 사이트 콘텐츠, 오픈 라이선스가 없는 학술지 PDF는 **작업용에만 둔다.**

### 2.2 제외된 출처를 다루는 방법

원문을 담지 않는다고 근거를 숨기는 것이 아니다. `SOURCES_CITED.csv`에
`source_id · 제목 · 발행처 · URL · 접근일 · 추출한 사실의 성격`을 남기고,
본문에서는 **사실을 추출·문장화하여 출처 표기와 함께** 사용한다 (D-28).

> **작성한 원칙**: 원문을 옮기지 않는다. 사실을 옮기고 출처를 밝힌다.

## 3. 폴더 명명 규칙

```
raw/<source_id>_<영문-슬러그>/<파일명>
예) raw/S-034_frontiers-household-food-toxic/fvets-2016-00026.pdf

snapshot/<종>/<source_id>_<영문-슬러그>.md
예) snapshot/bird/S-005_unsafe-foods-for-birds.md
```

- `source_id`는 **`자료수집원장.xlsx` 의 `source_id`와 반드시 일치**시킨다
  → 2026-07-30, 이 규칙을 어긴 2건(S-063→**S-061**, S-068→**S-067**)을 정정했다
- 파일명은 **영문·숫자·하이픈**만 사용한다 (경로 문제 방지)
- 인코딩은 **UTF-8**

### 3.1 스냅샷의 종 분류

`04_테스트-평가계획.md`가 **종별 분리 보고**를 요구하므로 종을 1차 축으로 둔다.

## 4. 스냅샷의 한계 — 반드시 읽을 것

스냅샷은 **원문 바이너리가 아니라 텍스트 추출본**이다. 각 파일 front-matter의
`capture: WebFetch 텍스트 추출` 표기가 이를 뜻한다. 품질을 5등급으로 판정해
`SNAPSHOT_MANIFEST.csv`의 `quality` 컬럼에 기록했다.

| 등급 | 뜻 | 건수 | 적재 가능 |
|---|---|---|---|
| **완전** | 원문 내용이 온전히 추출됨 | 30 | O |
| **부분** | 목록·표가 중간에서 절단됨 | 4 | 재수집 후 |
| **요약** | 추출기가 축약함 — 원문 표현 아님 | 5 | **사실 인용 금지** |
| **빈약** | 원문 자체에 내용이 거의 없음 | 2 | X |
| **부적합** | 자료 성격이 목록과 다름 | 1 | X |

> 2026-07-30 삭제(§7.5)로 55건 → **42건**이 되었다.

> **`요약` 등급을 원문 인용의 근거로 쓰지 않는다.**
> 축약된 문장을 원문으로 오인하면 그 자체가 환각의 출처가 된다.
> 이 프로젝트가 막으려는 실패를 데이터 단계에서 재현하는 셈이다.

개별 경고는 `SNAPSHOT_MANIFEST.csv`의 `notes`에 있다. 특히 **S-053**은 표 추출 오류가 의심되어
파일 안에 주석으로 표시했다 — 해당 수치를 사실로 적재하지 않는다.

## 5. 파일을 추가할 때

1. `raw/<source_id>_<슬러그>/` 또는 `snapshot/<종>/`에 넣는다
2. **해당 MANIFEST에 행을 추가**한다 — `source_id` · 원본명 · 수집자 · 수신일 · 형식 · 규모 · **해시** · **라이선스**
3. `자료수집원장.xlsx`의 해당 행에 `snapshot_path`를 기입하고 `status`를 갱신한다
4. **제출용 포함 여부(`submit_ok`)를 판정**한다 (§2.1)

> **라이선스 칸을 비워두지 않는다.** 나중에는 복원할 수 없다.

## 6. 보관 대상이 아닌 것

- 재배포 사이트 경유 자료 (Scribd 등) — 원 출처본으로 대체
- 원장 `usability` **D 제외** 판정분 (AI 생성 의심·출처 불명 등 15건)
- **이용약관에 AI 학습 금지 조항이 있는 자료** (D-33·D-37) — 2026-07-30 **15건 삭제** (§7.5)
- 구독·유료 접근이 필요한 자료 (D-32) — 구독 없이는 검증 불가 = 재현성 요건 탈락
- 개인정보가 포함된 자료
