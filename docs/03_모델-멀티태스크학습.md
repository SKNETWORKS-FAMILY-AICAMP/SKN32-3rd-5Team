## 1. 개요 — sLLM의 역할

과제 추가 요건은 *"하나의 sLLM이 다양한 멀티태스크를 함께 수행하도록 파인튜닝"* 이다.

본 프로젝트에서 sLLM은 **최종 답변 생성자가 아니라 RAG 파이프라인의 보조 처리 담당**이다.

> **지식은 RAG로, 태스크 수행 능력은 파인튜닝으로**

이 구도가 주는 이점

- 지식을 가중치에 넣지 않으므로 **환각과 갱신 불가 문제를 회피**
- 매 질의마다 대형 모델을 여러 번 호출하지 않아 **비용·지연 절감**
- **파인튜닝이 실패해도 대형 LLM 폴백으로 시스템은 동작** (리스크 격리)

### 1.1 태스크 선정 원칙

> **파이프라인이 실제로 필요로 하는 태스크만 고른다.**

억지로 채운 태스크는 "왜 하는가"에 답할 수 없다.
반대로 *"이 노드가 없으면 성능이 이만큼 떨어진다"* 를 실험으로 보이면 그 자체가 근거가 된다.

## 2. 채택 태스크

| # | 태스크 | 파이프라인 역할 | 출력 형태 | 출력 길이 |
|---|---|---|---|---|
| ① | **의도·위험 분류** | 중독/증상/영양/일반 × 물질 카테고리 × 위험도 × **종(개·고양이·앵무새)** (다중 라벨). 관찰 지표 라벨은 종별 분기 | 라벨 | 매우 짧음 |
| ② | **슬롯 추출** | 질문·일일 기록에서 종·품종·체중·연령·물질·섭취량·경과시간·증상 추출. 결측 시 되묻기 유발 | 구조화 (JSON) | 짧음 |
| ③ | **컨텍스트 압축 요약** | 검색 청크 압축 / 누적 기록 → 기간 리포트 | 문단 | 중간~김 |
| ④ | **근거 검증 (환각 판정)** | 답변 문장별 `근거있음/근거없음/모순` 판정 | 라벨 + 스팬 | 짧음 |
| ⑤ | **평이화** | 수의학 용어 → 보호자가 이해하는 언어 | 문단 | 김 |
| ⑥ | **번역** *(조건부)* | 영문 원자료 → 한국어 | 문단 | 김 |

### 2.1 ④가 핵심이다

과제 목표 1번(환각 방지)을 **파인튜닝 모델이 직접 담당**하게 되어, RAG와 파인튜닝이 같은 목표를 향한다.
기술적으로는 NLI(자연어 추론) 태스크에 해당한다.

### 2.2 ②는 이 도메인에서 상시 기능이다

질문 한 건에서 슬롯을 뽑는 데 그치지 않고, **매일 유입되는 자유서술 브이로그 기록을 구조화**한다.
학습 데이터가 자연스럽게 대량 확보되며, **결측 슬롯 되묻기는 시연의 핵심 장면**이 된다.

특히 **종(species) 슬롯은 필수**다. 확인되지 않으면 파이프라인이 진행되지 않는다 (02 §9).

### 2.3 ⑥ 번역의 조건부 채택

수집 자료의 **약 90%가 영문**임이 확인되어 채택 조건이 충족되었다 (01 §4.3).

| 선택지 | 내용 |
|---|---|
| 채택 | ⑥을 태스크에 포함하고, cross-lingual 전략 (a) 사전 번역 인덱싱과 연계 |
| 미채택 | 다국어 임베딩(b)만으로 cross-lingual 검색을 처리하고 ⑤만 유지 |

> **현재 상태: 채택 권고 / 최종 결정 대기.**
> 결정 기준은 01 §8의 cross-lingual 예비 실험 결과다.
> 채택 시 태스크가 6개가 되어 학습 부하와 태스크 간섭이 커지므로, **⑥ 추가 전후 성능 비교**를 실험 항목에 포함한다.

## 3. 출력 길이를 의도적으로 섞는다

짧은 출력 태스크만 고르면 멀티태스크 학습이 너무 쉽게 끝나고,
*"통합의 어려움이 무엇이었나"* 에 답할 근거가 사라진다.

| 출력 길이 | 태스크 | 학습상 특성 |
|---|---|---|
| 매우 짧음 | ① 분류, ④ 검증 | loss 기여 작음, 빠르게 수렴 |
| 짧음 | ② 슬롯 추출 | 구조화 출력 — **형식 준수가 관건** |
| 중간~김 | ③ 요약, ⑤ 평이화, ⑥ 번역 | **loss 지배 → 샘플링 비율 조정 필요** |

길이가 다른 태스크를 섞어야 **태스크 간섭·loss 불균형**이라는 실제 논점이 발생하고,
그 해결 과정이 보고서의 내용이 된다.

## 4. 학습 데이터 생성

RAG 코퍼스와 가상 반려동물 기록에서 각 태스크 데이터를 **파생**시킨다.
핵심 구도는 **distillation** — 대형 LLM으로 라벨을 만들고 sLLM에 증류한다.

| 태스크 | 생성 방식 | 규모 목표 | 난이도 |
|---|---|---|---|
| ① 분류 | 보호자 질의 생성 + 템플릿 증강 → 대형 LLM 라벨링 → 사람 검수 | 2,000~5,000 | 낮음 |
| ② 슬롯 추출 | 자유서술 기록·질의 생성 → 슬롯 JSON 라벨링. **결측 케이스를 의도적으로 포함** | 3,000~5,000 | 중 |
| ③ 요약 | (검색 청크 + 질문) → 압축 요약 / (기록 N일치) → 기간 리포트 | 2,000~3,000 | 중 |
| ④ 검증 | 정답 답변(positive) + **의도적 왜곡 답변(negative)** 생성 | 3,000~5,000 | 중 |
| ⑤ 평이화 | 수의학 용어·설명문 → 보호자 언어 변환 쌍 | 2,000~3,000 | 중 |
| ⑥ 번역 *(조건부)* | 영문 원자료 문단 ↔ 한국어. **용어집 기반 후처리** | 3,000~5,000 | 중 |

### 4.1 종별 데이터 균형

앵무새 자료는 개·고양이보다 분량이 적을 가능성이 높다.

- 태스크별 학습 데이터에 **종별 최소 비중을 배정**한다
- **종별 성능을 반드시 분리 보고**한다 (전체 평균만 보면 조류 성능 저하가 가려진다)
- 소수 클래스 대응(오버샘플링 / 손실 가중) 실험을 추가 검토한다

### 4.2 ④ 음성 샘플 설계가 관건

왜곡 유형을 미리 분류해서 생성하면 이후 오류 분석까지 연결된다.

| 왜곡 유형 | 예시 |
|---|---|
| 수치 변경 | 독성 임계 용량, 권장 급여량 왜곡 |
| 조건 누락 | 종별 차이·예외 규정 삭제 |
| 없는 내용 추가 | 문서에 없는 처치법 생성 |
| **종 혼동** | 개 기준을 고양이에, **포유류 기준을 조류에** 적용 |
| **단위 혼동** | kg 기준을 g 단위 개체(조류)에 그대로 적용 |

> **종 혼동은 이 도메인에서 가장 위험한 왜곡 유형**이며, 특히 **포유류 ↔ 조류 혼동**이 치명적이다.
> 생리 구조가 달라 기준값을 그대로 적용할 수 없으므로 음성 샘플에 반드시 포함한다.

### 4.3 검수 원칙

- 대형 LLM 라벨을 그대로 쓰지 않고 **사람 검수를 거친다** (특히 ①·④)
- 검수 샘플링 비율과 수정률을 기록한다 → 데이터 품질의 근거가 된다

## 5. instruction 템플릿 통일

태스크 태그가 없으면 모델이 수행할 작업을 구분하지 못한다.

```
### Task: classify | extract | summarize | verify | simplify | translate
### Input: ...
### Output: ...
```

- ②는 출력이 JSON이므로 **스키마를 프롬프트에 고정**하고 파싱 실패율을 관리한다
- ④는 문장 단위 판정이므로 입력에 `[문장 i]` 인덱스를 부여한다

## 6. 학습 방식

| 항목 | 설정 |
|---|---|
| 베이스 모델 | **`Qwen/Qwen3-4B`** (D-42). ⚠️ `configs/default.yaml` 의 `model.revision` 을 **학습 착수 시 채운다** — 비워두면 재현이 깨진다 |
| 스택 | **HF `transformers` + `peft` + `trl`** (D-42). Unsloth 미채택 — 래퍼 계층이 늘면 재현 설명이 어려워진다 |
| 방식 | **QLoRA 4bit (NF4, double quant, bf16 compute)** — 16GB VRAM에 들어간다 |
| LoRA | r=16 · alpha=32 · dropout=0.05 — `configs/default.yaml` `train.lora` |
| 대상 모듈 | attention + MLP projection 7종 (`q,k,v,o,gate,up,down_proj`) |
| loss | **프롬프트 구간 마스킹** |
| packing | 사용 시 **태스크 혼입 방지** |
| 시드 | 고정 (`train.seed=42`, 재현성) |
| 태스크 혼합 | `train.task_mix` — ④ 근거 검증 0.3 최대 (D-05). **04 E4의 조작 변수** |

> **설정은 코드가 아니라 `configs/*.yaml` 에 있다 (D-41).**
> 실험 보고 시 이 파일과 `constraints.txt` 의 커밋 해시를 함께 적으면 재현이 성립한다 (04 §8).
>
> ```bash
> PETTRIAGE_PROFILE=train make train
> ```
>
> 학습 진입 시 **골든셋 누수 검사**가 먼저 돈다 — 학습셋과 평가셋 입력이 겹치면
> 학습을 시작하지 않고 중단한다. 섞이면 04 평가 전체가 무의미해진다.

**출력 형식 관리**: ②의 **JSON 파싱 성공률**은 성능 지표만큼 중요하다. 실패 시 폴백(대형 LLM) 경로를 둔다.

## 7. 실험 계획

| # | 실험 | 목적 |
|---|---|---|
| **1** | **단일 어댑터 vs 태스크별 어댑터 N개** | 공지 취지는 단일이나, 비교군이 있어야 **"통합의 대가"를 정량화**할 수 있음. **보고서의 핵심 실험** |
| **2** | **태스크 샘플링 비율** | 균등 비율 vs 길이 보정 비율. loss 불균형 해소 여부 확인 |
| **3** | **파국적 망각 검증** | 일반 instruct 데이터 5~10% 혼입 여부에 따른 베이스 능력 유지 비교 |
| 4 | 종별 성능 및 소수 클래스 대응 | 오버샘플링 / 손실 가중 적용 전후 조류 성능 비교 |
| 5 | ⑥ 번역 추가 전후 | 태스크 6개 구성의 간섭 정도 측정 (⑥ 채택 시) |

### 7.1 최종 비교 구성

평가 결과는 04 문서의 핵심 비교표로 통합된다.

| 구성 | 설명 |
|---|---|
| A | 베이스 sLLM 프롬프팅 (파인튜닝 없음) |
| B | 태스크별 개별 파인튜닝 (어댑터 N개) |
| **C** | **멀티태스크 단일 파인튜닝** ← 본 프로젝트 |
| D | 대형 LLM 프롬프팅 (성능 상한선) |

> **C가 D에 얼마나 근접하면서 비용을 얼마나 줄였는가** — 이것이 프로젝트의 결론 문장이 된다.

## 8. 리스크

| 리스크 | 대응 |
|---|---|
| **태스크 간섭** | 통합 시 개별 대비 성능 하락은 정상 현상. 숨기지 말고 **"통합의 대가"로 정량 보고** → 오히려 좋은 보고서 |
| **loss 불균형** | 실험 2로 대응. 프롬프트 loss 마스킹 병행 |
| **파국적 망각** | 실험 3으로 검증. 일반 instruct 데이터 혼입 |
| **JSON 형식 붕괴 (②)** | 파싱 성공률 지표화, 대형 LLM 폴백 |
| **종별 불균형** | 실험 4, 종별 분리 보고 |
| **파인튜닝 실패** | **대형 LLM 폴백 경로 유지** → 시연 가능한 시스템은 항상 남는다 |
| **GPU 자원 부족** | 확보 방안 확정 필요 (9장) |
| **범위 폭증** | ① 분류 → ④ 검증 → ③ 요약 → ②⑤⑥ 순 **단계적 완성**. 분류만 붙어도 시스템은 동작 |
