## 1. 지금 무엇이 남았나

### 🔴 임계 경로는 **그래프 노드 하나뿐**이다

```
필수 산출물 4종
  ① 수집 데이터 · 전처리 문서      ✅ 사실 표 888행 · 45출처 · 문서 8종
  ② 시스템 아키텍처                ✅ 02 + 결정 43건 (D-01~D-49)
  ③ RAG 구현 코드                  ❌  ← 노드 11개 함수가 아직 비어 있다
  ④ 테스트 계획 및 결과 보고서      ❌  ← ③이 안 돌면 평가를 못 돌린다
```

**③과 ④가 같은 문제다.** 파이프라인이 안 돌면 지표가 안 나오고, 지표가 없으면
보고서에 쓸 것이 없다. **다른 무엇보다 여기가 먼저다.**

### 다만 **밑바닥부터 쓰는 것이 아니다**

노드가 쓸 부품은 이미 다 있고 테스트도 붙어 있다. **노드는 그것을 엮는 껍데기다.**

| 부품 | 무엇을 해 주나 |
|---|---|
| `triage/gate.py` | `apply_gate()` — 하향 금지 병합 (D-09). **직접 `max()` 를 쓰지 않는다** |
| `compute/rules.py` | `computable_for()` · `has_quantitative()` — 규칙 테이블 조회 (D-16) |
| `retrieval/store.py` | `search` · `filter_by_threshold` · `dedupe_by_substance` · `to_chroma_where` |
| `safety/contacts.py` | `scrub_contacts()` — 출력 직전 연락처 차단 (D-47) |
| `models/prompts.py` | `build_messages(task, input)` — 태스크 5종 프롬프트 |
| `models/serving/` | `LLMClient` 프로토콜 + `LocalQwen` · `API` · **`Echo`** |
| `app/contracts.py` | `Slots` · `TriageResult` · `Citation` — 계약 |

### 🟢 **모델 없이 지금 한 바퀴 돌릴 수 있다**

```python
class EchoClient:
    """테스트용. 모델 없이 그래프·계약을 돌린다."""
    def run(self, task, user_input, *, max_tokens=512) -> str: ...
```

태스크별 응답을 미리 넣어 두면 **파인튜닝을 기다리지 않고 파이프라인 전체가 돈다.**
`LLMClient` 프로토콜 뒤라 나중에 `LocalQwenClient` 로 바꾸는 것은 `deps.py` 한 줄이다.

> **오늘 목표는 "노드 11개 구현"이 아니라 "Echo 로 질의 하나가 답까지 가게 하기" 다.**
> 그게 되면 산출물 ③이 서고, 실제 LLM 을 끼우는 것은 **교체 작업**이 된다.
> 학습이 늦어져도 시연과 평가 구조는 살아 있다 (D-21 과 같은 판단).

## 1.5 그래프 노드 분담 — **이것부터 정한다**

11개 함수 · 7파일. `pytest -m todo` 19건이 완료 기준이다.

**절반은 LLM 을 안 부른다.**

| | 노드 | 남은 일 |
|---|---|---|
| **순수 코드 5** | `build_filter` | 슬롯 → 필터 dict. `to_chroma_where` 가 저장소 문법으로 옮긴다 |
| | `retrieve` | **세 줄** — `search` → `filter_by_threshold` → `dedupe_by_substance` |
| | `compute_metrics` | 체중 × 용량. 근거 없으면 **빈 dict** (지어내지 않는다) |
| | `decide_triage` | 규칙 판정을 뽑아 `apply_gate()` 에 넘긴다 |
| | `ask_clarify` | 결측 슬롯 → 되묻기 문장. 상한 2회 |
| **LLM 호출 6** | `classify_intent` · `extract_slots` · `compress_context` · `generate_draft` · `simplify` · `verify_grounding` | `client.run(task, input)` **+ 출력 검증** |

**LLM 노드의 검증 규격은 이미 `models/tasks.py` 의 `verified_by` 에 적혀 있다** —
*"허용목록 검증 · 미분류 시 폴백"*, *"JSON 스키마 검증 · 결측 판정 · 되묻기 상한 2회"* 처럼.
**LLM 출력을 그대로 믿지 않는다** — 그 검증 코드가 노드 본문의 절반이다 (05 §4).

| 파일 | 함수 | 무엇 | 의존 |
|---|---|---|---|
| `classify.py` | `classify_intent` | intent 4종 + risk. **도메인 밖 거절이 여기서 난다** (D-46) | 없음 |
| `slots.py` | `extract_slots` · `ask_clarify` | 종·체중·물질·섭취량. **물질 미상이면 되묻는다** (D-49) | 없음 |
| `retrieve.py` | `build_filter` · `retrieve` | 필터는 코드가 만든다. 검색 → 임계값 → **중복 접기** | `slots` |
| `compute.py` | `compute_metrics` | 체중당 계산. `compute.rules` 로 조회 | `slots` |
| `generate.py` | `compress_context` · `generate_draft` · `simplify` | ③⑤. `finalize` 는 이미 구현됨 (D-47) | `retrieve`·`compute` |
| `triage.py` | `decide_triage` | **`apply_gate` 를 반드시 거친다** (D-09) | `compute`·`generate` |
| `verify.py` | `verify_grounding` | ④ 문장별 근거 판정. **이 프로젝트의 핵심** | `generate` |

### 분담 후보안 — **의존이 없는 쪽을 갈라 놓는다**

| | 맡을 것 | 왜 |
|---|---|---|
| **이근준** | `classify.py` · `slots.py` · `retrieve.py` | **앞단 셋은 서로 의존하지 않는다.** 먼저 끝나야 뒷단이 붙으므로 우선순위가 높고, 백엔드에서 이미 FastAPI·계약을 다뤄 봤다 |
| **오한빈** | `compute.py` · `generate.py` · `triage.py` · `verify.py` | **뒷단은 사실 표·규칙 테이블·트리아지 규율을 알아야 한다.** 그걸 만든 사람이 붙는 편이 빠르다 |

> 파일이 겹치지 않으므로 **같은 브랜치에서 작업해도 충돌이 안 난다.**
> 다만 `graph/engine.py` 의 그래프 조립은 **양쪽이 끝난 뒤 팀장이 한 번에** 한다.

**막히면 즉시 알린다.** 노드 하나가 하루를 먹으면 ④가 통째로 날아간다 —
그때는 **그 노드를 스텁으로 두고 최소 경로부터 뚫는다.**

**데이터 생성은 CPU 작업이라 나눌 수 있다.** 이서은이 형식을 확정하면
손이 빈 사람이 분량을 나눠 만든다.

**단일 실패 지점 걱정은 이미 대비돼 있다** — D-21 이 *"대형 LLM 기준 RAG 를 먼저 완성한 뒤
sLLM 으로 교체"* 다. 파인튜닝이 실패해도 시연은 된다. 보험은 사람을 더 붙이는 게 아니라
그 순서다.

**3080 은 디버깅용**(`PETTRIAGE_PROFILE=train-local`), **본 학습은 RunPod**(`train`).
프롬프트는 `models/prompts.py` 에 이미 있고 **학습과 추론이 같은 문자열을 쓴다** — 건드리지 않는다.

학습 진입 시 **골든셋 누수 검사**가 먼저 돈다. 학습셋과 평가셋이 겹치면 학습이 중단된다.

**자기가 쓴 정답을 자기가 검수하면 같은 오해가 두 번 통과한다** (04 §2.4).

**읽을 것: `docs/04a_골든셋작성지침.md`.**

### WS5 UI — 권소라 + 이서은 (토 설계 / 월·화 연결)

| 할 일 | 담당 | 완료 기준 |
|---|---|---|
| 질의응답 화면 | 권소라 | 세 상태(`answered`·`clarify`·`refused`)가 전부 그려진다 |
| 다이어리 · 프로필 화면 | 권소라 | 기록 입력·조회 |
| 사진 업로드 (D-43) | 이서은 | 관문 5단계 통과 · **여유 시** |

**계약이 먼저 고정돼 있다** (D-40). `src/pettriage/app/web/index.html` 에 데모 화면이 있고,
그래프가 붙어도 **`engine` 만 바뀌고 응답 형식은 같다.** 백엔드를 기다릴 필요가 없다.

**세 상태를 다 그려야 한다.** 이 시스템의 특징은 잘 답하는 게 아니라
**모르면 되묻고 근거가 없으면 거절하는 것**이다. `answered` 화면만 있으면
설계의 핵심이 화면에서 사라진다.

> `refused` 는 **HTTP 200 + `status="refused"`** 로 온다 (D-40).
> 에러가 아니므로 에러 화면으로 처리하면 안 된다.

> **화면 셋이 무엇인지는 `golden_lse.csv` 27건을 훑으면 보인다.**
> `expected_status` 가 `answered`·`clarify`·`refused` 로 갈리는 그 셋이 곧 화면이다.
> 쓸 필요는 없다 — **읽기만 해도 된다** (2026-08-02 개정).

#### 사진 업로드는 마지막이다 (D-43)

00 §3.3 우선순위상 **2단계**다. 1단계(트리아지 QA)가 끝나기 전에 손대지 않는다.
착수하게 되면 순서는 이렇다 — **저장 전에 전부 코드가 한다.**

```
① 확장자·MIME·크기 검사   → 이미지 아니면 거부
② EXIF 전량 제거          → GPS·기기·시각. 원본 EXIF 보관 안 함
③ 얼굴 검출              → 1건이라도 있으면 저장 거부 + 이유 안내
④ 리사이즈 + 재인코딩     → 잔여 메타데이터 차단
⑤ 내부 UUID 로 저장       → 원본 파일명 버림
```

**사진은 LLM에 넣지 않는다.** 기록의 첨부물이지 판정 입력이 아니다 (D-11).

## 4. 서로 기다리지 않게 하는 규칙

```
사실 표(팀장) ✅ 888행 → 적재 ✅ 888청크 → 검색 ──┐
그래프 노드(팀장 뒷단 4 · 이근준 앞단 3) ─────────┼──→ 통합 → 평가(팀장)
골든셋(이서은·팀장) ─────────────────────────────┘   ← 아무것도 안 기다린다
화면(권소라) ────────────────────────────────────┘   ← 계약이 고정돼 있어 안 기다린다
```

**남은 것은 가운데 줄 하나뿐이다.** 위·아래 세 줄은 끝났거나 안 기다린다.

**막힐 때 할 수 있는 일**

| 막힌 것 | 대신 할 일 |
|---|---|
| ~~사실 표가 아직 없다~~ | ✅ 888행 · 888청크 적재 완료 |
| 그래프가 아직 없다 | 화면 (`StubEngine` 이 계약대로 응답한다) · 골든셋 |
| GPU 가 아직 없다 | 학습 데이터 생성 (CPU 로 된다) · 골든셋 |
| API 가 아직 없다 | `index.html` 을 열어 목 데이터로 화면부터 |

**골든셋이 모두의 대기 시간 흡수처다.** 막히면 자기 25건을 채운다.
