**이서은이 골든셋에서 빠진 것이 아니다** — 유형·난이도 배분과 `must_not_contain`
사용법이 전부 G-001~G-025 에서 잡혔고, 뒤의 27건은 그 기준으로 빈 자리를 채운 것이다.

**목표는 총량이 아니라 종별 최소다.**

| | 27건 | **52건** | 최소 |
|---|---|---|---|
| dog | 12 | **30** ✅ | 10 |
| cat | 7 | **14** ✅ | 10 |
| **bird** | 5 | **5** | **10 ← 팀장 8건이 여기를 메운다** |

종별이 안 차면 **종별 분리 보고(04 §4.2)를 못 낸다.** D-09 종별 분기가 핵심 주장인데
그것을 지표로 못 보여주게 된다. 지침: [`04a §7`](04a_골든셋작성지침.md)

> **유형 잔여** — `dose`·`slot`·`none` 은 목표를 채웠다. 남은 8건은
> `symptom` 2 · `species` 3 · `fact` 2 · `prevent` 1 이고 **전부 정성 케이스**다.
> 조류는 체중당 임계치가 0건이라 **`dose` 를 만들면 안 된다** — 숫자를 지어내야 한다.

**수집 자료 처리는 팀장이 단독으로 한다.** 사실 표는 정반대 성질이다 —
`threshold_type` 판정 하나가 규칙 테이블 전체를 좌우해서(01e §3),
해석이 넷으로 갈리면 병합에서 되돌리는 비용이 분담으로 아낀 시간보다 크다.

## 1. 지금 무엇이 남았나

### 🔴 임계 경로는 **그래프 노드 하나뿐**이다

```
필수 산출물 4종
  ① 수집 데이터 · 전처리 문서      ✅ 사실 표 888행 · 45출처 · 문서 8종
  ② 시스템 아키텍처                ✅ 02 + 결정 47건 (D-01~D-53)
  ③ RAG 구현 코드                  ❌  ← **노드 12개 함수**가 아직 비어 있다 (D-52)
  ④ 테스트 계획 및 결과 보고서      ◐   ← 계획·골든셋 52건·하네스 ✅ / **결과는 ③ 대기**
```

**③과 ④가 같은 문제다.** 파이프라인이 안 돌면 지표가 안 나오고, 지표가 없으면
보고서에 쓸 것이 없다. **다른 무엇보다 여기가 먼저다.**

### 다만 **밑바닥부터 쓰는 것이 아니다**

노드가 쓸 부품은 이미 다 있고 테스트도 붙어 있다. **노드는 그것을 엮는 껍데기다.**

> ③ `G-006`(날씨)이 `refused` 가 아니라 `clarify` 로 갔다 — **종 되묻기가 도메인 판정보다 먼저** 온다.
>    `classify_intent` 를 구현할 때 순서를 잡아야 한다 (06 §8 미결).

### 🟢 **모델 없이 지금 한 바퀴 돌릴 수 있다**

```python
class EchoClient:
    """테스트용. 모델 없이 그래프·계약을 돌린다."""
    def run(self, task, user_input, *, max_tokens=512) -> str: ...

태스크별 응답을 미리 넣어 두면 **파인튜닝을 기다리지 않고 파이프라인 전체가 돈다.**
`LLMClient` 프로토콜 뒤라 나중에 `LocalQwenClient` 로 바꾸는 것은 `deps.py` 한 줄이다.

> **오늘 목표는 "노드 12개 구현"이 아니라 "Echo 로 질의 하나가 답까지 가게 하기" 다.**
> 그게 되면 산출물 ③이 서고, 실제 LLM 을 끼우는 것은 **교체 작업**이 된다.
> 학습이 늦어져도 시연과 평가 구조는 살아 있다 (D-21 과 같은 판단).

## 1.5 그래프 노드 분담 — **이것부터 정한다**

**12개 함수 · 7파일.** `pytest -m todo` 19건 + `load_profile` 이 완료 기준이다 (D-52로 하나 늘었다).

**절반은 LLM 을 안 부른다.**

| | 노드 | 남은 일 |
|---|---|---|
| **순수 코드 5** | `build_filter` | 슬롯 → 필터 dict. `to_chroma_where` 가 저장소 문법으로 옮긴다 |
| | `retrieve` | **세 줄** — `search` → `filter_by_threshold` → `dedupe_by_substance` |
| | `compute_metrics` | 체중 × 용량. 근거 없으면 **빈 dict** (지어내지 않는다) |
| | `decide_triage` | 규칙 판정을 뽑아 `apply_gate()` 에 넘긴다 |
| | `ask_clarify` | 결측 슬롯 → 되묻기 문장. 상한 2회 |
| | **`load_profile`** 🆕 | `pet_id` → MySQL `pets` ORM 조회 → **확인 되묻기** (D-52). `pandas` 금지 |
| **LLM 호출 6** | `classify_intent` · `extract_slots` · `compress_context` · `generate_draft` · `simplify` · `verify_grounding` | `client.run(task, input)` **+ 출력 검증** |

**LLM 노드의 검증 규격은 이미 `models/tasks.py` 의 `verified_by` 에 적혀 있다** —
*"허용목록 검증 · 미분류 시 폴백"*, *"JSON 스키마 검증 · 결측 판정 · 되묻기 상한 2회"* 처럼.
**LLM 출력을 그대로 믿지 않는다** — 그 검증 코드가 노드 본문의 절반이다 (05 §4).

| 파일 | 함수 | 무엇 | 의존 |
|---|---|---|---|
| `classify.py` | `classify_intent` | intent 4종 + risk. **도메인 밖 거절이 여기서 난다** (D-46) | 없음 |
| `slots.py` | `extract_slots` · `ask_clarify` · **`load_profile`** | 종·체중·물질·섭취량. **물질 미상이면 되묻는다** (D-49). 프로필은 **확인받아** 쓴다 (D-52) | 없음 |
| `retrieve.py` | `build_filter` · `retrieve` | 필터는 코드가 만든다. 검색 → 임계값 → **중복 접기** | `slots` |
| `compute.py` | `compute_metrics` | 체중당 계산. `compute.rules` 로 조회 | `slots` |
| `generate.py` | `compress_context` · `generate_draft` · `simplify` | ③⑤. `finalize` 는 이미 구현됨 (D-47) | `retrieve`·`compute` |
| `triage.py` | `decide_triage` | **`apply_gate` 를 반드시 거친다** (D-09) | `compute`·`generate` |
| `verify.py` | `verify_grounding` | ④ 문장별 근거 판정. **이 프로젝트의 핵심** | `generate` |

### 분담 후보안 — **의존이 없는 쪽을 갈라 놓는다**

| | 맡을 것 | 왜 |
|---|---|---|
| **이근준** | `classify.py` · `slots.py` · `retrieve.py` | **앞단 셋은 서로 의존하지 않는다.** 먼저 끝나야 뒷단이 붙으므로 우선순위가 높고, 백엔드에서 이미 FastAPI·계약을 다뤄 봤다 |
| **오한빈** | `compute.py` · `generate.py` · `triage.py` · `verify.py` | **뒷단은 사실 표·규칙 테이블·트리아지 규율을 알아야 한다.** 그걸 만든 사람이 붙는 편이 빠르다 |

> 파일이 겹치지 않으므로 **같은 브랜치에서 작업해도 충돌이 안 난다.**
> 다만 `graph/engine.py` 의 그래프 조립은 **양쪽이 끝난 뒤 팀장이 한 번에** 한다.

**막히면 즉시 알린다.** 노드 하나가 하루를 먹으면 ④가 통째로 날아간다 —
그때는 **그 노드를 스텁으로 두고 최소 경로부터 뚫는다.**

                 → 되는 즉시 `make eval --engine graph` (하네스는 이미 있다)
                 골든셋 52 → 60건 (팀장 8, bird 5·cat 3) · sLLM 학습 · 화면 연결
8/04 화 오전     2차 평가 → 04 결과 보고서 · 발표 준비
```

> **8/2의 계획은 "노드"였는데 실제로 한 것은 "하네스와 골든셋"이다.**
> 결과적으로 나쁘지 않다 — 노드가 완성되는 순간 **채점까지 자동으로 이어진다.**
> 다만 **③이 하루 밀렸고, 이제 여유가 없다.**

**월요일 안에 "질문 하나가 답까지" 가 돌아야 한다.** 되묻기·재검색·거절 분기를
다 만들지 말고 **길 하나만** 먼저 뚫는다 — 그게 곧 산출물 ③이고 시연 영상이다.

**월요일에 반드시 1차 평가를 돌린다.** 화요일에 처음 돌리면 결과가 나빠도 손쓸 수 없다.
골든셋 52건으로도 돌린다 — 하네스는 몇 건이든 받는다.

#### ⏱️ 속도 — 노드를 짤 때 지킬 것 셋 (D-53)

**지연은 LLM 호출 6번이 지배한다.** 질의 임베딩은 **193ms**(실측)로 1% 남짓이다.
그런데 아래를 안 지키면 **LLM 과 무관한 곳에서 수십 초를 잃는다.**

| | 상태 |
|---|---|
| 모델을 프로세스에 상주 | ✅ **코드가 강제한다** — `get_embedder` 에 `lru_cache`. **팩토리를 쓰면 된다** |
| 워밍업 | ✅ FastAPI `lifespan` · 하네스 측정 전 1회. 노드에서 따로 안 불러도 된다 |
| 정량 임계치 `lru_cache` | ☐ **아직.** 질의마다 CSV 재파싱하지 않게 |
| 프롬프트 프리픽스 고정 | ☐ `models/prompts.py` 가 이미 고정 문자열 — **동적 조립하지 말 것** |

⚠️ **직접 `BGEEmbedder(...)` 를 만들지 않는다.** 인스턴스마다 따로 로드한다.
`get_embedder(cfg.retrieval.embedding_model)` 로 받는다.

**시연 전 확인** — `curl localhost:8000/api/health` 의 `model_loaded` 가 `true` 여야 한다.
`false` 면 첫 질의가 로딩을 맞고, 스트리밍이 없어 **완전한 침묵**이 된다 (02 §12.4).

**개발 중 재시작이 잦으면** 워밍업을 끈다 — 다만 시연 전에는 반드시 되돌린다.

```bash
PETTRIAGE__SERVE__WARMUP=false make serve
```

> ⚠️ **`NODES_IMPLEMENTED = True` 로 바꾸는 순간부터** `make serve` 가
> **기동 시점에** 엔진을 만든다 (D-53). 노드가 덜 됐는데 `True` 로 바꾸면
> **서버가 아예 안 뜬다** — 첫 요청에서 500 이 나던 예전보다 낫다.
> 그게 04 §8 이 원한 동작이다: *"반쯤 구현된 그래프로 평가를 돌리면 지표가 오염된다."*

**그 밖의 캐시는 붙이지 않는다.** 하네스가 이미 `p50`·`p95`·노드별을 재므로(04 §4.3)
**숫자를 먼저 보고** 판단한다. 캐시 금지 목록(프로필·트리아지·`finalize` 이전)은 D-53.

**⚠️ 이근준 팀원이 착수 전에 반드시 볼 것 — `src/pettriage/graph/nodes/__init__.py`**

그 파일의 「절대 어기면 안 되는 것」 목록에 **폐기된 정책이 하나 남아 있었다** (8/2 수정).

```
✗ (옛 판) 유사도 임계 미만은 거절이다 — 낮은 점수 문서로 답을 만들지 않는다
✓ (현재)  유사도 점수로 거절 분기를 만들지 않는다 (D-46)
```

실측에서 근거 있음(0.547~0.733)과 없음(0.494~0.659) 분포가 **겹쳤다.**
*"고양이 이름 지어주세요"* 가 0.550으로 양성 최저점(0.547)보다 높다.
**`retrieve` 는 세 줄이고 거절 분기가 없다** — 거절은 앞의 `classify_intent`(범위밖)와
뒤의 `verify_grounding`(근거없음)이 만든다. `retrieve` 가 낼 수 있는 거절은 **결과 0건** 뿐이다.

같은 파일에 D-49(증상·물질미상 되묻기)와 D-50(규칙은 바닥, LLM 판정을 건너뛰지 않는다)도
규칙으로 올려 뒀다.

## 4. 서로 기다리지 않게 하는 규칙

```
사실 표(팀장) ✅ 888행 → 적재 ✅ 888청크 → 검색 ──┐
그래프 노드(팀장 뒷단 4 · 이근준 앞단 3) 🔴 ──────┼──→ 통합 → 평가(팀장)
골든셋 ✅ 52/60 ─────────────────────────────────┘   ← 아무것도 안 기다린다
평가 하네스 ✅ ──────────────────────────────────┘   ← StubEngine 으로 만들어 검증 완료
화면(권소라) ────────────────────────────────────┘   ← 계약이 고정돼 있어 안 기다린다
```

**남은 것은 가운데 줄 하나뿐이다.** 나머지는 전부 끝났거나 안 기다린다.
**그래서 8/3 에 모두가 볼 곳이 하나다** — 노드가 뚫리면 채점까지 자동으로 이어진다.

**막힐 때 할 수 있는 일**

| 막힌 것 | 대신 할 일 |
|---|---|
| ~~사실 표가 아직 없다~~ | ✅ 888행 · 888청크 적재 완료 |
| ~~평가 하네스가 없다~~ | ✅ `make eval` 로 지금 돈다 |
| 그래프가 아직 없다 | 화면 (`StubEngine` 이 계약대로 응답한다) · **골든셋 검수** |
| GPU 가 아직 없다 | 학습 데이터 생성 (CPU 로 된다) · 골든셋 검수 |
| API 가 아직 없다 | `index.html` 을 열어 목 데이터로 화면부터 |

**이제 대기 시간 흡수처는 골든셋 "작성" 이 아니라 "검수" 다** (27건 · G-026~G-052).

## 7. 버리는 순서

00 §3.3 우선순위대로 **1단계(코어)를 먼저 끝낸다.** 시간이 남으면 2·3·4를 붙인다.

| 단계 | | 시간이 모자라면 |
|---|---|---|
| 1. 코어 — 중독·증상 트리아지 QA | **이것부터** | 절대 안 버린다 |
| 2. 맥락 — 개인 기록 반영 · **사진 업로드** | 코어 완성 후 | 사진부터 뺀다 |
| 3. 킬러 — 기간 리포트 | 코어 완성 후 | |
| 4. 부가 — 영양 정량 | 여유 시 | 가장 먼저 뺀다 |

> **네 개가 다 60%인 것보다 하나가 100%인 편이 점수가 높다.**
> 00 §7 첫 줄이 *"골든 셋 없이 '잘 동작하는 것으로 보인다'로 끝나는 보고서"* 다.
