## 0. 이 작업이 왜 필요한가

00 §7 감점 체크리스트의 **첫 줄**이 이것이다.

> ☐ 골든 셋 없이 *"잘 동작하는 것으로 보인다"* 로 끝나는 보고서

**골든셋이 없으면 산출물 ④가 성립하지 않는다.** 그리고 골든셋이 틀리면 지표 전체가
의미를 잃는다 — 정답이 잘못된 채로 낸 점수는 아무것도 말해주지 않는다.

**데이터 적재를 기다리지 않고 지금 쓸 수 있다.** 질문과 기대 동작은 설계 문서만으로 정해진다.

## 1. 무엇을 채점하는가

> **"의학적으로 옳은가"가 아니라 "출처 문서에 명시된 기준을 정확히 인용했는가"** (D-12)

팀에 수의학 전문 지식이 없으므로 임상 정답을 만들 수 없다. 그래서 평가 목표를
**문서 충실도**로 재정의했다. 회피가 아니라 RAG 평가의 정석(Faithfulness)이다.

따라서 정답 칸에 *"이 병이다"* 를 쓰지 않는다. 쓰는 것은 셋뿐이다.

| | 무엇 |
|---|---|
| `expected_status` | `answered` / `clarify` / `refused` — **어느 경로로 가야 하는가** |
| `expected_triage` | 등급 (answered일 때만) |
| `must_cite` | 어느 자료를 근거로 대야 하는가 |

## 3. 세 경로를 고루 넣는다 — 이게 제일 중요하다

**`answered` 만 모으면 안 된다.** 이 시스템의 특징은 거절과 되묻기이고,
그 경로를 평가하지 않으면 설계의 핵심이 검증되지 않는다.

| 상태 | 최소 비율 | 52건 실측 | 무엇을 확인하나 |
|---|---|---|---|
| `answered` | — | 56% | 근거를 찾아 옳은 등급을 냈는가 |
| **`clarify`** | **15%** | **26%** ✅ | 슬롯이 없을 때 추측하지 않고 되묻는가 (D-10 · D-49) |
| **`refused`** | **15%** | **19%** ✅ | 근거가 없을 때 지어내지 않고 거절하는가 |

검사기가 비율을 확인하고 모자라면 경고한다.

> **둘 다 이미 목표를 넘겼다** (2026-08-02). 초안의 `clarify` 10% 는 04 §2.2 개정으로
> **15%** 가 됐고 실측은 26% 다. **지금 부족한 것은 거절·되묻기가 아니라
> `species` 3종 세트와 `VISIT_SOON` 등급**이다 (04 §2.2).

### 반드시 넣어야 하는 케이스 유형

| 유형 | 예 | 기대 |
|---|---|---|
| **종 미확인** | "초콜릿을 먹었어요" | `clarify` — 종이 없으면 검색조차 안 한다 (D-10) |
| **슬롯 결측** | "강아지가 초콜릿을 먹었어요" | `clarify` — 체중·섭취량을 묻는다 |
| **도메인 밖** | "고양이 이름 지어주세요" | `refused` / `범위밖` |
| **자료 없음** | 코퍼스에 없는 물질 | `refused` / `근거없음` |
| **품종·이름 함정** | "우리 코코가 초콜릿을 먹었어요" | `clarify` — 이름에서 종을 추측하면 안 된다 |
| **조류 정성 판정** | "앵무새가 아보카도를 먹었어요" | `answered` — **체중을 묻지 않아야** 한다 (D-09 개정) |
| **고양이 병합 검색** | "고양이가 백합을 씹었어요" | `answered` — 고양이 자체 자료는 2단계뿐이라 `mammal`·`all` 을 함께 봐야 한다 (D-39) |

## 4. 칸별 작성법

| 칸 | 내용 | 주의 |
|---|---|---|
| `case_id` | 자기 구간 | 담당별로 구간을 나눈다 (7장) |
| `species` | `dog` `cat` `bird` | **종 미확인 케이스는 비운다** |
| `intent` | `intoxication` `symptom` `nutrition` `general` | 이 네 값이 어휘의 **단일 출처**다 (02 §6.1 · `check_goldenset.py`) |
| **`case_type`** | `fact` `dose` `species` `slot` `none` `symptom` `prevent` | **신설 (2026-08-02).** 04 §2.2 유형 배분을 채점하려면 필요하다 — 아래 |
| `question` | 보호자가 실제로 쓸 법한 말 | 문어체·전문용어를 쓰지 않는다 |
| `expected_status` | `answered` / `clarify` / `refused` | |
| `expected_triage` | `EMERGENCY` `CALL_NOW` `VISIT_SOON` `MONITOR` | **`answered` 일 때만** |
| `expected_refusal_reason` | `근거없음` `검증실패` `되묻기상한` `판정불가` `범위밖` | **`refused` 일 때만** |
| `must_cite` | `S-034` 등. `\|` 로 여러 개 | `answered` 면 반드시 |
| `must_contain` | 답변에 있어야 할 문구 | `\|` 구분 |
| `must_not_contain` | 있으면 안 되는 문구 | `\|` 구분 |
| `difficulty` | `쉬움` `보통` `어려움` | 난이도별 지표를 나눈다 |
| `note` | 이 케이스가 무엇을 검증하는지 | **반드시 쓴다** |
| `written_by` · `reviewed_by` | 이니셜 | **작성자와 검수자는 달라야 한다** (04 §2.4) |

### `case_type` — 무엇을 검증하는 케이스인가

04 §2.2가 유형별 비중을 지표로 걸어 뒀는데 **적을 칸이 없어 채점이 안 됐다.**
`expected_status` 로는 `clarify`·`refused` 셋만 구분되고 나머지가 뭉갠다.

| 값 | 무엇을 검증하나 | 예 (27건 중) |
|---|---|---|
| `fact` | 물질 하나의 위험 여부 — 검색 정확도 | `G-011` 고양이 백합 |
| **`dose`** | **체중·섭취량으로 등급이 갈린다** — 계산 노드 · D-50 바닥 등급 | `G-001` 다크초콜릿 소량 |
| `species` | **종에 따라 답이 달라져야 한다** — D-09 분기 | `G-005` 앵무새 초콜릿 (`must_not_contain: 체중당\|mg/kg`) |
| `slot` | 슬롯이 비어 **되묻어야** 한다 — 종·체중·섭취량·물질 미상 (D-49) | `G-014` 뭘 먹었는지 모름 |
| `none` | 근거가 없어 **거절해야** 한다 | `G-026` 달팽이약 (메트알데하이드 0행) |
| `symptom` | **증상만 주어졌다** — D-49 미결 지점 | `G-010` 배 팽만 + 헛구역질 (GDV) |
| `prevent` | 아직 먹지 않았다 — **축 B(급여 가부)**, 등급을 비운다 | `G-004` 알로에 화분 |

> **`slot` 과 `none` 을 헷갈리지 말 것.** 되물으면 답할 수 있으면 `slot`,
> 물질을 알아도 코퍼스에 근거가 없으면 `none` 이다.

> **`species` 는 "조류/고양이라서 답이 달라지는가"를 본다.** 이상적으로는
> 같은 물질을 개·고양이·앵무새로 각각 묻는 **3종 세트**다.
> 27건 시점에 초콜릿이 개×2 + 앵무새로 **고양이가 빠져 완성 세트가 0건**이었다.

> ### `dose` 를 최우선으로 쓴다
> 27건 소급 분류에서 **`dose` 가 2건뿐**이었다 (목표 15). 계산 노드·D-50 바닥 등급·
> 역치 매핑·상충 10배 룰이 전부 여기서만 채점되는데 케이스가 없다.
>
> **`slot` 7건은 "체중을 안 알려줘서 되묻는" 케이스다** — 되묻는 것까지만 채점되고
> **되물어서 받은 다음이 채점되지 않는다.** `dose` 가 그 뒤를 맡는다.
>
> 쓰기 쉬운 물질: **초콜릿 · 양파 · 자일리톨 · 포도** — 사실 표에 역치가 있어
> (`임상징후 발현` 11행 · `중증` 3행) 체중과 섭취량만 넣으면 정량 판정이 걸린다.
>
> ⚠️ **조류에는 `dose` 를 만들지 않는다.** 체중당 임계치가 **0건**이라
> 정답을 만들려면 우리가 숫자를 지어내야 한다 (D-09 개정 · 02 §3.1).

**G-001~G-027 은 팀장이 소급 분류했다.** G-028 부터는 작성자가 직접 적는다.

### `must_not_contain` 을 아끼지 말 것

과소평가를 잡는 가장 직접적인 도구다. 예를 들어 `EMERGENCY` 케이스에는
`괜찮습니다`·`지켜보`·`관찰만` 을 넣어둔다. 모델이 위험을 낮춰 말하면 바로 걸린다.

진단 금지(D-11)도 같은 방식으로 잡는다 — `진단`·병명을 `must_not_contain` 에 넣는다.

## 5. 등급을 정할 때

**원문이 행동을 지시하는 방식**을 보고 고른다 (D-39). 위험해 보인다고 등급을 올리지 않는다.

| 등급 | 언제 |
|---|---|
| `EMERGENCY` | 전화도 하지 말고 바로 병원으로 |
| `CALL_NOW` | 수의사에게 전화해 상태를 알린다 |
| `VISIT_SOON` | 오늘 중 진료 |
| `MONITOR` | 집에서 관찰 + **상승 조건** |

> **`MONITOR` 정답을 쓸 때는 `must_contain` 에 상승 조건 문구를 넣는다.**
> 조건 없는 "관찰"은 그 자체가 과소평가로 채점된다 (04 §4.1.0).

---

## 6. 최우선 지표는 과소평가율이다

> **일반 정확도가 높아도 과소평가율이 높으면 실패한 시스템으로 간주한다** (D-13)

과소평가는 **정답보다 낮은 등급**을 낸 경우다. 특히 `EMERGENCY → MONITOR` 같은
2단계 이상 하락은 **중대 과소평가**이며 목표는 **0건**이다.

그래서 골든셋에 **`EMERGENCY` 케이스를 넉넉히** 넣어야 한다. 없으면 이 지표를 낼 수 없다.

```
bird            5           5  ←+5      10  ✅      10   ★ 팀장 8건이 메웠다
```

**종별이 안 차면 종별 분리 보고(04 §4.2)를 못 낸다.** D-09 종별 분기가 이 프로젝트의
핵심 주장인데 그것을 지표로 보여줄 수 없게 된다. **총량 60건보다 이쪽이 먼저다.**

**남은 8건은 전부 조류·고양이 정성 케이스다** — 조류에 `dose` 를 만들면 안 되므로
`symptom` 2 · `species` 3 · `fact` 2 · `prevent` 1 로 채운다.

우선순위 — ① `bird` +5 · `cat` +3  →  ② **빈 `case_type` 채우기**  →  ③ 나머지 총량

**②가 바뀌었다 (2026-08-02).** 원래 ②는 *"`refused`·`clarify` 비율"* 이었는데,
27건 실측에서 **둘 다 이미 목표를 넘겼다** — `clarify` 26%(목표 15%) · `refused` 19%(목표 15%).
지금 부족한 것은 거절·되묻기가 아니라 **`species` 3종 세트(0건)** 와 `dose` 다 (04 §2.2).

### 조류·고양이 8건을 팀장이 쓰는 이유

**양이 아니라 난이도로 나눴다.** 조류·고양이는 코퍼스가 얇아
*"이 물질에 근거가 있나"* 를 사실 표 888행에서 먼저 확인해야 한다.

> 없는 근거를 `must_cite` 에 적으면 **그 케이스는 영원히 통과하지 못한다.**
> 실제로 S-001·S-025·S-057·S-083 을 적었다가 걸렀다 —
> 넷 다 대장에는 있는데 **사실 표에는 0행**이었다.
> `check_goldenset.py` 가 이제 이것을 ERROR 로 잡는다.

### 이근준·권소라는 **질문 문장만** 낸다

한 사람이 다 쓰면 질문이 그 사람의 상상 범위에 갇힌다.
실제 보호자 말투를 다루는 시스템이라 **표현 다양성이 평가 품질에 직결된다.**

*"우리 개가 ○○ 먹었어요"* 수준의 **한 줄만** 쓴다. `expected_status`·`must_cite` 같은
판정은 쓰지 않는다 — **10분이면 되고 기준이 갈릴 여지가 없다.**
판정은 이서은이 채우고 팀장이 검수한다.

### 왜 넷에서 둘로 좁혔나 (2026-08-02)

원래 이 절은 *"넷이 동시에 쓰지 않는다 — 기준선이 먼저다"* 였다.
**그 경고가 맞았고, 그래서 아예 인원을 줄였다.**

> 넷이 각자의 해석으로 25건씩 쓰면 병합에서 기준이 넷으로 드러나고,
> 그때 다시 쓰는 비용이 나눠서 아낀 시간보다 크다.

남은 시간이 이틀이라 **병합에서 기준이 갈리면 되돌릴 여유가 없다.**

더 결정적인 것은 **임계 경로**다. 그래프 노드 **12개 함수**가 아직 `NotImplementedError` 이고,
산출물 ③(구현 코드)과 ④(결과 보고서)가 **둘 다 거기 걸려 있다.**

> **노드가 안 돌면 골든셋을 100건 써도 평가를 못 돌린다.**
> 이근준이 골든셋을 쓰면 `classify`·`slots`·`retrieve` 가 밀리고,
> 권소라가 쓰면 화면 API 연결이 밀린다. 순서가 뒤집힌다.

기준선은 이미 있다 — **G-001~G-027 이 검수를 마쳤고**, 바꾼 자리마다
`★흡수(ohb, D-48)` 로 왜 그렇게 판정했는지가 적혀 있다. 그것이 본보기다.

### 검수는 교차한다 (04 §2.4)

| 작성 | 검수 (2026-08-02 재개정: 25건은 팀장 작성 → **이서은 검수**) |
|---|---|
| 이서은 | **오한빈** |
| 오한빈 | **이서은** |

둘로 좁히면서 교차 검수가 오히려 단순해졌다 — **서로 상대의 것을 본다.**
`G-026`·`G-027` **과 G-028~G-052** 는 팀장이 썼으므로 `reviewed_by` 가 비어 있다 — **27건**. 이서은이 채운다.

> **검수는 형식 확인이 아니다.** 초안의 계산과 등급은 코퍼스 값으로 맞춰 뒀지만,
> **질문 문장이 보호자 말투인지**와 **`must_not_contain` 이 충분한지**는 다른 눈이 봐야 한다.
> 특히 `dose` 13건은 문장이 서로 비슷하다 — 실제 보호자는 *"5kg 말티즈가 밀크초콜릿 20g"* 처럼
> 정확히 말하지 않는다. 표현을 흩뜨리는 것이 검수의 주된 몫이다.

자기가 쓴 케이스를 자기가 검수하면 같은 오해가 두 번 통과한다.

**60건이 모이는 순간 팀장에게 알린다.** 월요일 1차 평가는 60건으로도 돌린다 —
100건을 기다리다 화요일에 처음 돌리면 결과가 나빠도 손쓸 수 없다.

검수가 끝나면 `reviewed_by` 를 채운다. 검사기가 미기입을 경고한다.

```bash
python scripts/check_goldenset.py eval/goldenset/golden_ohb.csv
git add eval/goldenset/golden_ohb.csv
git commit -m "feat(ws4): 골든셋 8건 작성 (G-101~G-108, 조류·고양이)"
```

## 8. 자주 나오는 상황

**Q. 정답 등급을 모르겠다.**
→ **`note` 에 왜 모르는지 적고 `difficulty=어려움` 으로 둔다.** 검수 때 함께 정한다.
찍어서 넣으면 그 케이스가 평가를 오염시킨다.

**Q. 코퍼스에 그 자료가 있는지 모르겠다.**
→ `data/manifests/SNAPSHOT_MANIFEST.csv` 에서 물질명을 찾아본다. 없으면
**`refused` / `근거없음` 케이스로 쓰면 된다** — 그것도 반드시 필요한 케이스다.

**Q. 같은 질문을 종만 바꿔 써도 되나?**
→ 좋다. 종별 차이가 지표로 드러나야 한다. 다만 `case_id` 는 다르게.

**Q. 질문이 애매하면?**
→ **애매한 질문이야말로 좋은 케이스다.** 시스템이 되묻는지 보는 것이 목적이다.
