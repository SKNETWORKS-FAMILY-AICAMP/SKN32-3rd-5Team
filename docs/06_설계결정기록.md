## 0. 이 문서의 목적

> **설계의 매 순간마다 "왜 이렇게 설계했는가"에 명확한 이유를 댈 수 있어야 한다.**

"왜"에는 두 종류가 있다.

| 종류 | 질문 | 답하는 곳 |
|---|---|---|
| **존재의 이유** | 이 조각이 왜 필요한가 — 앞 조각의 어떤 한계를 푸는가 | **05** 정지 판정 |
| **선택의 이유** | 여러 대안 중 왜 이것을 골랐는가 | **본 문서** |

### 0.1 기록 형식

```
- 상태 / 맥락 / 대안 / 결정 / 트레이드오프 / 영향
```

**트레이드오프 문장이 핵심이다.**

> `[문제]를 풀기 위해 [선택]을 택했고, 그 덕분에 [얻은 것] 대신, [감수한 것]을 떠안았다.`

감수한 것을 적지 않은 "왜"는 자기 합리화이고, 적으면 설계 판단이 된다.
심사·리뷰에서 *"단점은 없나요?"* 라는 질문에 이미 답이 준비되어 있게 된다.

### 0.2 기록 규칙

- ✅ 기록한다 — 되돌리기 어려운 결정, **대안이 실제로 있었던** 결정, 나중에 질문받을 결정
- ❌ 기록하지 않는다 — 자명한 것, 언제든 바꿀 수 있는 것(변수명, 사소한 라이브러리 선택)
- 결정이 뒤집히면 **삭제하지 않고 `폐기` 또는 `대체됨` 상태로 남기고 새 번호를 부여**한다.
  **뒤집힌 이력 자체가 근거다.**
- 상태: `확정` / `제안` / `조건부` / `폐기` / `대체됨(→ D-xx)`

### D-01 · 도메인 — 반려동물 헬스케어 & 응급 대응

- **상태**: 확정 (2026-07-27)
- **맥락**: 과제 요건이 "내외부 문서 기반 QA"이고, 팀 기준으로 *"전문 지식이 없어 정보를 찾기 힘든 일상 영역"* 을 지향
- **대안**: (a) 근로계약서 검토 (b) 임대차 계약 검토 (c) 전자제품 A/S (d) 헬스장·학원 환불 (e) **반려동물 헬스케어**
- **결정**: (e). 환각 당위성·페인 포인트·분류 체계·신선함·시연 임팩트에서 우위이며, **개인정보 리스크가 낮아 개인 기록 축적 확장이 가능한 유일한 후보**
- **트레이드오프**:
  > 정보 비대칭이 큰 일상 영역을 다루려는 문제를 풀기 위해 반려동물 헬스케어를 택했고,
  > 그 덕분에 시연 임팩트와 확장성을 얻은 대신,
  > **정답 검증이 어렵고(수의학 지식 부재) 범위가 쉽게 폭증하는** 부담을 떠안았다.
- **영향**: 00 §3 · `도메인검토-반려동물-헬스케어.md`
- **연관**: D-12(정답 검증 우회) · D-21(범위 관리)

### D-02 · 브이로그 다이어리로 확장

- **상태**: 확정 (2026-07-27)
- **맥락**: 원안(중독 응급 QA)은 **"무엇이 내부 문서인가"** 에 답하지 못했고, 요약 태스크의 필연성도 약했다
- **대안**: (a) 동물병원 원내 프로토콜을 가상 생성해 내부 문서로 (b) 반려동물 프로필만 내부 데이터로 (c) **일상 기록 다이어리를 내부 문서로**
- **결정**: (c). 개인 기록이 곧 내부 문서가 되어 *"내 문서 × 공적 기준 → 판정"* 구조가 성립하고, **기간 요약 리포트**라는 킬러 유스케이스가 생긴다
- **트레이드오프**:
  > 내부 문서 부재와 요약 필연성 부족이라는 문제를 풀기 위해 다이어리 확장을 택했고,
  > 그 덕분에 두 약점을 동시에 해소하고 RAG 필연성까지 강화한 대신,
  > **다이어리 CRUD라는 RAG와 무관한 구현 부담**과 범위 폭증 리스크를 떠안았다.
- **영향**: 00 §3.1 · 01 §13 · 02 §5
- **연관**: D-21(다이어리 최소 구현)

## 2. 구조

### D-04 · RAG와 파인튜닝의 역할 분리

- **상태**: 확정 (2026-07-27)
- **맥락**: 과제가 RAG와 멀티태스크 파인튜닝을 **동시에** 요구한다. 둘을 어떻게 한 시스템에 담을 것인가
- **대안**: (a) 파인튜닝으로 도메인 지식 주입 + RAG 보조 (b) **RAG가 지식, sLLM은 보조 태스크** (c) 둘을 별개 산출물로 병렬 제출
- **결정**: (b). *"RAG가 근거를 가져오고, 파인튜닝한 sLLM이 그 근거가 지켜졌는지 검증한다"*
- **트레이드오프**:
  > 두 요건이 따로 노는 문제를 풀기 위해 역할 분리 구도를 택했고,
  > 그 덕분에 두 요건이 하나의 목표(환각 방지)로 묶이고 **파인튜닝 실패 시에도 폴백으로 시스템이 동작**하는 대신,
  > sLLM이 최종 답변을 생성하지 않아 **"파인튜닝 효과"를 보여주려면 별도 비교 실험이 필요한** 부담을 떠안았다.
- **영향**: 00 §2 · 03 §1 · 04 §5

### D-05 · 멀티태스크 구성 5종 (+번역 조건부)

- **상태**: 확정 (2026-07-27) / ⑥ 번역은 조건부 → D-19 연동
- **맥락**: 공지는 "분류·요약·번역"을 예시로 들었을 뿐 태스크 구성은 선택 가능
- **대안**: (a) 공지 예시 그대로 분류·요약·번역 (b) **파이프라인이 실제로 필요로 하는 태스크로 재구성**
- **결정**: (b) — ① 분류 ② 슬롯 추출 ③ 압축 요약 ④ **근거 검증** ⑤ 평이화. 번역은 조건부 ⑥
- **근거**: ④가 과제 목표 1번(환각 방지)을 파인튜닝 모델이 직접 담당하게 만든다. 출력 길이가 다른 태스크를 의도적으로 섞어 **태스크 간섭이라는 실제 논점**을 확보
- **트레이드오프**:
  > 억지로 채운 태스크는 "왜 하는가"에 답할 수 없다는 문제를 풀기 위해 파이프라인 수요 기반 재구성을 택했고,
  > 그 덕분에 각 태스크의 존재 이유를 ablation으로 증명할 수 있게 된 대신,
  > **공지 예시와 다른 구성을 설명해야 하는** 부담과 태스크 5종의 학습 부하를 떠안았다.
- **영향**: 03 §2 · 04 §3 · 04 E4

### D-06 · ReAct · MCP · 멀티에이전트 미채택

- **상태**: 확정 (2026-07-27)
- **맥락**: 에이전트 스택을 어디까지 붙일 것인가 — 정지 판정
- **대안**: (a) 전부 채택 (b) 도구 루프만 (c) **세 가지 모두 미채택**
- **결정**: (c)
  - **ReAct** — 계산 노드는 있으나 **LLM이 도구를 선택할 필요가 없다.** intent가 정해지면 어떤 계산이 필요한지 코드가 안다
  - **MCP** — 도구 재사용·표준화 수요 없음. 외부에 도구를 노출할 계획 없음
  - **멀티에이전트** — God Object 아님. 도구 5~7개+ 아님
- **트레이드오프**:
  > 한계가 드러나지도 않은 조각을 미리 붙이면 복잡도만 오른다는 문제를 풀기 위해 세 조각을 배제했고,
  > 그 덕분에 과설계를 피하고 디버깅 가능한 구조를 유지한 대신,
  > **"요즘 기술을 안 썼다"는 인상을 줄 수 있는** 위험과 매 단계 필요성을 판단해야 하는 부담을 떠안았다.
- **비고**: 후자의 위험은 **미채택 근거를 문서로 남김으로써** 상쇄한다. "안 썼다"가 아니라 "판정해서 뺐다"
- **영향**: 02 §1.1 · 05 §2

### D-07 · 오케스트레이션 — LangGraph

- **상태**: 확정 (2026-07-27)
- **맥락**: 되묻기 순환과 근거 검증 실패 시 재검색이 있어 흐름이 선형이 아니다
- **대안**: (a) LCEL 선형 체인 (b) 직접 구현한 상태 머신 (c) **LangGraph**
- **결정**: (c). 조건부 분기·순환·상태 공유를 명시적 그래프로 표현할 수 있고, 흐름이 코드에 드러난다
- **트레이드오프**:
  > 되묻기·재검색 순환을 선형 체인으로 표현할 수 없다는 문제를 풀기 위해 LangGraph를 택했고,
  > 그 덕분에 흐름의 예측 가능성과 디버깅 용이성을 얻은 대신,
  > **프레임워크 학습 비용과 상태 스키마 유지보수** 부담을 떠안았다.
- **영향**: 02 §6 · 05 §2

- **맥락**: 과제가 "LangChain을 활용한 연동"을 요구하나, 팀은 전면 의존을 피하고자 한다
- **대안**: (a) 전면 채택 (b) 완전 배제 (c) **계층별 선택적 채택**
- **결정**: (c) — 문서 규격·LangGraph·`@tool`·LangSmith는 채택, **체인·리트리버 추상화는 직접 구현**
- **트레이드오프**:
  > 요건 충족과 검색 로직 제어권 확보가 충돌하는 문제를 풀기 위해 계층별 선택 채택을 택했고,
  > 그 덕분에 요건을 충족하면서 핵심 로직의 통제권을 유지한 대신,
  > **직접 구현한 부분의 유지보수 책임**과 활용 범위를 설명해야 하는 부담을 떠안았다.
- **영향**: 02 §10

### D-42 · 베이스 sLLM — Qwen3-4B QLoRA

- **상태**: 확정 (2026-07-31)
- **맥락**: D-05가 태스크 5종을 정했으나 **어떤 모델에 얹을지가 비어 있었고**,
  이것이 학습 데이터 형식·프롬프트 템플릿·평가 비교군을 전부 막고 있었다.
  제약은 세 가지였다 — ① 한국어 성능 ② 상업적으로 안전한 라이선스
  ③ **팀이 실제로 굴릴 수 있는 VRAM**.
- **대안**: (a) Qwen3-1.7B (b) **Qwen3-4B** (c) Qwen3-8B 이상
- **결정**: (b) Qwen3-4B, QLoRA 4bit(NF4) + LoRA r=16.
  00 §5에 적은 *"1~4B급"* 의 상한이며, 4bit로 16GB VRAM에 들어간다.

  **1.7B를 택하지 않은 이유가 태스크 구성에 있다.** 이 프로젝트의 핵심 태스크는
  ④ 근거 검증이고(D-05), 이것은 라벨 분류가 아니라 **문장별 판단**이다.
  출력 길이가 서로 다른 5종을 한 어댑터에 얹으면 간섭이 생기는데(04 E4),
  용량이 작을수록 그 간섭이 성능 붕괴로 나타난다. 8B는 QLoRA로도 학습 시간이
  팀 일정에 맞지 않는다.

  **학습 스택은 HF PEFT + TRL**로 고정한다. Unsloth가 더 빠르지만 래퍼 계층이
  하나 더 생기고, 산출물 ③·④에서 *"무엇을 어떻게 학습했는가"* 를 설명할 때
  표준 스택 쪽이 검증하기 쉽다.

- **04 비교군과의 대응** — 같은 `LLMClient` 프로토콜 뒤에 셋을 둔다.

  | 비교군 | 구현 | 의미 |
  |---|---|---|
  | **A** | `APIClient` (대형 LLM) | 상한선이자 **폴백 경로** (D-21) |
  | **C** | `LocalQwenClient` (어댑터 O) | 파인튜닝 효과 |
  | **D** | `LocalQwenClient` (어댑터 X) | 베이스 대비 증분 |

  C와 D가 **같은 클래스**여야 조건이 동일해진다. 어댑터 유무만 다르게 둔다.

- **트레이드오프**:
  > 태스크 5종을 한 모델에 얹으면서 팀 GPU 안에 들어가야 하는 문제를 풀기 위해
  > Qwen3-4B QLoRA를 택했고,
  > 그 덕분에 **④ 근거 검증에 필요한 용량을 확보하면서 16GB에서 학습 가능**해진 대신,
  > **1.7B 대비 실험 반복 속도가 느려지고** 4bit 양자화로 인한 성능 손실을
  > 비교군에서 분리해내기 어려워지는 부담을 떠안았다.
- **비고**: `configs/default.yaml` 의 `model.revision` 을 **학습 착수 시 반드시 채운다.**
  모델도 코퍼스처럼 버전이 있고(D-20), 비워두면 재현이 깨진다.
  또한 평가 시 `do_sample=False` 를 강제한다 — 샘플링이 섞이면 04 §8이 성립하지 않는다.
- **미결**: 4bit 손실 분리를 위한 bf16 대조군을 돌릴지 (GPU 여유에 따라 판단)
- **영향**: 00 §5 · 03 §2·§4 · 04 §5 · D-04 · D-05 · D-21 · D-41

### D-09 · 트리아지 하향 금지 게이트 🔒

- **상태**: 확정 (2026-07-27)
- **맥락**: 트리아지 등급을 LLM이 판정하면 **과소평가(under-triage) 시 생명 위험**이 발생한다
- **대안**: (a) LLM 단독 판정 (b) 규칙 테이블 단독 (c) **하이브리드 + 하향 금지 게이트**
- **결정**: (c). 규칙 테이블이 1차 판정(`물질 × 종 × 체중당 섭취량`), LLM은 규칙 미적용 케이스만.
  최종 등급 = **위험도 기준 `max(rule, llm)`** — **LLM은 등급을 낮출 수 없다**
- **트레이드오프**:
  > LLM 판정이 과소평가를 낼 수 있다는 문제를 풀기 위해 하향 금지 게이트를 택했고,
  > 그 덕분에 under-triage를 **지표가 아니라 구조로** 억제하게 된 대신,
  > **과대평가(over-triage) 증가**와 규칙 테이블 유지보수 부담을 떠안았다.
- **비고**: 축①의 *"LLM 출력은 반드시 검증해서 받는다"* 가 가장 구체적으로 구현된 지점.
  트레이드오프는 실험 **E6**으로 정량화한다

#### 개정 — 종별 분기 (2026-07-30, D-39 도출 후)

초판은 규칙 테이블을 **`물질 × 종 × 체중당 섭취량`** 으로 잡았다.
**코퍼스 실측 결과 조류에는 체중당 섭취량이 0건이라 이 형태가 성립하지 않는다.**

| 종 | 규칙 테이블 입력 | 근거 |
|---|---|---|
| **개·고양이** | `물질 × 체중당 섭취량` **정량** | 주목 2.3 g/kg · Allium 체중 0.5% · 백합 1–2장 · 3시간 골든타임 |
| **조류** | `물질 × 증상` **정성** | 체중당 용량 **0건** · 호흡수 기준 **0건** · 체온 기준 **0건**.<br>유일한 수치 트리거는 출혈 5–10분(S-072) 1건 |

> **조류 질의에 체중·섭취량 수치를 요구하는 슬롯·프롬프트를 두면 반드시 환각이 발생한다.**
> 근거가 없는 값을 LLM이 지어내기 때문이다. 조류는 **질적 조건**
> (*"acting ill"* · *"not resolving"* · *"continues to vomit"*)과 증상 목록으로만 판정한다.

**등급 값은 D-39를 따른다** — `EMERGENCY(4) > CALL_NOW(3) > VISIT_SOON(2) > MONITOR(1)`.
**숫자가 클수록 위험**하므로 `max()`가 그대로 성립한다.

- **영향**: 02 §7.2 · 04 §4.1 · 04 E6 · 05 §5 · **D-39**

### D-39 · 트리아지 등급 — 데이터에서 도출한 4단계 + 별도 급여 축 🔒

- **상태**: 확정 (2026-07-30)
- **맥락**: D-09가 하향 금지 게이트를 정했으나 **등급 체계 자체가 미정**이었고, 이것이
  규칙 테이블·골든셋·04 지표를 전부 막고 있었다. 그리고 **D-38에서 "템플릿은 발명하지 않고
  데이터에서 도출한다"고 정해놓고 등급만 위에서 내려주는 것은 앞뒤가 맞지 않았다.**
- **대안**: (a) 통상적 트리아지 4단계(응급/조기내원/관찰/정상)를 차용
  (b) **살아있는 코퍼스 42건에서 실제 등급·행동 표현을 추출해 도출**
- **결정**: (b).

  **먼저 밝혀진 사실 — 코퍼스에 "긴급도 N단계"를 선언한 소스는 0개다.**

  > ⚠️ **초기 판단 정정.** 그동안 *"조류 등급의 유일한 근거는 Lafeber 3단계(S-005)"* 로 여러 번
  > 기술했으나, 원문을 재확인한 결과 이는 **급여 허용 등급이지 진료 긴급도 등급이 아니다.**
  > S-005 전문에 *"수의사에게 데려가라"* 는 지시가 **한 줄도 없다.**

  대신 **행동 지시어(action language)** 를 모으니 4단계로 갈렸다.

  | 값 | 정수 | 배지 | 사용자 문장 | 근거 (verbatim) | 근거 수 |
  |---|---|---|---|---|---|
  | `EMERGENCY` | **4** | 응급 | 지금 바로 동물병원으로 가세요 | *"**Don't call.** Take your pet straight to the nearest ER"* (S-038) | 18 |
  | `CALL_NOW` | **3** | 전화 | 지금 수의사에게 전화해 상태를 알리세요 | *"call your veterinarian to **discuss whether your pet needs to be seen**"* (S-086) | 10 |
  | `VISIT_SOON` | **2** | 내원 | 오늘 중 진료를 받으세요 | *"**Contact your veterinarian if** repetitive behavior occurs daily or worsens"* (S-080) | 11 |
  | `MONITOR` | **1** | 관찰 | 집에서 지켜보고, 아래 증상이 나타나면 연락하세요 | *"**Monitor condition. If condition is not resolving** seek veterinary care"* (S-092) | 11 |

  **`EMERGENCY`와 `CALL_NOW`를 병합할 수 없는 이유가 데이터에 있다** — S-038이
  *"Don't call"* 로 **전화를 명시적으로 금지**하고 이송을 지시한다. S-030도 전화번호(L2)와
  *"go immediately to the nearest emergency veterinary hospital"* (L1)을 나란히 배치한다.

  **`MONITOR`에는 상승 조건을 반드시 함께 표시한다.** 데이터의 이 단계는 "그냥 지켜봐라"가
  아니라 *"if not resolving"* 이라는 **조건부 상승**이 본질이다. 조건 없이 "관찰"만 띄우면
  **그 자체가 과소평가**다.

- **정수 방향**: **숫자가 클수록 위험**하다. D-09의 `max(rule, llm)`이 그대로 성립한다.
  (초안의 `L1=최고위험` 표기는 `min()`을 요구해 코드에서 혼동을 낳으므로 폐기)

- **축이 둘이다 — 섞지 않는다**

  ```
  축 A · 사고 대응 긴급도   EMERGENCY > CALL_NOW > VISIT_SOON > MONITOR
  축 B · 급여 가부          NEVER > CAUTION > SAFE
  ```

  *"포도는 개에게 금지"*(축 B)와 *"포도를 먹었으니 EMERGENCY"*(축 A)는 다른 판정이다.
  **D-38 템플릿의 `{risk_level}`은 축 B**이며, 축 A는 질의 시점에 `물질 + 증상 + (종별) 용량`으로 계산한다.

  | 축 B 값 | 표시 | 근거 |
  |---|---|---|
  | `NEVER` | 급여 금지 | *"should **never be fed** … under any circumstances"* |
  | `CAUTION` | 조건부 | *"**not recommended** but sometimes fed without incident"* / *"with caution"* |
  | `SAFE` | 안전 | *"safe for dogs **in moderation**"* |

  > **조류의 축 B는 2단계(`NEVER`/`CAUTION`)로 축약한다.** S-005와 S-091이 동일 항목
  > (Peanuts · Grit · Mushrooms)을 서로 다른 티어에 배정하고 있어, 3단계를 그대로 노출하면
  > **출처에 없는 정밀도를 주장**하게 된다.

- **종별 판정 근거의 비대칭** — 행동 단계 수는 같고, 판정 재료가 다르다

  | | 지지 단계 | 수치 트리거 |
  |---|---|---|
  | 개 | 4단계 완전. 유일하게 긴급도 라벨 보유(S-080) | 호흡수 40–60/분 · 주목 2.3 g/kg · 간식 10% |
  | 고양이 | **자체 자료는 2단계뿐**(`CALL_NOW`·`VISIT_SOON`) | Allium 체중 0.5% · 3시간 골든타임 |
  | 앵무새 | **4단계 지지** — S-092 단일 문서 안에서 대조 | **출혈 5–10분 1건이 전부** |

  > **고양이는 `mammal/`·`all/` 문서와 반드시 함께 인덱싱**해야 4단계가 성립한다.
  > 조류는 단계 수가 아니라 **판정 근거**가 빈약하다 (D-09 개정 참조).

- **트레이드오프**:
  > 등급 체계를 임의로 정하면 출처에 없는 정밀도를 주장하게 되는 문제를 풀기 위해
  > **코퍼스의 행동 지시어에서 도출**하는 방식을 택했고,
  > 그 덕분에 **모든 등급에 verbatim 근거가 붙고 종별 한계까지 드러난** 대신,
  > **통상적 트리아지 체계와 다른 구성**(정상 단계 없음)을 설명해야 하는 부담과
  > 코퍼스가 바뀌면 등급 근거를 재점검해야 하는 비용을 떠안았다.
- **비고**: **"정상 / 조치 불필요" 단계를 두지 않았다.** 사고 발생 후
  *"아무것도 하지 않아도 된다"* 는 지시가 코퍼스에 **0건**이기 때문이다.
  안전 진술은 전부 축 B(급여 가부)에 속한다.
  또한 `위험`·`중증` 같은 **의학적 중증도 어휘를 쓰지 않는다** — D-11 진단 금지.
  코퍼스의 소스들도 등급 이름 없이 **행동만 지시**하고 있었다
- **미결**: 사용자 노출 배지 표현은 팀 회의에서 확정. **내부 값은 본 결정으로 확정**
- **영향**: D-09 · D-11 · D-38 · 02 §7.2 · 04 §2.5·§4 · 01 §2.2

### D-12 · 평가 목표 재정의 — 문서 충실도

### D-31 · 접근 차단은 사유별로 다르게 처리한다

- **상태**: 확정 (2026-07-30)
- **맥락**: 스냅샷 확보에서 15건이 막혔는데, "막혔다"를 한 덩어리로 다루면
  **뚫어도 되는 것과 뚫으면 안 되는 것을 구분하지 못한다.** 실제로 근거가 서로 다르다
- **결정**: 차단 사유를 4분류하고 각각 다르게 처리한다

  | 사유 | 성격 | 처리 |
  |---|---|---|
  | **기술 오류** (404 · URL 결손 · JS 렌더링) | 아무 제한도 아님 | 주소 정정 후 그대로 수집 |
  | **봇 차단** (403 · CAPTCHA) | 자동화 거부. 사람은 대상 아님 | **사람이 받아 파일로 전달**. 링크 재fetch 아님 |
  | **robots.txt** | RFC 9309 — **크롤러 대상 권고**. *"not a form of access authorization"* | **사람이 받아 파일로 전달만.** 링크를 받아 재fetch하면 사람을 한 번 경유했을 뿐 여전히 자동 수집 |
  | **로그인·구독** | 접근 자체가 계약 대상 | **대체 출처로 교체.** D-32 참조 |

- **트레이드오프**:
  > "막혔다"를 한 덩어리로 다루면 뚫어도 되는 건 포기하고 뚫으면 안 되는 건 우회하게 되는 문제를 풀기 위해
  > 사유별 4분류를 택했고,
  > 그 덕분에 **각 건에 대해 근거 있는 판단**을 하게 된 대신,

#### 개정 이력 — 2026-07-30, 초판을 12개 도메인 38건에 적용한 결과

초판은 5단계를 **한 층으로 나열**했다. 보유 자료에 소급 적용해보니 두 가지가 드러났다.

**① G4·G5는 판정을 한 번도 뒤집지 못했다.** 38건 전부 G1·G2에서 결론이 났다.
다만 **Pet Poison Helpline은 예외**였다 — 약관 페이지 자체가 없어 G1~G3이 전부 "조항 없음"으로
통과하는데, 328행 통째 복제는 **약관과 무관하게 저작권법 제93조**에 걸린다.
즉 G4는 **차단 기준이 아니라, 약관이 침묵할 때 작동하는 사용 조건**이다. 지우지 않고 2층으로 옮긴다.

**② 초판 G1이 성격이 다른 둘을 한 칸에 섞고 있었다.**

| | 예시 | 우리에게 적용되나 |
|---|---|---|
| **목적 금지** | *"prohibited … to **train** any artificial intelligence models"* (Merck)<br>*"use of **artificial intelligence** … to repurpose"* (VCA) | ⛔ 못 피한다 |
| **수단 금지** | *"use any **robot, spider**"* (ASPCA·AKC)<br>*"**spider, crawl, or scrape**"* (WildEarth) | 수동 취득이면 해당 없음 |

이 둘을 구분하지 않아 **판정 근거가 흐려졌다.** 실제 갈림은 수단이 아니라
**G2 — 개인·비상업 복제를 허용하는가**였다.

- ASPCA — *"make a **single copy** … for your **personal and non-commercial** use"* → 허용 있음 → 조건부 통과
- Banfield — *"may not copy or **incorporate any of the Content into any other work**"* → 허용 없음 → 중단
- AKC — Reproduction Policy가 온라인 재이용을 **링크로만** 한정 → 중단

**판정 결과는 바뀌지 않았고 근거만 정정되었다.** ⛔ 4건(petMD·Banfield·AKC·WildEarth)의
사유를 G1 → **G2**로 고쳐 기록한다. *(이 4건은 이후 **D-37**로 재판정된다)*

#### 2차 개정 — 30개 도메인 전수 확인 후 (2026-07-30)

**③ `artificial intelligence`만 검색하면 놓친다.** 전수 확인 결과 **AI를 한 번도 언급하지 않고
벡터 색인을 금지하는 곳이 더 많았다.**

| 출처 | 문언 | AI 언급 |
|---|---|---|
| AVMA | *"…or **incorporate into any information retrieval system** (electronic or hard copy)"* | 없음 |
| FOUR PAWS | *"**stored, processed**, copied or distributed using **electronic systems**"* | 없음 |
| ASPCA | *"must not … **store**, **create derivative works of** …"* | 없음 |

셋 다 RAG를 정면으로 막는다. **G1a 검색어에 ②번 묶음을 추가**한다 —
`information retrieval system` · `storage and retrieval` · `stored, processed` ·
`electronic systems` · `store` · `derivative works`.

**이 검색어 추가로 ASPCA 6건이 "조건부 통과" → "사실추출 한정"으로 하향**되었다.

### D-37 · G2는 복제를 규율하고, G1a는 용도를 규율한다 🔒

- **상태**: 확정 (2026-07-30)
- **맥락**: D-35 게이트를 보유 자료에 적용해 18건이 ⛔로 판정됐다. 그런데 다음 질문이 남았다 —

  typically does not require permission"* 이라고 명시한다.

  내부에 남은 원문을 채점 기준으로 삼아 검증한다.

- **트레이드오프**:
  > 약관에 걸린 자료를 전부 버리면 근거가 고갈되는 문제를 풀기 위해
  > 규율 대상(복제/용도)을 구분한 판정을 택했고,
  > 그 덕분에 **⛔ 18건을 13건으로 줄이고 판정에 논리적 일관성을 얻은** 대신,
  > **원문 청크를 그대로 적재하는 편의를 포기**하고 문장화 공정을 필수로 떠안았다.
- **비고**: 우리는 변호사가 아니며, 약관(계약)이 저작권법상 자유이용을 어디까지 배제할 수 있는지는
  다툼의 여지가 있는 영역이다. **다만 G1a처럼 "AI에 쓰지 마라"라고 의사를 명시한 곳은
  법적 다툼과 별개로 존중한다** — D-33에서 정한 기준이 그것이다

#### 적용 한계 — 사실 추출로 회피되는 조항과 안 되는 조항 (2026-07-30 전수 재판정)

⛔ 19건을 이 기준으로 하나씩 다시 읽었다. **갈림은 조항이 무엇을 목적어로 삼는가**에 있다.

**회피되지 않는다 — 조항이 우리 행위 자체를 이름으로 부른다**

| 출처 | 문언 | 왜 못 피하나 |
|---|---|---|
| **VCA** (8) | *"use of artificial intelligence … to **rewrite**, republish, **adapt**, or **repurpose** this content, **in whole or in part**"* | "사실을 뽑아 우리 문장으로 재구성"이 곧 `rewrite`·`repurpose`다. `in whole or in part`라 부분 발췌도 막힌다 |
| **Merck** (5) | *"use any **manual or automated** … processes to 'scrape', 'data mine', **extract** … any data … **for any purpose**"* | `extract`가 사실 추출이다. `manual`까지 포함해 **사람이 읽고 정리해도** 걸린다 |

**회피된다 — 조항이 "저작물·Content"를 목적어로 삼는다**

| 출처 | 문언 | 왜 피할 수 있나 |
|---|---|---|
| **AVMA** (1) | *"…incorporate into any information retrieval system … **the AVMA Services, any Content or any portion thereof**"* | 금지 대상이 **AVMA의 Content**다. 우리가 쓴 문장은 Content가 아니다 |
| **FOUR PAWS** (2) | *"None of **the works** … may be … stored, processed"* | 금지 대상이 **the works**(저작물)다. 사실은 저작물이 아니며, *"single reproductions for personal, non-commercial use"* 도 허용한다 |
| **AAFCO** (1) | G3 유료 판정 | **도메인 단위 판정 오류였다.** 유료인 것은 Official Publication이고 **우리가 보유한 S-042는 무료 소비자 페이지**다 |

**조건부**

- **S-031 (Kaggle ASPCA CSV)** — 사실 추출은 가능하나 **1,896행 전량은 불가**. 저작권법 제93조 데이터베이스제작자 권리의 *"전부 또는 상당한 부분"* 에 해당한다 (D-34). **질의에 필요한 항목만** 추출하고 원본 CSV는 아카이브에서 제거
- **S-032 (VIN)** — 약관 확인 불가로 보류. 내용이 인덱스 페이지(품질 `빈약`)라 **실익이 없어** 제외
- **S-021 (WildEarth)** — 법적으로는 가능하나 비건 사료 D2C 브랜드 마케팅. **출처 신뢰도로 제외**

> **재판정 결과: ⛔ 19건 → 13건.**

**출처 표기는 별개다.** 코퍼스에 넣지 못하는 것과 참고문헌에 적는 것은 다르다.
⛔ 13건도 `SOURCES_CITED.csv`에 남기고, 산출물에는
**"확인했으나 라이선스상 적재하지 않음"** 으로 기록한다 — **검증 과정의 근거가 된다.**

**사실은 독점되지 않는다.** ⛔ 자료에서 확인한 사실이 **통과 판정 출처에도 있으면**
그 출처로 인용하면 된다. 예: 고양이 응급 징후는 VCA(⛔) 대신 AAHA S-037·S-038로 대체 가능하다.
⛔ 자료를 **"우리가 아는 사실의 목록"** 으로 삼아 교차 확인하는 작업을 01c에 신설한다.

- **영향**: 01 §2 · 01c §6.1·§6.2·§6.4 · D-15 · D-29 · D-33 · D-34 · D-35 · D-38

### D-38 · 문장화는 코드가 한다 — 그리고 문장화도 검증 대상이다 🔒

- **상태**: 확정 (2026-07-30)
- **맥락**: D-37로 대부분의 자료가 **경로 ②(사실 추출 + 자체 문장화)** 로 가게 되었다.
  그런데 벡터DB에 들어가는 것이 **우리가 쓴 문장**이면 새로운 문제가 생긴다.

  ```
  [런타임]  답변 ↔ 검색된 청크        → sLLM ④ 근거 검증이 담당 (기존)
  [빌드타임] 우리 문장 ↔ 원문          → 🆕 검증 주체가 없다
  ```

  **환각 방지 지점이 답변 단계에서 문장화 단계로 이동한다.**
  D-30에서 같은 것을 이미 보았다 — *"축약된 문장을 원문으로 오인하면 그 자체가 환각의 출처가 된다."*
- **대안**: (a) LLM에게 문장화를 시키고 사후 검증 (b) **템플릿을 미리 만들고 코드가 생성**
- **결정**: (b). **축① "결정론은 코드로, 판단·해석만 LLM에게"의 적용이다.**

  ```
  원문 ──[추출]──→ 사실 표 ──[템플릿]──→ 문장
                      ↑                    ↑
                여기만 검증하면      템플릿은 한 번만
                    된다              사람이 검수
  ```

  **템플릿은 발명하지 않고 데이터에서 도출한다.** 코퍼스의 `doc_type` 축을 그대로 쓴다 —
  `toxicity_food`(27) · `nutrition`(21) · `toxicity_plant`(11) · `emergency`(9) · `symptom`(7).

  ```python
  # toxicity_food 템플릿
  "{species}에게 {substance}은(는) {risk_level}로 분류된다."
  + if threshold: "체중 1kg당 {dose}{unit} 이상 섭취 시 위험하다."
  + if signs:     "주요 증상은 {signs}이다."
  + if onset:     "증상은 {onset} 이내에 나타난다."
  + "(출처: {publisher}, {source_id})"
  ```

  **결측 필드는 해당 절을 통째로 뺀다.** "정보 없음"이라고 쓰지 않는다 —
  그 문장이 검색되면 그 자체가 오답이 된다.

  > **부수 효과**: 임계값 필드가 비면 정량 문장이 생성되지 않는다.
  > 조류는 정량 임계치가 0건이므로 **조류 청크는 자동으로 정성 문장만 나온다.**
  > **D-09의 종별 분기가 데이터 단계에서 강제되어** 규칙 테이블에서 따로 막을 필요가 없다.

- **검증 체계**: 검증 대상이 문장이 아니라 **필드**로 축소된다.

  | 층 | 검사 | 방법 |
  |---|---|---|
  | **자동** | 그 숫자가 원문에 실제로 있는가 | 원문 문자열 검색 |
  | **자동** | **단위 변환 오류** | 재계산 — S-074에 실제 사례가 있다 (*"530°F (280°C)"*, 280°C = 536°F) |
  | **자동** | 종 이름이 원문과 일치하는가 | 문자열 대조 |
  | **자동** | 필수 필드 결측 | 스키마 검사 |
  | **사람** | 템플릿 검수 | **한 번만.** 템플릿이 맞으면 필드가 맞는 한 문장도 맞다 |
  | **사람** | 표본 대조 | 무작위 N건을 원문과 대조. **작성자·검수자 분리** (04 §2.4) |

  **04에 지표 3종을 추가한다** — 추출 정확도 / 문장화 충실도(원문에 없는 내용 생성 = **0**) /
  역추적 가능성(모든 청크가 `source_id` + 원문 위치 보유 = **100%**).

- **트레이드오프**:
  > 사실 추출이 문장화라는 새 환각 지점을 만드는 문제를 풀기 위해
  > 템플릿 기반 코드 생성을 택했고,
  > 그 덕분에 **검증 대상을 문장에서 필드로 축소**하고 종별 분기까지 데이터 단계에서 강제하게 된 대신,
  > **문장 표현이 획일화되어 임베딩 변별력이 떨어지는** 위험과 템플릿 설계 공정을 떠안았다.
- **완화**: 필드 값(물질명·종·증상)이 문장에 그대로 들어가고, 청킹이 물질 단위(D-14)라 항목별로 분리된다.
  효과는 **E1(청킹 단위 비교)에 "템플릿 문장 vs 원문 청크" 비교를 추가**해 측정한다 —
  라이선스 제약에서 나온 선택이 **측정 가능한 설계 판단**이 된다
- **비고**: 이 검증은 **빌드타임 비용**이다. 런타임마다 도는 것이 아니라 코퍼스 구축 시 한 번이면 끝난다.
  그리고 이 과정 자체가 04 §7(실패 분석)의 재료가 된다 —
  **"답변 단계뿐 아니라 데이터 단계에서도 환각을 막았다"**
- **영향**: 01 §2.1 · 04 §3·§7 · 04 E1 · D-09 · D-14 · D-15 · D-30 · D-37

### D-36 · 개인정보는 LLM에 닿기 전에 코드가 벗긴다 🔒

- **상태**: 확정 (2026-07-30)
- **맥락**: 본 도메인을 고른 이유 중 하나가 **개인정보 리스크가 낮다**는 것이었고(D-01),
  법적으로도 맞다. 확인한 바는 다음과 같다.

  | 확인한 것 | 근거 |
  |---|---|
  | **반려동물 정보 자체는 개인정보가 아니다** | 개인정보보호법 제2조1호 — "**살아 있는 개인**에 관한 정보". 제2조3호 정보주체 = "**사람**" |
  | **반려동물 건강정보는 민감정보가 아니다** | 제23조의 "건강"은 **정보주체(사람)의** 건강. 동물 진료기록은 해당 없음 |

  **그런데 위험은 동물 정보가 아니라 거기 딸려 오는 것에 있다.**

  | 항목 | 왜 문제인가 |
  |---|---|
  | **동물등록번호** | 동물보호법 시행령 제11조 — 등록 시 소유자 **성명·주민등록번호·주소·전화번호**가 함께 등록된다. 시행규칙 제12조는 인식표에 **소유자 성명·전화번호와 등록번호를 함께 표시**하도록 규정. 제2조1호 **나목(쉽게 결합)** 판단 대상이다 |
  | **사진 EXIF의 GPS** | 위치정보법 제2조2호 개인위치정보 — "다른 정보와 **용이하게 결합**하여 특정 개인의 위치를 알 수 있는 것을 포함". 제15조1항의 수범자는 "**누구든지**" — 사업자 여부와 무관하다 |
  | **사진 속 사람 얼굴** | 제2조1호 **가목** — "**영상 등**을 통하여 개인을 알아볼 수 있는 정보". PIPC 표준 해석례도 얼굴 사진 자체를 개인정보로 본다 |
  | **급여·배변·체중 시계열** | 누적되면 **생활 패턴**이 드러난다 |

- **대안**: (a) 입력 단계에서 사용자에게 주의 안내 (b) **코드가 기계적으로 제거**
- **결정**: (b). **축① "결정론은 코드로, 판단·해석만 LLM에게"의 적용이다.**
  개인정보 제거는 판단이 아니라 결정론이다. LLM에게 맡길 일이 아니다

  | # | 조치 | 근거 |
  |---|---|---|
  | 1 | **동물등록번호를 슬롯에서 제외**. 프로필 식별은 앱 내부 UUID | 제16조 최소수집. 트리아지에 필요한 건 종·품종·체중·나이·기저질환뿐이다 |
  | 2 | **업로드 직후 코드가 EXIF를 전량 제거**. GPS·촬영기기·시각 모두. 원본 EXIF는 보관하지 않는다 | 위치정보법 제15조 |
  | 3 | **얼굴 검출 시 마스킹 또는 저장 거부** | 제2조1호 가목 + 제16조 — 다이어리 목적에 사람 얼굴은 불필요 |
  | 4 | **보호자 본인의 건강정보는 슬롯 추출 단계에서 폐기** | 제23조 민감정보 — 별도 동의 대상이며 우리는 받지 않는다 |
  | 5 | **LLM·외부 API 전송 전 필터를 코드로 강제**. 필터를 통과한 것만 나간다 | 축① |
  | 6 | **LangSmith 트레이스에 실입력을 남기지 않는다** | 02 §10·04 §8의 트레이스가 **입력 원문을 그대로 저장**한다. 데모 입력은 가명화하거나 트레이스에서 제외 |
  | 7 | 학습·평가는 **가상 프로필만**(D-18). 데모 입력 기록은 **발표 종료 시 전량 파기** | 제21조 — 목적 달성 시 지체 없이 파기 |

- **트레이드오프**:
  > 반려동물 도메인이라 개인정보가 안전하다는 인식이 사진·등록번호·시계열의 위험을 가리는 문제를 풀기 위해
  > 코드 단계의 기계적 제거를 택했고,
  > 그 덕분에 **사용자의 주의력에 의존하지 않고 구조로 막게 된** 대신,
  > **전처리 파이프라인에 EXIF 제거·얼굴 검출 단계를 추가**하는 비용을 떠안았다.
- **비고**: 6번이 가장 놓치기 쉽다. **관측을 위해 넣은 LangSmith가 개인정보 저장소가 된다.**
  D-20(코퍼스 버전 태깅)·D-13(과소평가율 추적)이 모두 트레이스에 의존하므로 지우기도 어렵다.
  **가명화를 트레이스 설정 단계에서 켠다**
- **미결**: 얼굴 검출을 로컬 모델로 할지 API로 할지 → WS2·WS5 결정 대기
- **영향**: 01 §14 · 02 §10 · 04 §8 · 00 §리스크 · D-18

### D-40 · 배달 계층 — 화면이 아니라 계약을 먼저 고정한다 🔒

- **상태**: 확정 (2026-07-31)
- **맥락**: D-21이 *"UI는 가드레일 뒤"* 로 정했는데, 00 §9.3은 *"UI 스펙은 WS2와 사전 합의한다"* 를
  요구한다. **화면은 나중인데 합의는 먼저**라는 것이 모순처럼 보였다.

  모순이 아니다. **나중에 오는 것은 화면이고, 먼저 정해야 하는 것은 계약이다.**
  계약이 없으면 WS2는 무엇을 반환할지 모른 채 그래프를 짜고, WS5는 무엇이 올지 모른 채
  화면을 짠다. 둘이 만나는 시점에 재작업이 발생하는데, **D-21이 막으려던 것이 정확히 그 재작업**이다.
- **대안**:
  (a) Streamlit 단독 — 가장 빠르지만 API 계층이 없어 계약이 코드에 묻힌다.
      산출물 ③ *"연동 구현 코드"* 로 보여줄 경계가 흐려진다
  (b) React + Vite 별도 프론트 — 화면이 늘 때 유리하나 node 의존성·CORS·빌드 산출물 관리가 붙는다
  (c) **FastAPI + 정적 HTML 1장, 같은 출처 서빙**
- **결정**: (c). 그리고 **계약을 먼저 확정하고 엔진은 스텁으로 둔다.**

  ```
  web/index.html ──HTTP──> FastAPI ──Protocol──> QAEngine
                            (계약)                 ├─ StubEngine   ← 지금
                                                   └─ GraphEngine  ← WS2 완성 후
  ```

  빌드 도구도 node도 CORS 설정도 없다. 시연 재현이 `make serve` 한 줄로 끝난다 (04 §8).

  **세부 결정 네 가지가 이 결정의 실체다.**

  **① 거절을 4xx가 아니라 200으로 내보낸다.**

  `/api/ask` 는 항상 200을 반환하고 `status` 가 `answered` / `clarify` / `refused` 를 나른다.
  02 §9에서 **거절은 장애가 아니라 설계된 정상 경로**로 정의했다.
  4xx로 만들면 프론트가 에러 핸들러에서 처리하게 되고, **거절 화면이 장애 화면처럼 그려진다.**
  전송 계층 실패(500)와 정책상 거절을 구분하지 못하면 00 §7의 감점 항목
  *"검색 실패와 생성 실패를 구분하지 않은 오류 분석"* 을 그대로 재현하게 된다.

  **② 정책을 문서가 아니라 스키마로 강제한다.**

  | 불변식 | 위반 시 | 근거 |
  |---|---|---|
  | `answered` 인데 `citations` 가 비었다 | **응답 객체 생성 실패** | 02 §9 — 근거 없으면 답하지 않는다 |
  | `MONITOR` 인데 상승 조건이 없다 | **응답 객체 생성 실패** | D-39 — 조건 없는 "관찰"은 과소평가다 |
  | 경로 ② 근거에 원문 인용이 실렸다 | **응답 객체 생성 실패** | D-37 — 원문은 벡터DB에 없다 |

  세 항목 모두 **런타임 검사가 아니라 타입 수준**이다. 지키자고 합의한 것이 아니라
  어기면 응답이 만들어지지 않는다. 05 §6 *"LLM에 맡긴 지점마다 검증 코드가 한 겹 붙는다"* 의
  배달 계층 판본이다.

  **③ 엔진을 프로토콜 뒤에 둔다.**

  라우터는 `QAEngine` 프로토콜만 안다. WS2의 LangGraph가 완성되면 **주입 지점 한 줄**을 바꾼다.
  계약·프론트·테스트는 손대지 않는다. 지금의 `StubEngine` 은 검색과 LLM만 고정값이고
  **되묻기·상한 초과 거절·하향 금지 게이트는 실제로 통과시킨다** — 벡터DB 없이도 D-09·D-10·D-39가
  동작하는 것을 시연할 수 있다.

  **④ 등급 표현의 단일 출처를 API로 만든다.**

  `GET /api/triage-levels` 가 등급 이름·배지·행동 문장과 **도출 근거 원문(verbatim)** 을 함께 내려준다.
  프론트가 등급 표현을 자기 코드에 복사하면 D-39가 개정될 때 화면만 옛 표현으로 남는다.
  00 §9.4 단일 출처 원칙을 규칙이 아니라 **구조**로 만든 것이다.

- **트레이드오프**:
  > 판정 로직이 확정되기 전에 화면을 만들면 재작업이 생기고, 계약 없이 병렬 작업하면
  > WS2와 WS5가 만나는 지점에서 또 재작업이 생기는 문제를 **동시에** 풀기 위해
  > **계약 우선 + 스텁 엔진**을 택했고,
  > 그 덕분에 **로직 완성 전에도 WS5가 착수할 수 있고 정책 위반이 타입 오류로 잡히게 된** 대신,
  > **스텁과 실제 엔진 두 벌을 유지**하고 계약이 바뀔 때마다 양쪽을 고치는 부담을 떠안았다.

- **미채택 — SSE 스트리밍**: 토큰이 흘러나오는 체감은 좋으나, **등급이 확정되기 전에 문장이 먼저
  나가면 근거 검증 실패 시 이미 뱉은 문장을 회수할 수 없다.** 04 §4.1.0의 중대 과소평가율 0 목표와
  충돌한다. 축② *"통제가 먼저, 배달이 나중"* 이 문장 단위에도 적용된다.

- **비고**: 세션 저장소를 메모리로 두었다. 되묻기 슬롯(체중·섭취량)을 **보관하지 않는 것이
  D-36 최소수집과 맞다** — 프로세스가 죽으면 사라지는 것이 의도다.
  다중 워커로 띄울 때만 외부 저장소로 교체한다.
  또한 `answer` 만 읽는 클라이언트가 상승 조건을 빠뜨리지 않도록 `full_text` 필드를 함께 내보낸다 —
  **조건 누락은 이 도메인에서 과소평가와 같다** (D-39).

- **영향**: 00 §9.3·§10 · 02 §12·§13 · 04 §8 · 05 §2(조각 12) · D-09 · D-11 · D-21 · D-36 · D-37 · D-39

### D-41 · 저장소 구조 — 파라미터를 코드에서 빼고 의존성을 쪼갠다

- **상태**: 확정 (2026-07-31)
- **맥락**: 골격이 커지면서 두 가지가 걸렸다.

  **① 파라미터가 코드에 박혀 있었다.** `top_k=5`, `chunk_size=500`, LoRA rank가
  각각 다른 파일에 있었다. 04 §8이 재현성을 요구하는데, 실험 보고서에
  *"그때 top-k가 몇이었더라"* 를 적을 방법이 없다. 04의 감점 항목
  *"재현 불가 — 버전 미고정, 시드 미설정"* 을 그대로 밟는 구조였다.

  **② 의존성이 한 덩어리였다.** `requirements.txt` 하나에 torch와 fastapi가 같이 있어
  **API만 띄우려는 팀원도 수 GB를 받아야 했고**, CI도 마찬가지였다.

- **대안**:
  (a) 지금 구조 유지 — 4주 프로젝트에 과한 정비다
  (b) 모노레포(`apps/` + `packages/`) — 4인 규모에 과잉
  (c) **설정 외부화 + 의존성 그룹 분리 + 컨테이너**
- **결정**: (c). 네 가지를 바꿨다.

  **① 설정을 `configs/*.yaml` 로 뺀다.** 경계는 **재현에 필요한가**로 갈랐다.

  | | 어디 | 커밋 | 예 |
  |---|---|---|---|
  | 재현에 필요 | `configs/*.yaml` | **한다** | 모델 ID, LoRA rank, top-k, 임계값, 시드 |
  | 비밀·환경차이 | `.env` | 안 한다 | API 키, DB 주소, 트레이싱 on/off |

  **실험 결과를 보고할 때 YAML을 그대로 첨부하면 재현이 된다.**
  프로파일(`default` → `<profile>` → 환경변수) 순으로 덮으므로,
  평가는 `PETTRIAGE_PROFILE=eval` 하나로 조건이 고정된다.

  **② 의존성을 `[api] [rag] [ingest] [train] [dev]` 로 쪼갠다.**
  GPU 없는 팀원은 `pip install -e '.[api]'` 로 끝난다.
  버전 고정은 `constraints.txt` 가 따로 맡는다 — **무엇을 설치할지(extras)와
  어느 버전으로 고정할지(constraints)를 분리**해야 둘을 독립적으로 바꿀 수 있다.

  **③ 무거운 임포트를 함수 안으로 내린다.** `models/` 의 torch·transformers 임포트가
  모듈 최상단에 있으면 CI가 학습 의존성 없이 못 돈다. 이것은 스타일이 아니라 **제약**이며,
  CI의 `test` job이 `[api,dev]` 만 설치하는 것으로 강제된다.

  **④ 컨테이너를 나눈다.** API 이미지(`Dockerfile`)에 torch를 넣지 않고,
  학습은 `docker/train.Dockerfile` 로 분리한다. `compose.yaml` 에 pgvector를 함께 올려
  02 §11의 벡터DB 후보를 실제로 시험할 수 있게 한다.
  `.dockerignore` 가 `data/` 를 차단한다 — **이미지에 자료가 구워지면 배포가 곧 유출**이다 (D-29).

- **트레이드오프**:
  > 파라미터 산재로 재현이 안 되고 의존성 덩어리로 착수 비용이 큰 문제를 풀기 위해
  > 설정 외부화와 의존성 분리를 택했고,
  > 그 덕분에 **실험 조건을 파일 하나로 고정하고 GPU 없이도 개발할 수 있게 된** 대신,
  > **설정이 코드와 YAML 두 곳에 존재**하게 되어 기본값이 어긋날 여지와
  > 그룹별 설치를 팀원에게 안내해야 하는 부담을 떠안았다.
- **완화**: 어긋남이 위험한 값은 **테스트가 일치를 검사한다** —
  `triage.max_clarify_turns` 와 `contracts.MAX_CLARIFY_TURNS` 가 그 예다.
  안전에 직결되는 설정은 반드시 이 형태로 묶는다.
- **비고**: 어댑터·체크포인트는 `artifacts/` 로 보내고 커밋하지 않는다.
  **재현은 가중치가 아니라 `configs/` + `constraints.txt` + 시드로 한다.**
- **영향**: 00 §9.4 · 04 §8 · README · `configs/README.md` · D-20 · D-29 · D-40 · D-42
