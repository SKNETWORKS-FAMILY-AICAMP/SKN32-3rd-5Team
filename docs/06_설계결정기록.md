## 0. 이 문서의 목적

> **설계의 매 순간마다 "왜 이렇게 설계했는가"에 명확한 이유를 댈 수 있어야 한다.**

"왜"에는 두 종류가 있다.

| 종류 | 질문 | 답하는 곳 |
|---|---|---|
| **존재의 이유** | 이 조각이 왜 필요한가 — 앞 조각의 어떤 한계를 푸는가 | **05** 정지 판정 |
| **선택의 이유** | 여러 대안 중 왜 이것을 골랐는가 | **본 문서** |

### 0.1 기록 형식

```
- 상태 / 맥락 / 대안 / 결정 / 트레이드오프 / 영향
```

**트레이드오프 문장이 핵심이다.**

> `[문제]를 풀기 위해 [선택]을 택했고, 그 덕분에 [얻은 것] 대신, [감수한 것]을 떠안았다.`

감수한 것을 적지 않은 "왜"는 자기 합리화이고, 적으면 설계 판단이 된다.
심사·리뷰에서 *"단점은 없나요?"* 라는 질문에 이미 답이 준비되어 있게 된다.

### 0.2 기록 규칙

- ✅ 기록한다 — 되돌리기 어려운 결정, **대안이 실제로 있었던** 결정, 나중에 질문받을 결정
- ❌ 기록하지 않는다 — 자명한 것, 언제든 바꿀 수 있는 것(변수명, 사소한 라이브러리 선택)
- 결정이 뒤집히면 **삭제하지 않고 `폐기` 또는 `대체됨` 상태로 남기고 새 번호를 부여**한다.
  **뒤집힌 이력 자체가 근거다.**
- 상태: `확정` / `제안` / `조건부` / `폐기` / `대체됨(→ D-xx)`
- **결번 D-23~D-28** — 문서 5분할(D-22) 직후 번호를 앞당겨 붙이면서 비었다.
  D-29의 비고가 참조하는 `D-28(사실 추출 + 출처 표기)` 은 **D-37로 대체**되었다.

- **상태**: 확정 (2026-07-30)
- **맥락**: 과제 요건이 "내외부 문서 기반 QA"이고, 팀 기준으로 *"전문 지식이 없어 정보를 찾기 힘든 일상 영역"* 을 지향
- **대안**: (a) 근로계약서 검토 (b) 임대차 계약 검토 (c) 전자제품 A/S (d) 헬스장·학원 환불 (e) **반려동물 헬스케어**
- **결정**: (e). 환각 당위성·페인 포인트·분류 체계·신선함·시연 임팩트에서 우위이며, **개인정보 리스크가 낮아 개인 기록 축적 확장이 가능한 유일한 후보**
- **트레이드오프**:
  > 정보 비대칭이 큰 일상 영역을 다루려는 문제를 풀기 위해 반려동물 헬스케어를 택했고,
  > 그 덕분에 시연 임팩트와 확장성을 얻은 대신,
  > **정답 검증이 어렵고(수의학 지식 부재) 범위가 쉽게 폭증하는** 부담을 떠안았다.
- **영향**: 00 §3 · `도메인검토-반려동물-헬스케어.md`
- **연관**: D-12(정답 검증 우회) · D-21(범위 관리)

### D-02 · 브이로그 다이어리로 확장

- **상태**: 확정 (2026-07-30)
- **맥락**: 원안(중독 응급 QA)은 **"무엇이 내부 문서인가"** 에 답하지 못했고, 요약 태스크의 필연성도 약했다
- **대안**: (a) 동물병원 원내 프로토콜을 가상 생성해 내부 문서로 (b) 반려동물 프로필만 내부 데이터로 (c) **일상 기록 다이어리를 내부 문서로**
- **결정**: (c). 개인 기록이 곧 내부 문서가 되어 *"내 문서 × 공적 기준 → 판정"* 구조가 성립하고, **기간 요약 리포트**라는 킬러 유스케이스가 생긴다
- **트레이드오프**:
  > 내부 문서 부재와 요약 필연성 부족이라는 문제를 풀기 위해 다이어리 확장을 택했고,
  > 그 덕분에 두 약점을 동시에 해소하고 RAG 필연성까지 강화한 대신,
  > **다이어리 CRUD라는 RAG와 무관한 구현 부담**과 범위 폭증 리스크를 떠안았다.

## 2. 구조

### D-04 · RAG와 파인튜닝의 역할 분리

- **상태**: 확정 (2026-07-30)
- **맥락**: 과제가 RAG와 멀티태스크 파인튜닝을 **동시에** 요구한다. 둘을 어떻게 한 시스템에 담을 것인가
- **대안**: (a) 파인튜닝으로 도메인 지식 주입 + RAG 보조 (b) **RAG가 지식, sLLM은 보조 태스크** (c) 둘을 별개 산출물로 병렬 제출
- **결정**: (b). *"RAG가 근거를 가져오고, 파인튜닝한 sLLM이 그 근거가 지켜졌는지 검증한다"*
- **트레이드오프**:
  > 두 요건이 따로 노는 문제를 풀기 위해 역할 분리 구도를 택했고,
  > 그 덕분에 두 요건이 하나의 목표(환각 방지)로 묶이고 **파인튜닝 실패 시에도 폴백으로 시스템이 동작**하는 대신,
  > sLLM이 최종 답변을 생성하지 않아 **"파인튜닝 효과"를 보여주려면 별도 비교 실험이 필요한** 부담을 떠안았다.
- **영향**: 00 §2 · 03 §1 · 04 §5

### D-05 · 멀티태스크 구성 5종 (+번역 조건부)

- **상태**: 확정 (2026-07-30) / **⑥ 번역은 채택하지 않는다** — 2026-08-01, D-19 후속으로 닫힘.
  **멀티태스크 5종 확정**
- **맥락**: 공지는 "분류·요약·번역"을 예시로 들었을 뿐 태스크 구성은 선택 가능
- **대안**: (a) 공지 예시 그대로 분류·요약·번역 (b) **파이프라인이 실제로 필요로 하는 태스크로 재구성**
- **결정**: (b) — ① 분류 ② 슬롯 추출 ③ 압축 요약 ④ **근거 검증** ⑤ 평이화. 번역은 조건부 ⑥
- **근거**: ④가 과제 목표 1번(환각 방지)을 파인튜닝 모델이 직접 담당하게 만든다. 출력 길이가 다른 태스크를 의도적으로 섞어 **태스크 간섭이라는 실제 논점**을 확보
- **트레이드오프**:
  > 억지로 채운 태스크는 "왜 하는가"에 답할 수 없다는 문제를 풀기 위해 파이프라인 수요 기반 재구성을 택했고,
  > 그 덕분에 각 태스크의 존재 이유를 ablation으로 증명할 수 있게 된 대신,
  > **공지 예시와 다른 구성을 설명해야 하는** 부담과 태스크 5종의 학습 부하를 떠안았다.
- **영향**: 03 §2 · 04 §3 · 04 E4

### D-06 · ReAct · MCP · 멀티에이전트 미채택

- **상태**: 확정 (2026-07-30)
- **맥락**: 에이전트 스택을 어디까지 붙일 것인가 — 정지 판정
- **대안**: (a) 전부 채택 (b) 도구 루프만 (c) **세 가지 모두 미채택**
- **결정**: (c)
  - **ReAct** — 계산 노드는 있으나 **LLM이 도구를 선택할 필요가 없다.** intent가 정해지면 어떤 계산이 필요한지 코드가 안다
  - **MCP** — 도구 재사용·표준화 수요 없음. 외부에 도구를 노출할 계획 없음
  - **멀티에이전트** — God Object 아님. 도구 5~7개+ 아님
- **트레이드오프**:
  > 한계가 드러나지도 않은 조각을 미리 붙이면 복잡도만 오른다는 문제를 풀기 위해 세 조각을 배제했고,
  > 그 덕분에 과설계를 피하고 디버깅 가능한 구조를 유지한 대신,
  > **"요즘 기술을 안 썼다"는 인상을 줄 수 있는** 위험과 매 단계 필요성을 판단해야 하는 부담을 떠안았다.
- **비고**: 후자의 위험은 **미채택 근거를 문서로 남김으로써** 상쇄한다. "안 썼다"가 아니라 "판정해서 뺐다"
- **영향**: 02 §1.1 · 05 §2

### D-42 · 베이스 sLLM — Qwen3-4B QLoRA

- **상태**: 확정 (2026-07-31)
- **맥락**: D-05가 태스크 5종을 정했으나 **어떤 모델에 얹을지가 비어 있었고**,
  이것이 학습 데이터 형식·프롬프트 템플릿·평가 비교군을 전부 막고 있었다.
  제약은 세 가지였다 — ① 한국어 성능 ② 상업적으로 안전한 라이선스
  ③ **팀이 실제로 굴릴 수 있는 VRAM**.
- **대안**: (a) Qwen3-1.7B (b) **Qwen3-4B** (c) Qwen3-8B 이상
- **결정**: (b) Qwen3-4B, QLoRA 4bit(NF4) + LoRA r=16.
  00 §5에 적은 *"1~4B급"* 의 상한이며, 4bit로 16GB VRAM에 들어간다.

  **1.7B를 택하지 않은 이유가 태스크 구성에 있다.** 이 프로젝트의 핵심 태스크는
  ④ 근거 검증이고(D-05), 이것은 라벨 분류가 아니라 **문장별 판단**이다.
  출력 길이가 서로 다른 5종을 한 어댑터에 얹으면 간섭이 생기는데(04 E4),
  용량이 작을수록 그 간섭이 성능 붕괴로 나타난다. 8B는 QLoRA로도 학습 시간이
  팀 일정에 맞지 않는다.

  **학습 스택은 HF PEFT + TRL**로 고정한다. Unsloth가 더 빠르지만 래퍼 계층이
  하나 더 생기고, 산출물 ③·④에서 *"무엇을 어떻게 학습했는가"* 를 설명할 때
  표준 스택 쪽이 검증하기 쉽다.

- **04 비교군과의 대응** — 같은 `LLMClient` 프로토콜 뒤에 셋을 둔다.

  | 비교군 | 구현 | 의미 |
  |---|---|---|
  | **A** | `APIClient` (대형 LLM) | 상한선이자 **폴백 경로** (D-21) |
  | **C** | `LocalQwenClient` (어댑터 O) | 파인튜닝 효과 |
  | **D** | `LocalQwenClient` (어댑터 X) | 베이스 대비 증분 |

  C와 D가 **같은 클래스**여야 조건이 동일해진다. 어댑터 유무만 다르게 둔다.

- **트레이드오프**:
  > 태스크 5종을 한 모델에 얹으면서 팀 GPU 안에 들어가야 하는 문제를 풀기 위해
  > Qwen3-4B QLoRA를 택했고,
  > 그 덕분에 **④ 근거 검증에 필요한 용량을 확보하면서 16GB에서 학습 가능**해진 대신,
  > **1.7B 대비 실험 반복 속도가 느려지고** 4bit 양자화로 인한 성능 손실을
  > 비교군에서 분리해내기 어려워지는 부담을 떠안았다.
- **비고**: `configs/default.yaml` 의 `model.revision` 을 **학습 착수 시 반드시 채운다.**
  모델도 코퍼스처럼 버전이 있고(D-20), 비워두면 재현이 깨진다.
  또한 평가 시 `do_sample=False` 를 강제한다 — 샘플링이 섞이면 04 §8이 성립하지 않는다.
- **미결**: 4bit 손실 분리를 위한 bf16 대조군을 돌릴지 (GPU 여유에 따라 판단)
- **후속 (2026-08-01)**: **`transformers` 하한이 이 결정에 종속된다.**

  `constraints.txt` 가 `transformers==4.48.0` 을 박고 있었는데, **Qwen3 아키텍처 지원은
  4.51 부터**다. 그대로 두면 학습 착수 당일 모델 로드 시점에야 발견됐을 문제다.
  `4.51.3` 으로 올리고, `pyproject` 하한도 `>=4.51` 로 함께 올렸다.

  연쇄로 두 개가 더 움직였다 — `chromadb 0.5.23` 이 `tokenizers<=0.20.3` 을 요구해
  충돌하므로 `0.6.3` 으로, `langchain-community 0.3.14` 가 py3.11 에서 `numpy<2` 를
  요구하므로 `0.3.24` 로 올렸다(`langchain-core` 는 그에 딸려 `0.3.63`).

  **이 조합은 Python 3.11 에서 실제 설치·테스트·Chroma 왕복까지 확인했다.**

  > **왜 CI 가 못 잡았나** — `test` 잡이 `.[api,dev]` 만 설치해서 `rag` 그룹이
  > 한 번도 해결된 적이 없었다. `rag-deps` 잡을 추가해 설치 해결과
  > **Qwen3 지원 여부를 CI 가 직접 검사**하게 했다. 하한이 다시 내려가면 CI 가 막는다.

### D-09 · 트리아지 하향 금지 게이트 🔒

- **상태**: 확정 (2026-07-30)
- **맥락**: 트리아지 등급을 LLM이 판정하면 **과소평가(under-triage) 시 생명 위험**이 발생한다
- **대안**: (a) LLM 단독 판정 (b) 규칙 테이블 단독 (c) **하이브리드 + 하향 금지 게이트**
- **결정**: (c). 규칙 테이블이 1차 판정(`물질 × 종 × 체중당 섭취량`), LLM은 규칙 미적용 케이스만.
  최종 등급 = **위험도 기준 `max(rule, llm)`** — **LLM은 등급을 낮출 수 없다**
- **트레이드오프**:
  > LLM 판정이 과소평가를 낼 수 있다는 문제를 풀기 위해 하향 금지 게이트를 택했고,
  > 그 덕분에 under-triage를 **지표가 아니라 구조로** 억제하게 된 대신,
  > **과대평가(over-triage) 증가**와 규칙 테이블 유지보수 부담을 떠안았다.
- **비고**: 축①의 *"LLM 출력은 반드시 검증해서 받는다"* 가 가장 구체적으로 구현된 지점.
  트레이드오프는 실험 **E6**으로 정량화한다

#### 개정 — 종별 분기 (2026-07-31, D-39 도출 후)

초판은 규칙 테이블을 **`물질 × 종 × 체중당 섭취량`** 으로 잡았다.
**코퍼스 실측 결과 조류에는 체중당 섭취량이 0건이라 이 형태가 성립하지 않는다.**

| 종 | 규칙 테이블 입력 | 근거 |
|---|---|---|
| **개·고양이** | `물질 × 체중당 섭취량` **정량** | 주목 2.3 g/kg · Allium 체중 0.5% · 백합 1–2장 · 3시간 골든타임 |
| **조류** | `물질 × 증상` **정성** | 체중당 용량 **0건** · 호흡수 기준 **0건** · 체온 기준 **0건**.<br>유일한 수치 트리거는 출혈 5–10분(S-072) 1건 |

> **조류 질의에 체중·섭취량 수치를 요구하는 슬롯·프롬프트를 두면 반드시 환각이 발생한다.**
> 근거가 없는 값을 LLM이 지어내기 때문이다. 조류는 **질적 조건**
> (*"acting ill"* · *"not resolving"* · *"continues to vomit"*)과 증상 목록으로만 판정한다.

**등급 값은 D-39를 따른다** — `EMERGENCY(4) > CALL_NOW(3) > VISIT_SOON(2) > MONITOR(1)`.
**숫자가 클수록 위험**하므로 `max()`가 그대로 성립한다.

#### 후속 (2026-08-01) — **"0건" 전제는 깨졌다. 그래도 결정은 유지한다**

팀원이 추가 수집한 조류 학술 문헌 3건(S-070 전문 재수집 · S-093 · S-094)을 추출하면서
**조류 체중당 수치 11건**이 나왔다. 개정판이 근거로 삼은 *"체중당 용량 0건"* 은
**더 이상 사실이 아니다.**

| 성격 | 건수 | 예 |
|---|---|---|
| **중독 임계치** | **2** | `F-070-034` DMSA **≥80 mg/kg 치사** · `F-070-009` 집참새 **≥1500 mg/kg NaCl** |
| 치료 용량 | 9 | 활성탄 1–3 g/kg · CaEDTA 35–40 mg/kg IM · 비타민 K1 2.2 mg/kg IM 등 |

**그럼에도 종별 분기는 그대로 둔다.** 나온 2건이 규칙 테이블에 못 들어가기 때문이다.

- `F-070-034` 는 **킬레이션 약물(DMSA)의 과량 투여** 치사량이다. 보호자가 먹이는 물질이 아니다
- `F-070-009` 는 **집참새(house sparrow)** 실험값이다. 앵무류가 아니고, 조류는 종 간
  체중이 10 g~1 kg으로 100배 차이라 **다른 종의 체중당 값을 옮겨 쓸 수 없다**
- 치료 용량 9건은 **수의사가 투여하는 양**이다. 이걸 섭취 역치로 오인하면 정반대 오답이 된다

> **바뀐 것은 근거의 형태이지 결론이 아니다.**
> 초판 근거 *"코퍼스에 0건"* → 개정 근거 **"보호자 질의에 쓸 수 있는 조류 체중당 역치가 0건"**.
> 문헌에는 있고, 우리 시스템이 쓸 수 있는 것은 없다.

- **`check_facts.py` 의 `species=bird` + `dose` → ERROR 규칙은 유지한다.**
  추출 시 위 11건 전부 `dose` 를 비우고 `note` 에 원문 위치와 값을 남겼다.
  **검사기가 막았기 때문에 사람이 판단할 기회가 생겼다** — 규칙이 의도대로 동작한 사례다.
- **다시 열 조건**: 앵무류(psittacine) 대상의 **경구 섭취** 체중당 역치가 나오면 그때 재검토한다.
  그 전까지 조류는 정성 판정이다.
- **미결**: `F-070-034`·`F-070-009` 를 `threshold_type=기타` 로 행에 남길지,
  `note` 로만 둘지 — 지금은 후자다

- **영향**: 02 §7.2 · 04 §4.1 · 04 E6 · 05 §5 · `scripts/check_facts.py` · **D-39**

  |---|---|---|---|---|---|
  | `EMERGENCY` | **4** | 응급 | 지금 바로 동물병원으로 가세요 | *"**Don't call.** Take your pet straight to the nearest ER"* (S-038) | 18 |
  | `CALL_NOW` | **3** | 전화 | 지금 수의사에게 전화해 상태를 알리세요 | *"call your veterinarian to **discuss whether your pet needs to be seen**"* (S-086) | 10 |
  | `VISIT_SOON` | **2** | 내원 | 오늘 중 진료를 받으세요 | *"**Contact your veterinarian if** repetitive behavior occurs daily or worsens"* (S-080) | 11 |
  | `MONITOR` | **1** | 관찰 | 집에서 지켜보고, 아래 증상이 나타나면 연락하세요 | *"**Monitor condition. If condition is not resolving** seek veterinary care"* (S-092) | 11 |

  **`EMERGENCY`와 `CALL_NOW`를 병합할 수 없는 이유가 데이터에 있다** — S-038이
  *"Don't call"* 로 **전화를 명시적으로 금지**하고 이송을 지시한다. S-030도 전화번호(L2)와
  *"go immediately to the nearest emergency veterinary hospital"* (L1)을 나란히 배치한다.

  **`MONITOR`에는 상승 조건을 반드시 함께 표시한다.** 데이터의 이 단계는 "그냥 지켜봐라"가
  아니라 *"if not resolving"* 이라는 **조건부 상승**이 본질이다. 조건 없이 "관찰"만 띄우면
  **그 자체가 과소평가**다.

- **정수 방향**: **숫자가 클수록 위험**하다. D-09의 `max(rule, llm)`이 그대로 성립한다.
  (초안의 `L1=최고위험` 표기는 `min()`을 요구해 코드에서 혼동을 낳으므로 폐기)

- **축이 둘이다 — 섞지 않는다**

  ```
  축 A · 사고 대응 긴급도   EMERGENCY > CALL_NOW > VISIT_SOON > MONITOR
  축 B · 급여 가부          NEVER > CAUTION > SAFE
  ```

  *"포도는 개에게 금지"*(축 B)와 *"포도를 먹었으니 EMERGENCY"*(축 A)는 다른 판정이다.
  **D-38 템플릿의 `{risk_level}`은 축 B**이며, 축 A는 질의 시점에 `물질 + 증상 + (종별) 용량`으로 계산한다.

  | 축 B 값 | 표시 | 근거 |
  |---|---|---|
  | `NEVER` | 급여 금지 | *"should **never be fed** … under any circumstances"* |
  | `CAUTION` | 조건부 | *"**not recommended** but sometimes fed without incident"* / *"with caution"* |
  | `SAFE` | 안전 | *"safe for dogs **in moderation**"* |

  > **조류의 축 B는 2단계(`NEVER`/`CAUTION`)로 축약한다.** S-005와 S-091이 동일 항목
  > (Peanuts · Grit · Mushrooms)을 서로 다른 티어에 배정하고 있어, 3단계를 그대로 노출하면
  > **출처에 없는 정밀도를 주장**하게 된다.

- **종별 판정 근거의 비대칭** — 행동 단계 수는 같고, 판정 재료가 다르다

  | | 지지 단계 | 수치 트리거 |
  |---|---|---|
  | 개 | 4단계 완전. 유일하게 긴급도 라벨 보유(S-080) | 호흡수 40–60/분 · 주목 2.3 g/kg · 간식 10% |
  | 고양이 | **자체 자료는 2단계뿐**(`CALL_NOW`·`VISIT_SOON`) | Allium 체중 0.5% · 3시간 골든타임 |
  | 앵무새 | **4단계 지지** — S-092 단일 문서 안에서 대조 | **출혈 5–10분 1건이 전부** |

  > **고양이는 `mammal/`·`all/` 문서와 반드시 함께 인덱싱**해야 4단계가 성립한다.
  > 조류는 단계 수가 아니라 **판정 근거**가 빈약하다 (D-09 개정 참조).

- **트레이드오프**:
  > 등급 체계를 임의로 정하면 출처에 없는 정밀도를 주장하게 되는 문제를 풀기 위해
  > **코퍼스의 행동 지시어에서 도출**하는 방식을 택했고,
  > 그 덕분에 **모든 등급에 verbatim 근거가 붙고 종별 한계까지 드러난** 대신,
  > **통상적 트리아지 체계와 다른 구성**(정상 단계 없음)을 설명해야 하는 부담과
  > 코퍼스가 바뀌면 등급 근거를 재점검해야 하는 비용을 떠안았다.
- **비고**: **"정상 / 조치 불필요" 단계를 두지 않았다.** 사고 발생 후
  *"아무것도 하지 않아도 된다"* 는 지시가 코퍼스에 **0건**이기 때문이다.
  안전 진술은 전부 축 B(급여 가부)에 속한다.
  또한 `위험`·`중증` 같은 **의학적 중증도 어휘를 쓰지 않는다** — D-11 진단 금지.
  코퍼스의 소스들도 등급 이름 없이 **행동만 지시**하고 있었다
- **미결**: 사용자 노출 배지 표현은 팀 회의에서 확정. **내부 값은 본 결정으로 확정**
- **영향**: D-09 · D-11 · D-38 · 02 §7.2 · 04 §2.5·§4 · 01 §2.2

- **대안**: (a) 원본 그대로 RAG (b) 정형 DB로만 적재하고 벡터 검색 제외 (c) **정형 레코드 + 문장화 청크 병행**

- **비고**: 원문 인용(`quote`)을 반드시 보존하여 근거 제시 시 사용한다
- **영향**: 01 §9~11

### D-19 · cross-lingual — 다국어 임베딩 기본안

- **상태**: **확정** (2026-08-01) — 전제가 바뀌어 조건부를 닫는다. 아래 후속 참조
- **맥락**: 외부 자료의 약 90%가 영문인데 사용자는 한국어로 질의한다
- **대안**: (a) 사전 번역 인덱싱 (b) **다국어 임베딩 cross-lingual 검색** (c) 질의 번역
- **결정**: (b)를 기본안으로 두고 (a)와 비교(E2). D-15의 문장화가 한국어로 이뤄지므로 부담이 일부 완화된다
- **연동**: (a)를 채택하면 **번역 태스크 ⑥이 함께 채택**된다 (D-05)
- **트레이드오프**:
  > 언어 불일치로 검색이 실패하는 문제를 풀기 위해 다국어 임베딩을 기본안으로 택했고,
  > 그 덕분에 추가 번역 비용 없이 대응 가능해진 대신,
  > **임베딩 모델의 cross-lingual 성능에 전적으로 의존**하게 되어 검증 실험이 필수가 되었다.

#### 후속 (2026-08-01) — **전제가 사라져 조건부를 닫는다**

이 결정은 *"영문 원문이 벡터DB에 들어간다"* 를 전제로 썼다. **그 전제가 세 번 바뀌었다.**

| | 무엇이 바뀌었나 |
|---|---|
| **D-37** | 복제 허락이 없어 **원문을 넣지 못한다.** 사실만 뽑아 재구성한다 |
| **D-38** | 그 재구성을 **코드가 한국어로** 한다 |
| **D-45** | 복제 허락이 있는 자료까지 **원문 적재를 껐다** |

실제 적재된 433청크가 이렇다.

```
개에게 양파·리크·샬롯·마늘·차이브(알리움류)는 급여 금지로 분류된다. (출처: WSAVA, S-053)
앵무새에서 PTFE(테플론) 과열 흄은 전화 상황이다. 확인할 증상은 개구호흡, 꼬리 흔들림…
```

**코퍼스가 한국어이고 질의도 한국어다.** 원 맥락의 *"자료 90%가 영문"* 은 **수집 시점의 사실**이지
**적재 시점의 사실이 아니다.** 이 문서가 *"문장화로 부담이 일부 완화된다"* 고 적었던 것은
실제로는 "일부"가 아니라 대부분이었다.

- **남은 다국어 요소는 둘뿐이다** — `scientific_name` 을 원문 그대로 둔 것(*Lilium* ·
  *Persea americana* · *Pasteurella multocida*)과, 팀원이 중국어·일본어 자료를 추가할 가능성.
  둘 다 다국어 임베딩이 있으면 무료로 처리되므로 **`bge-m3` 를 그대로 쓴다.**

### D-31 · 접근 차단은 사유별로 다르게 처리한다

- **상태**: 확정 (2026-07-31)
- **맥락**: 스냅샷 확보에서 15건이 막혔는데, "막혔다"를 한 덩어리로 다루면
  **뚫어도 되는 것과 뚫으면 안 되는 것을 구분하지 못한다.** 실제로 근거가 서로 다르다
- **결정**: 차단 사유를 4분류하고 각각 다르게 처리한다

  | 사유 | 성격 | 처리 |
  |---|---|---|
  | **기술 오류** (404 · URL 결손 · JS 렌더링) | 아무 제한도 아님 | 주소 정정 후 그대로 수집 |
  | **봇 차단** (403 · CAPTCHA) | 자동화 거부. 사람은 대상 아님 | **사람이 받아 파일로 전달**. 링크 재fetch 아님 |
  | **robots.txt** | RFC 9309 — **크롤러 대상 권고**. *"not a form of access authorization"* | **사람이 받아 파일로 전달만.** 링크를 받아 재fetch하면 사람을 한 번 경유했을 뿐 여전히 자동 수집 |
  | **로그인·구독** | 접근 자체가 계약 대상 | **대체 출처로 교체.** D-32 참조 |

- **트레이드오프**:
  > "막혔다"를 한 덩어리로 다루면 뚫어도 되는 건 포기하고 뚫으면 안 되는 건 우회하게 되는 문제를 풀기 위해
  > 사유별 4분류를 택했고,
  > 그 덕분에 **각 건에 대해 근거 있는 판단**을 하게 된 대신,
  > 차단될 때마다 사유를 확인하는 공정을 떠안았다.
- **비고**: **robots.txt를 통과해도 끝이 아니다.** 이용약관과 저작권은 별개 층으로 남는다.
  robots는 "수집해도 되는가", 약관·저작권은 "확보한 것을 쓸 수 있는가"를 규율한다
- **영향**: 01c §6.5 · `data/README.md` §2

  | **G2** | **개인·비상업 복제를 허용하는가** | 허용 문언이 없으면 ⛔ **중단.** 불명확(허락도 금지도 없음)은 **작업용 한정**으로 착수 |
  | **G3** | 접근에 구독·로그인이 필요한가 | ⛔ **중단** — 재현성 탈락 (D-32) |

  **2층 · 사용 조건** — 통과한 뒤 "어떻게 쓸지"를 정한다

  | # | 확인 | 조치 |
  |---|---|---|
  | **G4** | 대량 DB인가 | 전량 복제 대신 **항목 단위 추출 + 자체 재구성** (D-34) |
  | **G5** | 개인정보가 포함되는가 | 코드로 제거 후 사용. 제거 불가면 중단 (D-36) |

- **트레이드오프**:
  > 수집·전달·분석을 다 끝낸 뒤 버리게 되는 매몰 비용 문제를 풀기 위해
  > 수집 전 게이트를 택했고,
  > 그 덕분에 **버릴 자료에 시간을 쓰지 않게 된** 대신,
  > **자료 1건마다 착수 전 확인 절차**를 떠안았다.
- **비고**: **불명확을 "배제"가 아니라 "사용 범위 축소"로 처리한다**는 점이 핵심이다.
  그래야 Lafeber(조류 3단계 등급의 유일한 출처)처럼 조건이 불분명하지만 대체 불가능한 자료를
  잃지 않는다. D-29의 보관/배포 분리가 이 완충을 만들어준다

#### 개정 이력 — 2026-07-31, 초판을 12개 도메인 38건에 적용한 결과

초판은 5단계를 **한 층으로 나열**했다. 보유 자료에 소급 적용해보니 두 가지가 드러났다.

**① G4·G5는 판정을 한 번도 뒤집지 못했다.** 38건 전부 G1·G2에서 결론이 났다.
다만 **Pet Poison Helpline은 예외**였다 — 약관 페이지 자체가 없어 G1~G3이 전부 "조항 없음"으로
통과하는데, 328행 통째 복제는 **약관과 무관하게 저작권법 제93조**에 걸린다.
즉 G4는 **차단 기준이 아니라, 약관이 침묵할 때 작동하는 사용 조건**이다. 지우지 않고 2층으로 옮긴다.

**② 초판 G1이 성격이 다른 둘을 한 칸에 섞고 있었다.**

| | 예시 | 우리에게 적용되나 |
|---|---|---|
| **목적 금지** | *"prohibited … to **train** any artificial intelligence models"* (Merck)<br>*"use of **artificial intelligence** … to repurpose"* (VCA) | ⛔ 못 피한다 |
| **수단 금지** | *"use any **robot, spider**"* (ASPCA·AKC)<br>*"**spider, crawl, or scrape**"* (WildEarth) | 수동 취득이면 해당 없음 |

이 둘을 구분하지 않아 **판정 근거가 흐려졌다.** 실제 갈림은 수단이 아니라
**G2 — 개인·비상업 복제를 허용하는가**였다.

- ASPCA — *"make a **single copy** … for your **personal and non-commercial** use"* → 허용 있음 → 조건부 통과
- Banfield — *"may not copy or **incorporate any of the Content into any other work**"* → 허용 없음 → 중단
- AKC — Reproduction Policy가 온라인 재이용을 **링크로만** 한정 → 중단

**판정 결과는 바뀌지 않았고 근거만 정정되었다.** ⛔ 4건(petMD·Banfield·AKC·WildEarth)의
사유를 G1 → **G2**로 고쳐 기록한다. *(이 4건은 이후 **D-37**로 재판정된다)*

#### 2차 개정 — 30개 도메인 전수 확인 후 (2026-07-31)

**③ `artificial intelligence`만 검색하면 놓친다.** 전수 확인 결과 **AI를 한 번도 언급하지 않고
벡터 색인을 금지하는 곳이 더 많았다.**

| 출처 | 문언 | AI 언급 |
|---|---|---|
| AVMA | *"…or **incorporate into any information retrieval system** (electronic or hard copy)"* | 없음 |
| FOUR PAWS | *"**stored, processed**, copied or distributed using **electronic systems**"* | 없음 |
| ASPCA | *"must not … **store**, **create derivative works of** …"* | 없음 |

셋 다 RAG를 정면으로 막는다. **G1a 검색어에 ②번 묶음을 추가**한다 —
`information retrieval system` · `storage and retrieval` · `stored, processed` ·
`electronic systems` · `store` · `derivative works`.

**이 검색어 추가로 ASPCA 6건이 "조건부 통과" → "사실추출 한정"으로 하향**되었다.

- **영향**: 01c §6.1 · 01b · `data/README.md` §5

### D-38 · 문장화는 코드가 한다 — 그리고 문장화도 검증 대상이다 🔒

- **상태**: 확정 (2026-07-31)
- **맥락**: D-37로 대부분의 자료가 **경로 ②(사실 추출 + 자체 문장화)** 로 가게 되었다.
  그런데 벡터DB에 들어가는 것이 **우리가 쓴 문장**이면 새로운 문제가 생긴다.

  ```
  [런타임]  답변 ↔ 검색된 청크        → sLLM ④ 근거 검증이 담당 (기존)
  [빌드타임] 우리 문장 ↔ 원문          → 🆕 검증 주체가 없다
  ```

  **환각 방지 지점이 답변 단계에서 문장화 단계로 이동한다.**
  D-30에서 같은 것을 이미 보았다 — *"축약된 문장을 원문으로 오인하면 그 자체가 환각의 출처가 된다."*
- **대안**: (a) LLM에게 문장화를 시키고 사후 검증 (b) **템플릿을 미리 만들고 코드가 생성**
- **결정**: (b). **축① "결정론은 코드로, 판단·해석만 LLM에게"의 적용이다.**

  ```
  원문 ──[추출]──→ 사실 표 ──[템플릿]──→ 문장
                      ↑                    ↑
                여기만 검증하면      템플릿은 한 번만
                    된다              사람이 검수
  ```

  **템플릿은 발명하지 않고 데이터에서 도출한다.** 코퍼스의 `doc_type` 축을 그대로 쓴다 —
  `toxicity_food`(27) · `nutrition`(21) · `toxicity_plant`(11) · `emergency`(9) · `symptom`(7).

  ```python
  # toxicity_food 템플릿
  "{species}에게 {substance}은(는) {risk_level}로 분류된다."
  + if threshold: "체중 1kg당 {dose}{unit} 이상 섭취 시 위험하다."
  + if signs:     "주요 증상은 {signs}이다."
  + if onset:     "증상은 {onset} 이내에 나타난다."
  + "(출처: {publisher}, {source_id})"
  ```

  **결측 필드는 해당 절을 통째로 뺀다.** "정보 없음"이라고 쓰지 않는다 —
  그 문장이 검색되면 그 자체가 오답이 된다.

  > **부수 효과**: 임계값 필드가 비면 정량 문장이 생성되지 않는다.
  > 조류는 정량 임계치가 0건이므로 **조류 청크는 자동으로 정성 문장만 나온다.**
  > **D-09의 종별 분기가 데이터 단계에서 강제되어** 규칙 테이블에서 따로 막을 필요가 없다.

- **검증 체계**: 검증 대상이 문장이 아니라 **필드**로 축소된다.

  | 층 | 검사 | 방법 |
  |---|---|---|
  | **자동** | 그 숫자가 원문에 실제로 있는가 | 원문 문자열 검색 |
  | **자동** | **단위 변환 오류** | 재계산 — S-074에 실제 사례가 있다 (*"530°F (280°C)"*, 280°C = 536°F) |
  | **자동** | 종 이름이 원문과 일치하는가 | 문자열 대조 |
  | **자동** | 필수 필드 결측 | 스키마 검사 |
  | **사람** | 템플릿 검수 | **한 번만.** 템플릿이 맞으면 필드가 맞는 한 문장도 맞다 |
  | **사람** | 표본 대조 | 무작위 N건을 원문과 대조. **작성자·검수자 분리** (04 §2.4) |

  **04에 지표 3종을 추가한다** — 추출 정확도 / 문장화 충실도(원문에 없는 내용 생성 = **0**) /
  역추적 가능성(모든 청크가 `source_id` + 원문 위치 보유 = **100%**).

- **트레이드오프**:
  > 사실 추출이 문장화라는 새 환각 지점을 만드는 문제를 풀기 위해
  > 템플릿 기반 코드 생성을 택했고,
  > 그 덕분에 **검증 대상을 문장에서 필드로 축소**하고 종별 분기까지 데이터 단계에서 강제하게 된 대신,
  > **문장 표현이 획일화되어 임베딩 변별력이 떨어지는** 위험과 템플릿 설계 공정을 떠안았다.
- **완화**: 필드 값(물질명·종·증상)이 문장에 그대로 들어가고, 청킹이 물질 단위(D-14)라 항목별로 분리된다.
  효과는 **E1(청킹 단위 비교)에 "템플릿 문장 vs 원문 청크" 비교를 추가**해 측정한다 —
  라이선스 제약에서 나온 선택이 **측정 가능한 설계 판단**이 된다
- **비고**: 이 검증은 **빌드타임 비용**이다. 런타임마다 도는 것이 아니라 코퍼스 구축 시 한 번이면 끝난다.
  그리고 이 과정 자체가 04 §7(실패 분석)의 재료가 된다 —
  **"답변 단계뿐 아니라 데이터 단계에서도 환각을 막았다"**
- **영향**: 01 §2.1 · 04 §3·§7 · 04 E1 · D-09 · D-14 · D-15 · D-30 · D-37

### D-36 · 개인정보는 LLM에 닿기 전에 코드가 벗긴다 🔒

- **상태**: 확정 (2026-07-31)
- **맥락**: 본 도메인을 고른 이유 중 하나가 **개인정보 리스크가 낮다**는 것이었고(D-01),
  법적으로도 맞다. 확인한 바는 다음과 같다.

  | 확인한 것 | 근거 |
  |---|---|
  | **반려동물 정보 자체는 개인정보가 아니다** | 개인정보보호법 제2조1호 — "**살아 있는 개인**에 관한 정보". 제2조3호 정보주체 = "**사람**" |

  **그런데 위험은 동물 정보가 아니라 거기 딸려 오는 것에 있다.**

  | 항목 | 왜 문제인가 |
  |---|---|
  | **동물등록번호** | 동물보호법 시행령 제11조 — 등록 시 소유자 **성명·주민등록번호·주소·전화번호**가 함께 등록된다. 시행규칙 제12조는 인식표에 **소유자 성명·전화번호와 등록번호를 함께 표시**하도록 규정. 제2조1호 **나목(쉽게 결합)** 판단 대상이다 |
  | **사진 EXIF의 GPS** | 위치정보법 제2조2호 개인위치정보 — "다른 정보와 **용이하게 결합**하여 특정 개인의 위치를 알 수 있는 것을 포함". 제15조1항의 수범자는 "**누구든지**" — 사업자 여부와 무관하다 |

  | **급여·배변·체중 시계열** | 누적되면 **생활 패턴**이 드러난다 |

- **대안**: (a) 입력 단계에서 사용자에게 주의 안내 (b) **코드가 기계적으로 제거**
- **결정**: (b). **축① "결정론은 코드로, 판단·해석만 LLM에게"의 적용이다.**
  개인정보 제거는 판단이 아니라 결정론이다. LLM에게 맡길 일이 아니다

  | # | 조치 | 근거 |
  |---|---|---|
  | 1 | **동물등록번호를 슬롯에서 제외**. 프로필 식별은 앱 내부 UUID | 제16조 최소수집. 트리아지에 필요한 건 종·품종·체중·나이·기저질환뿐이다 |
  | 2 | **업로드 직후 코드가 EXIF를 전량 제거**. GPS·촬영기기·시각 모두. 원본 EXIF는 보관하지 않는다 | 위치정보법 제15조 |
  | 3 | **얼굴 검출 시 마스킹 또는 저장 거부** | 제2조1호 가목 + 제16조 — 다이어리 목적에 사람 얼굴은 불필요 |
  | 4 | **보호자 본인의 건강정보는 슬롯 추출 단계에서 폐기** | 제23조 민감정보 — 별도 동의 대상이며 우리는 받지 않는다 |
  | 5 | **LLM·외부 API 전송 전 필터를 코드로 강제**. 필터를 통과한 것만 나간다 | 축① |
  | 6 | **LangSmith 트레이스에 실입력을 남기지 않는다** | 02 §10·04 §8의 트레이스가 **입력 원문을 그대로 저장**한다. 데모 입력은 가명화하거나 트레이스에서 제외 |
  | 7 | 학습·평가는 **가상 프로필만**(D-18). 데모 입력 기록은 **발표 종료 시 전량 파기** | 제21조 — 목적 달성 시 지체 없이 파기 |

  > 코드 단계의 기계적 제거를 택했고,
  > 그 덕분에 **사용자의 주의력에 의존하지 않고 구조로 막게 된** 대신,
  > **전처리 파이프라인에 EXIF 제거·얼굴 검출 단계를 추가**하는 비용을 떠안았다.
- **비고**: 6번이 가장 놓치기 쉽다. **관측을 위해 넣은 LangSmith가 개인정보 저장소가 된다.**
  D-20(코퍼스 버전 태깅)·D-13(과소평가율 추적)이 모두 트레이스에 의존하므로 지우기도 어렵다.
  **가명화를 트레이스 설정 단계에서 켠다**
- **미결 해소**: 얼굴 검출은 **로컬 모델** · 검출 시 **저장 거부** → **D-43**

### D-43 · 사진 업로드를 만든다 — 대신 업로드 경로에 관문을 둔다 🔒

- **상태**: 확정 (2026-08-01)
- **맥락**: 07 §6에서 마감 압박을 이유로 **"사진 업로드 기능은 만들지 않는다"** 고 잘라냈었다.
  안 받으면 D-36의 조치 7개 중 2개(EXIF 제거·얼굴 검출)가 통째로 불필요해지기 때문이다.

  **그런데 다이어리에서 사진을 빼면 기록이 성립은 해도 쓰이지 않는다.**
  보호자가 남기고 싶은 것은 *"오늘 밥 잘 먹음"* 이라는 문장이 아니라 그때의 사진이다.
  기록이 안 쌓이면 00 §3.3의 2단계(맥락)와 3단계(킬러 — 기간 리포트)가 함께 죽는다.
  **차별화 지점 전체가 사진 한 장에 걸려 있었다.**

  반려동물 사진이라 위험이 낮아 보이지만, **실제로 올라오는 것은 반려동물 사진이 아니다.**

  | 실제로 올라오는 것 | 왜 개인정보인가 |
  |---|---|
  | 고양이를 안고 있는 **보호자의 얼굴·손** | 개인정보보호법 제2조1호 **가목** — "영상 등을 통하여 개인을 알아볼 수 있는 정보" |
  | **집 안 배경** — 우편물·달력·창밖 풍경 | 가목 + 나목(쉽게 결합). 주소가 드러난다 |
  | EXIF의 **GPS 좌표** | 위치정보법 제2조2호 · 제15조1항 수범자는 "**누구든지**" |
  | **기록마다 쌓이는 사진의 촬영 시각** | 시계열과 결합하면 생활 패턴 + 상시 체류지가 드러난다 |

  마지막 줄이 프로필 1장짜리 설계와 결정적으로 다른 지점이다.
  **한 장은 위치이지만 백 장은 동선이다.**

- **대안**: (a) 만들지 않는다 (07 §6 원안) (b) 프로필 1장만 허용
  (c) **프로필 + 다이어리 기록 양쪽 허용, 대신 업로드 경로를 관문화**
- **결정**: (c). 기능은 되살리되 **D-36의 조치 2·3을 "하면 좋은 것"에서
  "통과하지 못하면 저장되지 않는 관문"으로 승격**한다.

  | # | 관문 (업로드 직후 · 저장 **전** · 전부 코드) | 근거 |
  |---|---|---|
  | 1 | 확장자·MIME·크기 검사 — 이미지가 아니면 거부 | — |
  | 2 | **EXIF 전량 제거**. GPS·촬영기기·촬영시각 모두. 원본 EXIF는 어디에도 남기지 않는다 | 위치정보법 제15조 |
  | 3 | **얼굴 검출 → 1건이라도 있으면 저장 거부 + 이유 안내** | 제2조1호 가목 · 제16조 |
  | 4 | 리사이즈 + **재인코딩** — 2를 빠져나간 잔여 메타데이터를 인코딩 단계에서 끊는다 | 방어 이중화 |
  | 5 | 앱 내부 UUID로 저장. **원본 파일명은 버린다** | 파일명에 이름·날짜·기기명이 들어온다 |

- **얼굴 검출은 로컬 모델로 한다** — D-36의 미결 사항을 여기서 해소한다.

  > 개인정보를 빼내기 위해 그 개인정보를 외부 API로 내보내는 것은 자기모순이다.
  > 검출 대상이 곧 보호해야 할 대상이므로, **판정이 경계 밖으로 나가면 안 된다.**

  OpenCV Haar 또는 MediaPipe 급의 경량 로컬 모델을 쓴다. 정확도는 최상이 아니지만
  **이 관문에서 요구되는 것은 정밀도가 아니라 봉쇄**다.

- **마스킹이 아니라 거부인 이유** — 실패했을 때 어느 쪽으로 틀리는가가 다르다.

  | | 검출을 놓쳤을 때 | 잘못 검출했을 때 |
  |---|---|---|
  | 마스킹 | **얼굴이 그대로 저장된다** | 사진 일부가 가려진다 |
  | **거부** | 얼굴이 그대로 저장된다 | 사용자가 다시 올린다 |

  두 방식 모두 놓치면 똑같이 위험하지만, **거부는 오검출의 대가가 불편함뿐**이다.
  게다가 마스킹은 "얼마나 잘 가려졌는가"를 검증해야 하는데 그 시간이 마감 안에 없다.
  **검증할 수 없는 안전장치는 안전장치가 아니다** (04 §8).

- **거부할 때 반드시 이유를 보여준다.** 왜 막혔는지 모르는 사용자는 우회를 시도한다.
  *"사람이 함께 나온 사진은 저장하지 않습니다. 반려동물만 나오도록 다시 올려주세요."*

- **사진은 LLM에 넣지 않는다.** 이번 범위에서 사진은 **기록의 첨부물이지 판정 입력이 아니다.**
  멀티모달로 사진을 읽는 순간 D-11(진단 금지)의 경계가 무너진다 —
  **사진으로 피부 병변을 "보는" 것은 그 자체가 진단이다.**
  트리아지 입력은 지금처럼 텍스트 슬롯뿐이다.

- **트레이드오프**:
  > 사진 없는 다이어리는 쓰이지 않아 개인화·리포트가 함께 죽는 문제를 풀기 위해
  > 업로드 허용 + 경로 관문화를 택했고,
  > 그 덕분에 **00 §3.3의 2·3단계가 실제로 성립하게 된** 대신,
  > **처리 파이프라인에 관문 5단계와 얼굴 검출 의존성을 추가**하고
  > 정상 사진이 거부당하는 오검출을 감수했다.
- **완화**: 관문은 **업로드 라우터 한 곳**에만 둔다. 우회 경로를 만들지 않기 위해서다.
  테스트가 *"관문을 거치지 않고 저장에 도달하는 경로가 없다"* 를 검사한다.
- **비고**: 00 §3.3 우선순위는 **바뀌지 않는다.** 사진은 2단계(맥락)에 속하며,
  **1단계(코어 — 트리아지 QA)가 끝나기 전에는 착수하지 않는다.**
  코어 없는 사진 업로드는 이 프로젝트의 산출물이 아니다.
- **영향**: 00 §3.3 · 02 §12 · 07 · D-11 · D-36

  > 한 파일을 네 명이 동시에 고치는 문제와 산출물 4종 매핑 불일치를 풀기 위해 5분할을 택했고,
  > 그 덕분에 병렬 작업과 산출물 직결 구조를 얻은 대신,
  > **문서 간 참조 관리와 일관성 유지** 부담을 떠안았다.
- **비고**: 후자는 00의 **문서 맵**과 단일 출처 원칙으로 관리한다
- **영향**: 00 §0

### D-40 · 배달 계층 — 화면이 아니라 계약을 먼저 고정한다 🔒

- **상태**: 확정 (2026-07-31)
- **맥락**: D-21이 *"UI는 가드레일 뒤"* 로 정했는데, 00 §9.3은 *"UI 스펙은 WS2와 사전 합의한다"* 를
  요구한다. **화면은 나중인데 합의는 먼저**라는 것이 모순처럼 보였다.

  모순이 아니다. **나중에 오는 것은 화면이고, 먼저 정해야 하는 것은 계약이다.**
  계약이 없으면 WS2는 무엇을 반환할지 모른 채 그래프를 짜고, WS5는 무엇이 올지 모른 채
  화면을 짠다. 둘이 만나는 시점에 재작업이 발생하는데, **D-21이 막으려던 것이 정확히 그 재작업**이다.
- **대안**:
  (a) Streamlit 단독 — 가장 빠르지만 API 계층이 없어 계약이 코드에 묻힌다.
      산출물 ③ *"연동 구현 코드"* 로 보여줄 경계가 흐려진다
  (b) React + Vite 별도 프론트 — 화면이 늘 때 유리하나 node 의존성·CORS·빌드 산출물 관리가 붙는다
  (c) **FastAPI + 정적 HTML 1장, 같은 출처 서빙**
- **결정**: (c). 그리고 **계약을 먼저 확정하고 엔진은 스텁으로 둔다.**

  ```
  app/web/index.html ──HTTP──> FastAPI ──Protocol──> QAEngine
                            (계약)                 ├─ StubEngine   ← 지금
                                                   └─ GraphEngine  ← WS2 완성 후
  ```

  빌드 도구도 node도 CORS 설정도 없다. 시연 재현이 `make serve` 한 줄로 끝난다 (04 §8).

  **세부 결정 네 가지가 이 결정의 실체다.**

  **① 거절을 4xx가 아니라 200으로 내보낸다.**

  `/api/ask` 는 항상 200을 반환하고 `status` 가 `answered` / `clarify` / `refused` 를 나른다.
  02 §9에서 **거절은 장애가 아니라 설계된 정상 경로**로 정의했다.
  4xx로 만들면 프론트가 에러 핸들러에서 처리하게 되고, **거절 화면이 장애 화면처럼 그려진다.**
  전송 계층 실패(500)와 정책상 거절을 구분하지 못하면 00 §7의 감점 항목
  *"검색 실패와 생성 실패를 구분하지 않은 오류 분석"* 을 그대로 재현하게 된다.

  **② 정책을 문서가 아니라 스키마로 강제한다.**

  | 불변식 | 위반 시 | 근거 |
  |---|---|---|
  | `answered` 인데 `citations` 가 비었다 | **응답 객체 생성 실패** | 02 §9 — 근거 없으면 답하지 않는다 |
  | `MONITOR` 인데 상승 조건이 없다 | **응답 객체 생성 실패** | D-39 — 조건 없는 "관찰"은 과소평가다 |
  | 경로 ② 근거에 원문 인용이 실렸다 | **응답 객체 생성 실패** | D-37 — 원문은 벡터DB에 없다 |

  세 항목 모두 **런타임 검사가 아니라 타입 수준**이다. 지키자고 합의한 것이 아니라
  어기면 응답이 만들어지지 않는다. 05 §6 *"LLM에 맡긴 지점마다 검증 코드가 한 겹 붙는다"* 의
  배달 계층 판본이다.

  **③ 엔진을 프로토콜 뒤에 둔다.**

  라우터는 `QAEngine` 프로토콜만 안다. WS2의 LangGraph가 완성되면 **주입 지점 한 줄**을 바꾼다.
  계약·프론트·테스트는 손대지 않는다. 지금의 `StubEngine` 은 검색과 LLM만 고정값이고
  **되묻기·상한 초과 거절·하향 금지 게이트는 실제로 통과시킨다** — 벡터DB 없이도 D-09·D-10·D-39가
  동작하는 것을 시연할 수 있다.

  **④ 등급 표현의 단일 출처를 API로 만든다.**

  `GET /api/triage-levels` 가 등급 이름·배지·행동 문장과 **도출 근거 원문(verbatim)** 을 함께 내려준다.
  프론트가 등급 표현을 자기 코드에 복사하면 D-39가 개정될 때 화면만 옛 표현으로 남는다.
  00 §9.4 단일 출처 원칙을 규칙이 아니라 **구조**로 만든 것이다.

- **트레이드오프**:
  > 판정 로직이 확정되기 전에 화면을 만들면 재작업이 생기고, 계약 없이 병렬 작업하면
  > WS2와 WS5가 만나는 지점에서 또 재작업이 생기는 문제를 **동시에** 풀기 위해
  > **계약 우선 + 스텁 엔진**을 택했고,
  > 그 덕분에 **로직 완성 전에도 WS5가 착수할 수 있고 정책 위반이 타입 오류로 잡히게 된** 대신,
  > **스텁과 실제 엔진 두 벌을 유지**하고 계약이 바뀔 때마다 양쪽을 고치는 부담을 떠안았다.

- **미채택 — SSE 스트리밍**: 토큰이 흘러나오는 체감은 좋으나, **등급이 확정되기 전에 문장이 먼저
  나가면 근거 검증 실패 시 이미 뱉은 문장을 회수할 수 없다.** 04 §4.1.0의 중대 과소평가율 0 목표와
  충돌한다. 축② *"통제가 먼저, 배달이 나중"* 이 문장 단위에도 적용된다.

- **비고**: 세션 저장소를 메모리로 두었다. 되묻기 슬롯(체중·섭취량)을 **보관하지 않는 것이
  D-36 최소수집과 맞다** — 프로세스가 죽으면 사라지는 것이 의도다.
  다중 워커로 띄울 때만 외부 저장소로 교체한다.
  또한 `answer` 만 읽는 클라이언트가 상승 조건을 빠뜨리지 않도록 `full_text` 필드를 함께 내보낸다 —
  **조건 누락은 이 도메인에서 과소평가와 같다** (D-39).

- **영향**: 00 §9.3·§10 · 02 §12·§13 · 04 §8 · 05 §2(조각 12) · D-09 · D-11 · D-21 · D-36 · D-37 · D-39

### D-41 · 저장소 구조 — 파라미터를 코드에서 빼고 의존성을 쪼갠다

- **상태**: 확정 (2026-07-31)
- **맥락**: 골격이 커지면서 두 가지가 걸렸다.

  **① 파라미터가 코드에 박혀 있었다.** `top_k=5`, `chunk_size=500`, LoRA rank가
  각각 다른 파일에 있었다. 04 §8이 재현성을 요구하는데, 실험 보고서에
  *"그때 top-k가 몇이었더라"* 를 적을 방법이 없다. 04의 감점 항목
  *"재현 불가 — 버전 미고정, 시드 미설정"* 을 그대로 밟는 구조였다.

  **② 의존성이 한 덩어리였다.** `requirements.txt` 하나에 torch와 fastapi가 같이 있어
  **API만 띄우려는 팀원도 수 GB를 받아야 했고**, CI도 마찬가지였다.

- **대안**:
  (a) 지금 구조 유지 — 4주 프로젝트에 과한 정비다
  (b) 모노레포(`apps/` + `packages/`) — 4인 규모에 과잉
  (c) **설정 외부화 + 의존성 그룹 분리 + 컨테이너**
- **결정**: (c). 네 가지를 바꿨다.

  **① 설정을 `configs/*.yaml` 로 뺀다.** 경계는 **재현에 필요한가**로 갈랐다.

  | | 어디 | 커밋 | 예 |
  |---|---|---|---|
  | 재현에 필요 | `configs/*.yaml` | **한다** | 모델 ID, LoRA rank, top-k, 임계값, 시드 |
  | 비밀·환경차이 | `.env` | 안 한다 | API 키, DB 주소, 트레이싱 on/off |

  **실험 결과를 보고할 때 YAML을 그대로 첨부하면 재현이 된다.**
  프로파일(`default` → `<profile>` → 환경변수) 순으로 덮으므로,
  평가는 `PETTRIAGE_PROFILE=eval` 하나로 조건이 고정된다.

  **② 의존성을 `[api] [rag] [ingest] [train] [dev]` 로 쪼갠다.**
  GPU 없는 팀원은 `pip install -e '.[api]'` 로 끝난다.
  버전 고정은 `constraints.txt` 가 따로 맡는다 — **무엇을 설치할지(extras)와
  어느 버전으로 고정할지(constraints)를 분리**해야 둘을 독립적으로 바꿀 수 있다.

  **③ 무거운 임포트를 함수 안으로 내린다.** `models/` 의 torch·transformers 임포트가
  모듈 최상단에 있으면 CI가 학습 의존성 없이 못 돈다. 이것은 스타일이 아니라 **제약**이며,
  CI의 `test` job이 `[api,dev]` 만 설치하는 것으로 강제된다.

  **④ 컨테이너를 나눈다.** API 이미지(`Dockerfile`)에 torch를 넣지 않고,
  학습은 `docker/train.Dockerfile` 로 분리한다. `compose.yaml` 에 pgvector를 함께 올려
  02 §11의 벡터DB 후보를 실제로 시험할 수 있게 한다.
  `.dockerignore` 가 `data/` 를 차단한다 — **이미지에 자료가 구워지면 배포가 곧 유출**이다 (D-29).

- **트레이드오프**:
  > 파라미터 산재로 재현이 안 되고 의존성 덩어리로 착수 비용이 큰 문제를 풀기 위해
  > 설정 외부화와 의존성 분리를 택했고,
  > 그 덕분에 **실험 조건을 파일 하나로 고정하고 GPU 없이도 개발할 수 있게 된** 대신,
  > **설정이 코드와 YAML 두 곳에 존재**하게 되어 기본값이 어긋날 여지와
  > 그룹별 설치를 팀원에게 안내해야 하는 부담을 떠안았다.
- **완화**: 어긋남이 위험한 값은 **테스트가 일치를 검사한다** —
  `triage.max_clarify_turns` 와 `contracts.MAX_CLARIFY_TURNS` 가 그 예다.
  안전에 직결되는 설정은 반드시 이 형태로 묶는다.
- **비고**: 어댑터·체크포인트는 `artifacts/` 로 보내고 커밋하지 않는다.
  **재현은 가중치가 아니라 `configs/` + `constraints.txt` + 시드로 한다.**
- **영향**: 00 §9.4 · 04 §8 · README · `configs/README.md` · D-20 · D-29 · D-40 · D-42

### D-44 · 벡터DB — Chroma 확정 (pgvector 우선 검토를 뒤집는다)

- **상태**: 확정 (2026-08-01)
- **맥락**: 02 §11 은 **pgvector 를 우선 검토**로 두고 있었다. 근거는 두 가지였다 —
  ① 메타데이터 필터를 SQL 로 처리 ② 프로필·정형 기준표를 같은 DB 에서 관리해
  계산 노드와 통합하기 쉽다.

  **그런데 설계가 진행되면서 ②의 전제가 사라졌다.**

  | 당시 가정 | 실제로 정해진 것 |
  |---|---|
  | 정량 임계치를 DB 에 넣고 SQL 로 조인한다 | **D-38** — 문장화도 계산도 **코드가 한다.** 임계치는 `compute/tables/*.csv` 를 코드가 직접 읽는다 |
  | 프로필·기록을 같은 DB 에 둔다 | 현재 `RecordStore` 는 인메모리이고 **인증조차 없다.** DB 에 넣을 단계가 아니다 (04 범위 밖) |
  | 복잡한 메타데이터 필터가 필요하다 | 실제 필터는 `species` · `doc_type` · `substance` 의 **동등 비교와 목록 포함**뿐이다 |

  즉 pgvector 의 이점은 **발생하지 않았고**, 서버를 띄워야 하는 비용만 남았다.
  마감이 8/04 이고 팀원 3명이 Windows 인 상황에서 이 비용은 작지 않다.

- **대안**: (a) pgvector (02 §11 원안) (b) **Chroma** (c) Qdrant
- **결정**: (b) **Chroma**, `chromadb==0.6.3`, `PersistentClient` 파일 기반.

  | | |
  |---|---|
  | **착수 비용** | Docker·서버 없이 `pip install` 만으로 돈다. 팀원이 오늘 밤 바로 검색을 붙일 수 있다 |
  | **필터** | `where` 로 충분함을 **실측**했다 — 종 동등 비교, 목록 포함(D-39 고양이 병합 검색 `["cat","mammal","all"]`)까지 동작 |
  | **증분 적재** | `upsert` 로 **재적재 멱등성 확인** (D-20 코퍼스 버전 태깅의 전제) |
  | **재현** | `persist_dir` 를 지우고 `build_index.py` 로 통째로 재생성된다. 상태가 파일 하나에 모인다 |

- **텔레메트리는 끈다.** 개인 기록을 다루는 시스템이 외부로 사용 신호를 내보내면 안 된다
  (D-36 조치 5·6 과 같은 취지). `anonymized_telemetry=False` 를 넣었고,
  0.6.3 이 기동 이벤트 2건에서 이 설정을 무시하지만 **호출 자체가 실패해 전송되는 것은 없다.**
  실패 경고만 로그에서 지웠다 — 진짜 오류가 소음에 묻히면 안 되기 때문이다.

- **트레이드오프**:
  > SQL 필터와 정형 데이터 통합이라는 pgvector 의 이점이 실제로는 발생하지 않는데
  > 서버 기동 부담만 남는 문제를 풀기 위해 Chroma 를 택했고,
  > 그 덕분에 **팀원 전원이 Docker 없이 검색 계층을 돌릴 수 있게 된** 대신,
  > **정형 데이터와의 조인 질의가 필요해지는 순간 저장소를 갈아야 하는** 부담을 떠안았다.
- **완화**: `VectorStore` **Protocol 뒤에 있다.** 갈아야 할 때 다시 쓰는 것은
  `retrieval/store.py` 한 파일이고 **그래프 노드는 손대지 않는다.**
  `compose.yaml` 의 pgvector 서비스는 지우지 않고 남겨둔다 — 여유가 생기면 그대로 시험할 수 있다.
- **비고**: 이 결정은 **성능 비교로 내린 것이 아니다.** 남은 시간과 팀 환경으로 내렸고,
  그 사실을 여기 적어둔다. 지표로 뒤집을 근거가 나오면 뒤집는다.
- **미결**: Top-k · 유사도 임계값은 **1차 평가 후** 정한다 (지금 정하면 근거가 없다)
- **영향**: 02 §11 · 04 §8 · `configs/default.yaml` · `retrieval/store.py` · D-19 · D-20 · D-36 · D-41

### D-45 · 경로①(원문 청크 적재)을 끄고, 자격 목록을 원장에서 유도한다 🔒

- **상태**: 확정 (2026-08-01)
- **맥락**: 사실 표 433행 추출을 마친 뒤 *"원문을 그대로 쓸 수 있는 자료도 굳이 추출해야 하나"*
  라는 질문이 나왔다. 답을 확인하려고 경로① 목록을 원장과 대조하다 **더 큰 문제가 나왔다.**

  `scripts/check_facts.py` 의 `ROUTE1_SOURCES` 는 코드에 박힌 8건짜리 목록이었는데,
  원장에서 자격을 다시 유도하니 **8건 중 7건이 어긋나 있었다.** 겹친 것은 `S-043` 하나다.

  | | 자료 | 무엇이 문제인가 |
  |---|---|---|
  | **잘못 허용하고 있었다** | `S-001` | **G1a(AI 학습 금지)로 삭제된 자료**다. DELETION_LOG 에 있다 |
  | | `S-012` `S-023` `S-064` | `usability = B 가공활용` — **복제 금지.** 원문을 실으면 약관 위반이다 |
  | | `S-042` `S-055` `S-070` | 품질 `빈약`·`X`·`요약` — D-30 상 인용 근거로 쓸 수 없다 |
  | **잘못 막고 있었다** | `S-016` `S-029` `S-046` | `usability = A 자유이용` · `submit_ok = O`. FDA·주정부 자료다 |
  | | `S-034` `S-044` `S-045` | CC BY · 정부 간행물. 원장 `license` 에 명시돼 있다 |

  > **가장 위험한 것은 `S-012`·`S-023`·`S-064` 였다.** 이 셋은 이미 사실 표 34행을 갖고 있고,
  > 목록이 `quote` 를 허용하고 있었으므로 **복제 금지 자료의 원문이 벡터DB에 들어갈 수 있었다.**
  > D-37 판정의 전제 — *"원문이 벡터DB에 들어가지 않을 때만 성립한다"* — 가 코드에서 깨져 있었다.
  > 지금은 전 행 `quote` 가 비어 있어 실제 사고로 이어지지 않았을 뿐이다.

- **대안**: (a) 목록을 고친다 (b) **목록을 없애고 원장에서 유도한다** (c) 경로①을 아예 없앤다
- **결정**: (b) + **스위치는 끈다.**

  ### ① 자격은 코드가 아니라 원장이 정한다

  ```python
  def route1_eligible() -> set[str]:      # 세 조건을 모두 만족해야 한다
      # 1. 원장이 배포 가능으로 표시 — 스냅샷 submit_ok=O / 원본 license 오픈·정부
      # 2. 품질이 완전·부분        — 요약을 원문으로 인용하면 그게 곧 환각이다 (D-30)
      # 3. 삭제 이력에 없다         — D-33 · G1a
  ```

  **손으로 관리하는 목록은 원장과 반드시 어긋난다.** D-22의 단일 출처 원칙이 데이터에만
  적용되고 코드에는 적용되지 않았던 것이 이번 사고의 원인이다.
  원장을 못 읽으면 **빈 집합**을 돌려준다 — 자격이 없는 쪽으로 실패한다.

  현재 유도 결과는 **7건** — `S-016` `S-029` `S-034` `S-043` `S-044` `S-045` `S-046`.
  01c §6.2의 라이선스 통과 8건에서 `S-070`(품질 `요약`)이 D-30으로 빠진 수다.

  ### ② 스위치는 이번 범위에서 끈다 — `ROUTE1_ENABLED = False`

  두 경로를 함께 켜면 같은 사실이 두 번 적재된다.

  - 같은 사실이 **top-k 를 두 칸 잡아먹는다**
  - **④ 근거 검증 노드가 둘을 모순으로 판정**할 수 있다 — 경로①은 원문이라
    *"An occasional apple seed will not harm"* 같은 완화 표현이 살아 있고,
    사실 표에서는 같은 항목이 `NEVER` 로 정리된다

  중복 제거 규칙과 검증 노드 예외를 함께 설계해야 하는데, **마감(8/04)까지 그 이득이
  위험보다 크지 않다.** 경로②만으로 산출물 4종이 모두 성립한다.

- **"경로① 자료는 사실 표에서 빼면 되지 않나" — 안 된다.**

  **규칙 테이블과 계산 노드는 텍스트를 읽지 않는다.** D-38이 *"문장화는 코드가 한다"* 로
  정한 순간, 코드가 판정에 쓰는 값은 전부 구조화된 칸에서 나오게 됐다.
  원문 청크에 *"2.3 g leaves/kg"* 이라 적혀 있어도 `dose`·`unit`·`threshold_type` 칸이
  없으면 `apply_gate()` 가 볼 수 없다.

  > **경로 구분은 적재 방식이지 추출 여부가 아니다.**
  > 정량·등급 값이 있는 자료는 경로와 무관하게 사실 표 행이 필요하다.

- **원문은 버리지 않는다.** 04 §1.1의 *"출처 문서에 명시된 기준을 정확히 인용했는가"* 는
  `data_work_*.zip` 에 남은 원문을 **골든셋 채점 기준**으로 삼아 검증한다 (D-29 · D-37).
  원문의 쓰임이 "적재 대상"에서 "채점 기준"으로 바뀔 뿐이다.

- **트레이드오프**:
  > 원문 인용의 충실도와 중복 적재의 위험이 충돌하는 문제를 풀기 위해
  > 경로① 차단 + 원장 유도를 택했고,
  > 그 덕분에 **복제 금지 자료가 적재될 경로가 구조적으로 사라지고 적재 경로가 하나로 단순해진**
  > 대신, **원문을 그대로 인용해 얻을 수 있는 충실도 점수를 포기**했다.
- **완화**: 스위치 하나로 되돌릴 수 있다. 1차 평가에서 인용 충실도가 낮게 나오면
  자격 7건에 한해 켜고 재측정한다 — 그때는 지표라는 근거가 생긴다.
  켜더라도 자격은 원장이 정하므로 삭제·복제금지 자료가 다시 새어 들어오지 않는다.
- **비고**: 이 사고는 **검사기가 통과했다고 안전한 것이 아님**을 보여준다.
  `check_facts.py` 는 433행을 ERROR 0 으로 통과시키는 동안, 정작 자기 화이트리스트가
  틀렸다는 것은 몰랐다. **검사기의 기준 자체를 검사할 것이 필요하다** — 그래서 원장 유도로 바꿨다.
- **영향**: 00 §5 · 01c §6.2 · 01e §0·§2 · 02 §7·§13 · 04 §1.1 · `scripts/check_facts.py` · D-22 · D-29 · D-30 · D-33 · D-37 · D-38

### D-46 · 유사도 임계값은 거절을 만들지 못한다 — 0.50 으로 두고 거절은 노드가 책임진다 🔒

- **상태**: 확정 (2026-08-01)
- **맥락**: 02 §8.3이 *"유사도 임계 미만이면 검색 실패로 보고 거절한다"* 로 정해 두었고,
  `configs/default.yaml` 은 `score_threshold: 0.35` 를 **근거 없이** 담고 있었다.
  `bge-m3` 로 433청크를 실제 적재한 뒤 측정했다.

  근거가 **있어야 하는** 질의 12건과 **없어야 하는** 질의 10건을 던졌다.

  | | 범위 |
  |---|---|
  | 근거 있음 | **0.547 ~ 0.733** |
  | 근거 없음 | **0.494 ~ 0.659** |

  **두 분포가 겹친다.** 겹치는 구간이 `0.547 ~ 0.659` 로 근거 있음의 아래쪽 절반을 덮는다.

  | 근거 없는 질의 | 점수 | 물어온 것 |
  |---|---|---|
  | *"앵무새 체중 100g 기준 초콜릿 몇 g부터 위험한가요"* | **0.659** | 초콜릿 (조류) |
  | *"앵무새 발톱은 얼마나 자주 깎아야 하나요"* | 0.578 | 그릿(grit) |
  | *"고양이 중성화 수술 비용이 궁금해요"* | 0.572 | 중독 의심 시 대응 |
  | *"강아지 배변 훈련은 어떻게 하나요"* | 0.553 | 강박장애(CCD) |
  | *"우리 강아지 사료 브랜드 추천해주세요"* | 0.537 | Pedigree High Protein (리콜 자료) |

  > **어떤 임계값도 이 둘을 가르지 못한다.** 0.55 로 올리면 근거가 있는
  > *"앵무새 앞에서 프라이팬을 태웠어요"*(0.547)가 거절된다 — **과소평가**다(D-13).
  > 내리면 도메인 밖 질의가 전부 통과한다.

- **대안**: (a) 근거 있음 최저(0.547) 바로 아래로 바짝 붙인다 (b) **0.50 — 완전 무관만 자르는 최소선**
  (c) 임계값을 없앤다
- **결정**: (b) **`score_threshold: 0.50`**.

  | | |
  |---|---|
  | **근거 있는 12건 전부 통과** | 하나도 거절되지 않는다. D-13이 과소평가를 최우선으로 두므로 **이 방향으로 틀린다** |
  | 근거 없는 것 중 최저 1건만 차단 | 방어 효과는 거의 없다. **그 사실을 숨기지 않는다** |

  (a)를 택하지 않은 이유 — 0.54 로 붙이면 PTFE 질의가 임계선 위에 아슬아슬하게 걸린다.
  **자료가 한 건만 늘어도 순위가 흔들려 거절로 넘어간다.** 안전 장치가 데이터에 흔들리면 안 된다.

  (c)를 택하지 않은 이유 — 임계값이 없으면 **검색이 항상 무언가를 돌려준다.**
  0.2대 문서로 답을 만드는 경로가 열린다. 최소선은 남긴다.

- **⚠️ 거절의 책임이 옮겨간다 — 이것이 이 결정의 핵심이다.**

  02 §8.3은 임계값이 거절을 만든다고 적었지만, **측정 결과 그럴 수 없다.**
  거절은 두 노드가 만들어야 한다.

  | 노드 | 무엇을 막나 | 근거 |
  |---|---|---|
  | **① 의도 분류** | **도메인 밖**을 검색 전에 걸러낸다. `intent=general` 이면 검색하지 않고 `refused / 범위밖` | 02 §6 · 05 §4 |
  | **④ 근거 검증** | 검색은 됐지만 **문장별 근거가 없는** 경우를 잡는다 | D-11 · 02 §9 |

  **`build_filter` 는 이 판정을 하지 않는다.** 필터는 결정론이고, 도메인 판정은 의미 판단이다.

  > 측정 5건 중 4건이 *"코퍼스 밖"·"도메인 밖"* 이었다 — **①이 잡아야 할 것들**이다.
  > ①을 대충 만들면 임계값이 받쳐주지 못하므로 **그대로 답으로 나간다.**

- **드러난 개별 문제 두 가지**

  **① 리콜 자료가 브랜드 추천 질의를 끌어온다.** *"사료 브랜드 추천해주세요"* 가
  `Pedigree High Protein`(S-046 리콜 목록)을 0.537로 물어온다. **리콜된 제품이 추천으로 읽히면
  최악의 오답**이다. `doc_type=recall` 은 사용자가 그 제품을 명시할 때만 검색되게 해야 한다.

  **② 조류 정량 질의가 정성 근거를 물어온다.** *"앵무새 체중 100g 기준 초콜릿 몇 g"* 이
  조류 초콜릿 청크를 **0.659** 로 가져온다. 검색은 맞다 — 그 자료는 실재한다.
  틀리는 것은 **정량으로 답할 근거가 없는데 정량 질문을 받았다**는 판정이고,
  이건 검색이 아니라 **계산 노드**가 해야 한다 (D-09: 조류 체중당 임계치 0건).

- **트레이드오프**:
  > 임계값 하나로 거절을 만들려던 설계가 측정에서 성립하지 않는 문제를 풀기 위해
  > 임계값을 최소 방어선으로 낮추고 거절 책임을 노드로 옮겼고,
  > 그 덕분에 **근거가 있는 질의를 거절하지 않게 된** 대신,
  > **① 의도 분류의 품질에 거절 정확도가 직결**되게 되었다.
- **완화**: 골든셋의 `refused` 15% 가 이 지점을 직접 채점한다 (04a §3).
  ①이 부실하면 그 지표가 먼저 떨어지므로 1차 평가에서 드러난다.
- **비고**: **측정하지 않았다면 0.35를 그대로 두고 "임계값이 거절을 만든다"고 보고했을 것이다.**
  그 보고는 04 §7의 *"잘 동작하는 것으로 보인다"* 와 같은 종류의 문장이 된다.
  재현 명령은 `python scripts/calibrate_threshold.py` 다.
- **미결**: 하이브리드 검색(BM25 + dense)이 정석 해법이나 마감 내 도입하지 않는다.
  1차 평가에서 거절 정확도가 낮으면 그때 재검토한다
- **영향**: 02 §6·§8.3 · 04 §4 · 04a §3 · `configs/default.yaml` · `graph/nodes/classify.py` ·
  `graph/nodes/retrieve.py` · `graph/nodes/compute.py` · D-09 · D-11 · D-13 · D-44

### D-47 · 답변에 실린 연락처는 출력 직전에 코드가 뺀다 🔒

- **상태**: 확정 (2026-08-01) · 1차 검수에서 발견
- **맥락**: 코퍼스 45건 중 **응급 지침 자료가 전부 미국 것이다.**
  ASPCA · FDA · Pet Poison Helpline · FOUR PAWS · Cornell · Banfield 가 하나같이
  말미에 24/7 핫라인을 단다.

  | 번호 | 기관 | 등장 자료 |
  |---|---|---|
  | 855-764-7661 | Pet Poison Helpline | S-027 · S-029 · S-085 · S-100 |
  | 888-426-4435 | ASPCA APCC | S-007 · S-029 · S-100 |
  | 855-289-0358 · 855-454-4130 | FOUR PAWS 안내 | S-030 |

  검수 전에는 **이 번호들이 서로 상충하는 줄 알았다.** 대조해 보니 아니었다 —
  기관이 다르거나, 같은 기관을 다른 자료가 다르게 적은 것이다. 진짜 문제는 따로 있었다.

  > 응급 상황에서 걸리지 않는 번호는 오답보다 나쁘다 — 전화를 걸어보는 시간만큼
  > 병원 도착이 늦어지기 때문이다.

- **대안**
  1. **사실 표에서 해당 행 삭제** — 연락처가 본문인 행을 뺀다.
     번호와 함께 *"무엇이 위험한가"* 같은 나머지 근거까지 잃는다. **기각**
  2. **국내 연락처로 치환** — 국내에 미국 APCC 에 대응하는 **공식 중독 상담 창구가 없다.**
     있는 것처럼 적으면 그게 곧 환각이다. **기각**
  3. **④ 근거 검증에 맡긴다** — 검색 근거에 없는 번호이므로 `근거없음` 으로 잡혀야 한다.
     맞는 말이지만 **판정은 보장이 아니다.** 보조 수단으로만 둔다. **기각**
  4. **출력 직전에 코드가 뺀다** ← 채택

- **결정**: `safety/contacts.py` 의 `scrub_contacts()` 를 그래프 마지막 노드
  `finalize` 에서 부른다. 데이터는 **그대로 둔다.**

  - **문장 단위로 뺀다.** 번호만 지우면 *"ASPCA APCC에 연락하세요"* 가 남는데
    국내 사용자에겐 여전히 오답이다. ④ 검증이 이미 쓰는 조치와 같은 방식이다
  - 기관명이 나와도 **행동 지시가 없으면 살린다** —
    *"APCC 자료에 따르면 아보카도는 조류에게 치명적이다"* 는 출처 인용이다
  - 뺐으면 `"가까운 동물병원이나 24시 동물병원으로 바로 연락해 주세요"` 를 붙인다.
    **존댓말이다** — 청크는 검색 대상이라 평서체(`~다`)로 두지만
    화면에 뜨는 문장은 보호자가 응급 상황에서 읽는 말이라 명령조가 되면 안 된다
  - **국내 번호도 함께 막는다.** 지금 코퍼스에 검증된 국내 연락처가 0건이라
    통과시킬 근거가 없다. 검증된 창구가 생기면 그때 예외를 명시적으로 뚫는다
  - 거절·되묻기 응답도 통과시킨다 — 거절 문구에 연락처를 넣는 실수를 막는다
  - 뺀 문장은 `state["removed_contacts"]` 에 남긴다.
    **무엇을 뺐는지 기록하지 않으면 검증할 수 없다** (04 §8)

- **트레이드오프**: 전부 연락처인 답은 안내 문장 하나만 남는다. 답이 빈약해지지만
  **틀린 번호를 주는 것보다 낫다.** 오탐 위험은 용량 수치다 —
  `2.8-36.4 g/kg` 이 번호로 잡히면 답변이 통째로 사라지므로,
  숫자 뒤 단위(`mg`·`g`·`kg`·`mL`·`%`·`IU`·`kcal`)를 보고 제외한다.
  `tests/test_contacts.py` 가 이 경우를 고정한다.
- **비고**: 데이터를 고치지 않고 계층을 하나 더 두는 것은 D-40 과 같은 판단이다.
  **원문 충실성(D-30)과 사용자 안전이 부딪힐 때, 원문은 남기고 출력에서 막는다.**
- **부수 결정 — 출력 문체**: 사용자에게 나가는 문장은 **존댓말**로 쓴다.
  코퍼스 청크는 검색 대상이라 `ingest/templates.py` 가 평서체(`~다`)로 문장화하지만,
  화면에 뜨는 답변은 보호자가 **응급 상황에서** 읽는 말이다. 명령조가 되면 안 된다.
  `safety.GUIDANCE` 가 기준 문체이고, ⑤ 평이화 노드가 이를 따른다
  (`graph/nodes/generate.py::simplify` 계약에 명시).
- **영향**: 02 §2 · 05 §4 · `safety/contacts.py` · `graph/nodes/generate.py` ·
