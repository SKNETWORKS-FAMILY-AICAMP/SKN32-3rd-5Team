## 1. 두 축

본 프로젝트의 모든 설계 결정은 다음 두 축을 따른다.

### 축① 결정론은 코드로, 판단·해석만 LLM에게

> **"이 일은 코드가 할까, LLM이 할까?"** 를 조각을 붙일 때마다 던진다.

**판단 3문 (위에서부터 순서대로)**

```
① 자연어 이해·생성·의미 판단이 꼭 필요한가?
     아니오 → 코드 (여기서 끝)
     예 ↓
② 같은 입력에 항상 같은 답이 나와야 하나? (재현·감사 필요)
     예 → 규칙으로 표현 가능한지 재검토 → 가능하면 코드
     애매 ↓
③ 규칙 먼저, 안 잡히는 것만 LLM (하이브리드)
     → LLM 출력은 반드시 '검증'해서 받는다
```

**경계가 애매하면 코드 쪽으로 기운다.** 코드로 옮길수록 빠르고, 비용이 들지 않고, 재현 가능하다.

#### 가장 좋은 예시 — 문장화 (D-38, 2026-07-31 추가)

이용약관 제약으로 **대부분의 자료를 원문이 아니라 "사실을 추출해 우리 문장으로" 적재**하게 되었다
(D-37 · 01 §2.1). 그러면 *"그 문장은 누가 쓰는가"* 라는 질문이 생긴다.

| | LLM이 문장화 | **코드가 문장화** |
|---|---|---|
| 검증 대상 | **문장 전체** — 원문에 없는 말이 섞였는지 매번 확인해야 함 | **필드만** — 숫자·단위·종만 대조하면 됨 |
| 재현성 | 같은 입력에 다른 문장 | 항상 같은 문장 |
| 비용 | 자료 건수만큼 호출 | 0 |

3문을 그대로 돌려보면 답이 나온다.
**① 자연어 생성이 꼭 필요한가? → 아니다.** 필드를 문장에 끼워 넣는 일이다. **여기서 끝난다.**

그래서 **템플릿을 데이터에서 도출해 미리 만들고, 코드가 필드를 채워 생성**한다.

```python
f"{species_ko}에게 {substance}{eun_neun}(은/는) {feeding_lead}."     # 조사도 코드가 고른다
+ if threshold: f"체중 1kg당 {dose}{unit} 이상 섭취 시 위험하다."
+ f"(출처: {publisher}, {source_id})"
```

> ⚠️ **`은(는)`·`와(과)` 를 문자 그대로 쓰지 않는다** (2026-08-02 개정).
> 초안 예시가 `{substance}은(는)` 이었는데, 그러면 888청크 전체에
> *"초콜릿은(는)"* 같은 병기가 그대로 남는다. **받침을 코드가 판정해 하나만 고른다** —
> `_UNIT_BATCHIM`(kcal·kg·mg·mL·IU·g·%) · `_LATIN_BATCHIM`(엘·엠·엔·알만 받침) · `_wa()`.
> 축①의 *"경계가 애매하면 코드 쪽으로"* 가 조사 하나에도 적용된다.
> 실제로 `10%이다(다)` · `BER이다(다)` · `반려동물와` 가 나왔고, 888청크 전수 검사로 0건을 만들었다.

> **결측 필드는 절을 통째로 뺀다.** "정보 없음"이라고 쓰면 그 문장이 검색되어 오답이 된다.
>
> **부수 효과**: 임계값이 없으면 정량 문장이 생성되지 않는다.
> 조류는 정량 임계치가 0건이므로 **조류 청크는 자동으로 정성 문장만 나온다** —
> 5장 하향 금지 게이트의 종별 분기가 **데이터 단계에서 강제**된다.
> (실측: `species=bird` 159행 중 `dose`·`max_value` 보유 **0건**)
>
> ⚠️ **단 `species=all` 은 예외다** — 77행 중 32행이 정량을 갖고 있고 조류 검색에도 딸려 온다.
> 조류 정량 판정을 막는 것은 데이터가 아니라 `triage.quantitative_species: [dog, cat]` 이다.

**이것이 축①이 라이선스 제약을 만나 오히려 설계를 단단하게 만든 사례다.**

### 축② 통제가 먼저, 배달이 나중

> 예측 가능 · 검증 가능 · 안전 가능한 지능을 만든 **뒤에야** 서비스로 내보낸다.

```
[통제 없이 배달하면]
  화려한 데모 → "왜 이 답이 나왔지?" 추적 불가 → 신뢰 붕괴

[통제 후 배달하면]
  예측 가능(같은 입력 → 같은 경로)
  + 검증 가능(LLM 출력을 믿지 않고 확인)
  + 안전 가능(위험 응답을 게이트로 차단)
   → "이 처리가 규칙대로 됐음"을 증명 → 신뢰
```

**본 도메인은 오답이 생명과 직결되므로 이 순서가 절대적이다.**

## 2. 정지 판정 — 어디까지 붙이는가

한 조각의 한계가 **실제로 나타나기 전에 미리 붙이면 복잡도만 오른다.**
요구사항 기준으로 채택 여부를 판정한 결과는 다음과 같다.

| # | 조각 | 채택 | 근거 |
|---|---|---|---|
| 0 | 빈 껍데기 | ✅ | 데모 UI / API 그릇 |
| 1 | LLM 호출 | ✅ | — |
| 2 | 프롬프트 통제(PE) | ✅ | 트리아지 등급·슬롯 JSON 등 **출력 형식 강제**가 필수 |
| 3 | 기억(Memory) | ⚠️ **부분** | 3장 참조 — 되묻기 세션 상태만 해당 |
| 4 | RAG | ✅ | 도메인의 존재 이유. 검증된 문서 근거로만 답한다 |
| 5 | 코드/LLM 분리 | ✅ **척추** | 생명 관련 판정 → 가장 강하게 적용 |
| **6** | **도구(ReAct)** | ❌ **미채택** | 계산 노드는 있으나 **LLM이 도구를 선택할 필요가 없다.** intent가 정해지면 어떤 계산이 필요한지 코드가 안다. Thought→Action→Observation 루프는 과설계 |
| **7** | **MCP** | ❌ **미채택** | 도구 재사용·표준화 수요 없음. 외부 에이전트에 도구를 노출할 계획 없음 |
| 8 | 오케스트레이션 | ✅ **LangGraph** | **되묻기 순환 + 근거 검증 실패 시 재검색**이 있어 선형 체인으로 표현 불가 |
| **9** | **멀티에이전트·A2A** | ❌ **미채택** | God Object 아님. 도구 5~7개+ 아님. 역할 분리 수요 없음 |
| 10 | 가드레일·HITL | ✅ **필수** | 의료 인접 도메인. 위험 응답 차단·고지 노출 |
| 11 | 캐싱 | 🔶 **선택 유지** | 반복 질의는 많으나 **지연을 아직 안 재 봤다.** 8장 첫 줄(*"한계가 실제로 관측되었는가"*)에 아직 아니오다. **캐시보다 측정을 먼저 넣었다** — 하네스 `p50`·`p95`·노드별 (D-53 · 04 §4.3). ⚠️ **캐시 금지 목록**: 프로필 · 트리아지 판정 · `finalize` 이전 출력 |
| 12 | 배달(FastAPI/UI) | ✅ | 시연 필수 |
| 13 | 측정·검증·운영 | ✅ | **필수 산출물 ④ 그 자체** |

### 2.1 채택 경로

```
0 → 1 → 2 → 3(부분) → 4 → 5(척추) → 8 → 10 → 12 → 13
                                    (11은 선택)
```

### 2.2 미채택을 명시하는 이유

**6·7·9를 "안 썼다"가 아니라 "판정해서 뺐다"로 남긴다.**

> *"왜 에이전트를 안 쓰셨죠?"*
> → *"도구 선택 판단이 필요 없어 ReAct 루프는 과설계입니다. 계산은 intent에 따라 코드가 호출합니다."*

과설계를 피한 근거가 문서로 남아 있는 것과, 그냥 안 쓴 것은 평가에서 다르게 읽힌다.

## 3. 조각 3의 이중 성격 — 혼동 금지

본 프로젝트에서 "기억"으로 불릴 수 있는 것이 두 가지인데, **완전히 다르게 처리한다.**

| 성격 | 정체 | 처리 | 저장소 |
|---|---|---|---|
| **되묻기 세션 상태** | "체중이 어떻게 되나요?" → 답변 → 슬롯 충족 | **조각 3** — LangGraph State | 세션(휘발성) |
| **반려동물 일일 기록** | 다이어리 누적 기록 | **조각 3이 아니라 조각 4 (RAG)** | 원본 **MySQL `records`** → 인덱스 **Chroma `internal`** (D-53) |
| **반려동물 프로필** | 이름·종·품종·체중 — *바뀌는 사실* | 조각 3도 4도 아니다. **그냥 관계형 데이터** | **MySQL `pets`** |

> 두 번째를 "장기 기억"으로 부르면 설계가 흐려진다. **검색 대상 문서**다.
> 아키텍처 다이어그램·문서에서 용어를 혼용하지 않는다.

> **벡터DB는 원본이 아니라 인덱스다** (D-53). 일일 기록은 **자주 수정된다** —
> 원본이 벡터DB면 수정·삭제가 지옥이 되고, 지우다 빠뜨린 청크가 **유령처럼 검색된다.**
> 사실 표 888행 → `external` 이 이미 그 구조다(`make index` 로 재생성).
> `internal` 도 같아야 하고, 그러려면 **원본이 관계형에 있어야** 한다.

> **세 번째를 첫 번째·두 번째와 섞지 않는다** (D-52 · 02 §11.1).
> 프로필을 벡터DB에 넣으면 *"코코는 5.2kg"* 이 검색 결과로 떠올라 근거처럼 인용된다.
> 반대로 일일 기록을 MySQL 에 넣으면 **검색 대상이 아니게 되어** 도메인 서사가 무너진다.
> **셋은 담는 것도, 읽는 법도, 신뢰 등급도 다르다** —
> 프로필은 근거가 아니라 **사용자에게 확인받아야 할 입력**이다.

## 4. 지점별 분업표

| 지점 | LLM (판단·해석) | 코드 (결정론) |
|---|---|---|
| ① 의도·위험 분류 | 자연어 의도 파악 | 라벨 **허용목록 검증**, 미분류 시 `unknown` (§6.1). **`general` → 거절** (D-46) |
| ② 슬롯 추출 | 자유서술 → 슬롯 구조화 | **JSON 스키마 검증**, 결측 판정, 되묻기 문구 템플릿, **루프 상한 2회** |
| **되묻기 판정** | — | **증상만 있거나 물질이 미상이면 되묻는다** (D-49). 아래 §4.1 |
| **프로필 조회** | — | **ORM 한 줄. `NULL` 을 `NaN` 으로 바꾸지 않는다** (D-52). 값은 **확인을 받아** 쓴다 |
| 검색 | — | **필터 구성 전부** (`species`·`source_type`·`record_date`), Top-k, 잡음 하한, 물질 중복 접기.<br>⚠️ **유사도로 거절하지 않는다** (D-46) |
| 계산 | — | **권장 열량·체중당 섭취량·독성 임계치 전부.** 환산 불가 단위는 **버리지 않고 사유를 남긴다** (D-51) |
| **트리아지 판정** | **정도(degree) — 항상 받는다** | **규칙 테이블이 바닥을 깐다 + 하향 금지 게이트** (5장 · D-50) |
| ③ 컨텍스트 압축 | 압축·리포트 생성 | 압축 실행 여부(길이 임계) |
| ④ 근거 검증 | 문장별 `근거있음/없음/모순` | 판정 결과에 따른 **게이트·재검색 트리거·문장 제거** |
| ⑤ 평이화 | 용어 변환 | **용어집 준수 검증** |
| **연락처 차단** | — | **출력 직전 문장 단위 제거 전부** (D-47). 아래 §4.1 |
| 응답 조립 | — | **고지 문구·출처 표기·등급 배지·거절 문구** |
| **문장화 (인덱싱)** | — | **템플릿 기반 생성 전부** (D-38). LLM 호출 없음 |
| **개인정보 제거** | — | **EXIF 삭제·얼굴 마스킹·필드 폐기 전부** (D-36). 판단이 아니라 결정론이다 |
| **자료 판정** | — | **수집 전 게이트 4+2단계** (D-35). 약관 검색은 사람, 판정 기록은 코드 |

**LLM에 맡긴 지점은 5개뿐이며, 모두에 검증 코드가 한 겹 붙는다** (6장).

> 2026-07-31에 추가된 세 지점(문장화·개인정보·자료 판정)은 **전부 코드 쪽**이었다.
> **8월 2일에 추가된 네 지점(되묻기 판정·프로필 조회·연락처 차단·환산 불가 처리)도 전부 코드 쪽이다.**
> 새 요구가 생겼을 때 3문을 돌리면 대개 코드로 끝난다는 것을 일곱 번째로 보여준다.

### 4.1 8월 2일에 늘어난 코드 쪽 지점 넷

**① 되묻기 판정 (D-49)** — *"토하고 밥을 안 먹어요"* 에 검색을 태우면 답은 나온다.
문제는 **증상 목록이 겹치는 아무 물질이나 1위로 올라온다**는 것이다. 실측에서 토마토가
0.616으로 1위였고, 상위 5의 점수 폭이 **0.030** 이었다 — 순위가 측정 잡음 안에서 결정된다.

3문을 돌리면 답이 나온다. **① 자연어 이해가 필요한가? → 증상을 알아듣는 데는 필요하다.
그러나 "원인을 찾을 수 있는가"는 이해 문제가 아니라 구조 문제다.**
코퍼스가 물질 단위(D-14)라 각 청크가 *"이 물질 → 이런 증상"* 이고, **역방향은 일대일이 아니다.**
그래서 되묻기 조건은 LLM 판단이 아니라 **슬롯 상태로 코드가 정한다.**

**② 연락처 차단 (D-47)** — 프롬프트로 *"연락처를 쓰지 마라"* 고 해도 LLM은 계속 쓴다.
①에 **아니오**다 — 전화번호와 기관명을 찾아 지우는 일에 의미 판단이 필요 없다.
다만 **문장 단위로 지운다** — 번호만 지우면 *"ASPCA APCC에 연락하세요"* 가 남는다.

**③ 프로필 조회 (D-52)** — DB에서 체중을 읽는 일에 의미 판단이 없다. ①에 **아니오**다.
다만 **읽은 값을 그대로 쓰지 않는다** — 등록 체중은 낡고, 낡은 숫자로 mg/kg 을 계산하면
등급이 통째로 어긋난다. **확인을 받아서 쓴다.**
그리고 **`pandas` 를 통과시키지 않는다** — `NULL` 이 `NaN` 이 되면
`is None` 검사를 뚫고 모든 역치 비교에서 `False` 를 돌려주어 **조용히 `MONITOR`** 가 된다.
*"타입이 값의 의미를 지킨다"* 도 축①이다.

**④ 환산 불가 처리 (D-51)** — 주목 `2.3 g leaves/kg` 를 `g/kg` 로 취급하면 산술은 맞지만
**잎 무게를 독소 무게로 바꿔치기한 숫자**가 되고, 그 숫자가 EMERGENCY 를 판정한다.
D-38이 *"코드가 원문에 없는 문장을 만들면 안 된다"* 였다면 이것은 **숫자** 판이고, 더 위험하다.
환산에 실패하면 **침묵하지 않고 사유를 남긴 뒤 정성 경로로 내려간다.**

## 5. 트리아지 판정 — 하이브리드 설계

이 프로젝트에서 축①이 가장 날카롭게 적용되는 지점이다.

### 5.1 3문 적용

```
① 자연어 이해가 꼭 필요한가?
     → 부분적. 증상 서술 해석엔 필요. 단 "물질 × 종 × 체중당 섭취량 → 등급"은 규칙.
② 같은 입력에 항상 같은 답이 나와야 하나?
     → 예. 생명이 걸리고 감사가 필요하다.
③ → 규칙 먼저, 안 잡히는 것만 LLM (하이브리드)
```

### 5.2 설계

```
[1차] 규칙 테이블 (코드)
      물질 × 종 × 체중당 섭취량  →  rule_triage_level
        │
        ├─ 규칙 적중 → **바닥** 확보. 확정이 아니다 (D-50)
        └─ 규칙 미적용 → None. 바닥이 없을 뿐, 거절이 아니다
        │
[2차] LLM 판정 → llm_triage_level     ← 규칙 적중 여부와 무관하게 **항상** 받는다
        │
[게이트] final = max(rule_triage_level, llm_triage_level)   ← 위험도 기준 상향만
```

> **`if rule_level: return rule_level` 은 D-50 위반이다.**
> 규칙 테이블은 *"역치를 넘었는가"* 만 안다. *"얼마나 위험한가"* 는 모른다 —
> 초콜릿 20 mg/kg 과 200 mg/kg 은 같은 역치를 넘지만 같은 상황이 아니다.
> 규칙이 낸 값을 확정으로 쓰면 **상향할 자리가 사라진다.**
>
> 축① 관점에서도 그게 맞다. 3문의 ③ *"규칙 먼저, 안 잡히는 것만 LLM"* 에서
> **"안 잡히는 것"은 "규칙이 아무 값도 못 낸 경우"가 아니라 "규칙이 모르는 부분"** 이다.
> 정도(degree)는 규칙이 모르는 부분이므로 언제나 LLM 몫이 남는다.

### 5.3 🔒 등급 하향 금지 게이트

> **LLM은 등급을 낮출 수 없다.**
> 코드가 규칙으로 산출한 등급보다 **낮은 등급을 LLM이 제시하면 무시**하고,
> **상향(안전 방향)만 수용**한다.

| 규칙 판정 | LLM 판정 | 최종 | |
|---|---|---|---|
| 응급 | 관찰 | **응급** | LLM 하향 무시 |
| 관찰 | 응급 | **응급** | 상향 수용 |
| **미적용** | 조기 내원 | 조기 내원 | **바닥이 없을 뿐 거절이 아니다** (D-50) |
| 관찰 | 관찰 | 관찰 | 단, **상승 조건이 비면 출력하지 않는다** (D-39) |
| 미적용 | 없음 | **거절** | 양쪽 다 없으면 추측하지 않는다 (`apply_gate` 가 `ValueError`) |

**이 한 줄이 과소평가율(under-triage)을 구조적으로 억제한다.**
평가 지표로만 관리하던 것을 **아키텍처로 못 박는** 셈이며, 축①의
*"LLM 출력은 반드시 검증해서 받는다"* 가 가장 구체적으로 구현되는 지점이다.

> 부작용으로 과대평가(over-triage)가 늘 수 있다. 이는 **의도된 트레이드오프**이며,
> 04 문서에서 두 지표를 함께 보고하되 **과소평가 억제를 우선**한다.

## 6. LLM 출력 검증 — 한 겹씩

| 지점 | 검증 방식 | 실패 시 |
|---|---|---|
| ① 분류 | 라벨이 **허용목록**(`ALLOWED_INTENTS`)에 있는가 | **`unknown`** 으로 떨어뜨리고 로그 — 아래 ⚠️ |
| ② 슬롯 추출 | **JSON 스키마** 파싱 성공 여부, 타입·단위 검증 | 대형 LLM 폴백 → 재시도 1회 → 실패 시 되묻기 |
| 트리아지 | **규칙 테이블과 대조**, 하향 금지 게이트 | 규칙 등급 채택 |
| ③ 요약 | 요약문 내 **수치가 원문에 존재**하는가 | 해당 문장 제거 |
| ④ 근거 검증 | 판정 결과 형식 검증, 스팬이 컨텍스트 내에 존재하는가 | 보수적으로 `근거없음` 처리 |
| ⑤ 평이화 | **용어집 준수율**, 수치 변형 여부 | 원문 유지 |

> 특히 ③·⑤에서 **수치 변형 검사**는 필수다. 요약·평이화 과정에서 임계 용량이 바뀌면 치명적이다.

### 6.1 ⚠️ ① 분류의 폴백은 `general` 이 아니라 `unknown` 이다

**이 문서의 이전 판은 폴백을 `general` 로 적고 있었다. 위험한 오기였다.**

D-46 이후 **`general` 은 "우리가 다루지 않는 질문" 이고, 곧 `refused / 범위밖`** 이다
(`graph/nodes/classify.py`). 폴백을 `general` 로 두면

> **LLM 출력이 한 번 흔들린 것이 곧 사용자 거절이 된다.**
> 초콜릿을 먹은 개 질문에 파싱이 실패하면 *"저희가 다루지 않는 질문입니다"* 가 나간다.

파싱 실패는 **모델이 답을 못 낸 것**이지 **질문이 범위 밖인 것**이 아니다. 둘을 같은 라벨로
접으면 **거절 사유가 오염되고**, 04 §1.2가 나눈 *"검색 실패 / 생성 실패"* 구분도 무너진다.

| 값 | 뜻 | 다음 동작 |
|---|---|---|
| `intoxication` · `symptom` · `nutrition` | 우리가 다루는 질문 | 파이프라인 진행 |
| **`general`** | **도메인 밖** — 이름 짓기·훈련·보험·제품 추천 | `refused / 범위밖` (D-46) |
| **`unknown`** | **분류에 실패했다** | 재시도 1회 → 그래도 실패면 되묻기. **거절이 아니다** |

`ALLOWED_INTENTS` 는 앞의 넷이고 `unknown` 은 **그 밖의 값**이다 —
허용목록에 넣으면 LLM 이 "모르겠다"를 정답처럼 고르기 시작한다.
`models/prompts.py` 의 분류 지시문도 *"판단이 서지 않으면 `unknown` 을 출력한다"* 로 되어 있다.

**UI를 먼저 만들지 않는다.** 판정 로직이 확정되기 전에 화면을 만들면,
로직이 바뀔 때마다 화면을 다시 손대게 되어 이중 비용이 발생한다.

> **SSE 스트리밍은 미채택이다** (02 §12.4). 토큰이 흘러나오는 체감은 좋으나
> **등급이 확정되기 전에 문장이 먼저 나가면 근거 검증 실패 시 회수할 수 없다.**
> 축② *"통제가 먼저, 배달이 나중"* 이 **문장 단위에도** 적용된다.
>
> **다만 "UI를 안 만든다"가 아니라 "계약을 먼저 고정한다"** 이다 (D-40).
> 계약이 스키마로 박혀 있으면 화면은 로직 변경에 흔들리지 않는다 —
> 그래서 WS5는 §6 그래프가 없는 지금도 진행할 수 있다. 순서를 지키는 것과
> 병렬로 일하는 것은 충돌하지 않는다.

> 로드맵상 **10(가드레일)이 12(배달)보다 앞**에 온다. 00 문서 §8 참조.

새 기능·구조를 붙이기 전에 확인한다.

- ☐ 에이전트가 실제로 God Object인가? (아니면 분리는 불필요)
- ☐ LLM 출력을 검증하는 코드가 있는가?
- ☐ 루프에 상한이 있는가?
- ☐ 안전 방향으로만 조정되는 게이트가 있는가?

**하나라도 "아니오"면 붙이지 않는다.**

### 8.1 자료를 추가할 때 (2026-07-31 추가)

**코드가 아니라 데이터를 붙일 때도 체크리스트가 있다.** 수집 착수 **전에** 통과시킨다 (D-35).

- ☐ 약관에 **용도 금지** 조항이 있는가? `artificial intelligence` · `train` · `data mining` · `repurpose`
- ☐ ⚠️ **AI를 언급하지 않고 막는 표현**은 없는가? `information retrieval system` · `stored, processed` · `store` · `derivative works`
- ☐ 개인·비상업 **복제 허락 문언**이 있는가? (없으면 원문 적재 불가 / 사실 추출은 가능 — D-37)

- ☐ 대량 DB인가? (전량 복제 금지, 항목 단위 추출 — D-34)
- ☐ 개인정보가 포함되는가? (D-36)
