## 1. 평가 철학

### 1.1 무엇을 정답으로 볼 것인가

본 도메인은 임상 판단이 개체차·품종·기저질환에 좌우되며, **팀에 수의학 전문 지식이 없다.**
따라서 평가 목표를 다음과 같이 재정의한다.

> **"의학적으로 옳은가"가 아니라 "출처 문서에 명시된 기준을 정확히 인용했는가"**

이는 회피가 아니라 **RAG 평가의 정석**(Faithfulness)이며, 시스템 포지셔닝과도 일치한다 (00 §3.2).

- ✅ 평가 대상 — 검색 정확도, 근거 충실도, 트리아지 등급 일치도, 거절·되묻기 적절성
- ❌ 평가 대상 아님 — 수의학적 진단의 임상적 타당성

### 1.2 검색 실패와 생성 실패를 분리한다

두 층으로 나누어 측정하지 않으면 원인 분석이 불가능하다.

| 계층 | 질문 |
|---|---|
| 검색 | 정답 근거를 가져왔는가 |
| 생성 | 가져온 근거대로만 답했는가 |

## 2. 골든 셋

모든 평가의 전제이며, **도메인 확정 직후 최우선으로 착수**한다.

### 2.1 구성 방식

**시나리오 기반**: (가상 프로필 + 누적 기록) + 질의 → 기대 트리아지 등급 · 근거 문서(`chunk_id`) · 정답 요지

**규모: 100건 이상**

### 2.2 질의 유형 배분

| 유형 | 비중 | 예시 |
|---|---|---|
| 단순 사실형 | 25% | "포도는 강아지에게 위험한가요?" |
| **용량·개체 조건형** | 20% | "5kg 푸들이 초콜릿 20g을 먹었어요" |
| 기록 참조형 | 15% | "요즘 사료 바꾸고 나서 이상한 것 같아요" |
| **종 구분형** | 15% | 같은 물질에 대한 **개 / 고양이 / 앵무새 질의 3종 세트** |
| **슬롯 결측형** | 10% | 체중·섭취량·**종** 미기재 → 되묻기 기대 |
| **답 없음** | 15% | 자료에 근거가 없는 질의 → 거절 기대 |

### 2.3 종별 최소 배정

자료 분량이 달라도 **평가는 균등하게** 한다.

| 종 | 최소 건수 |
|---|---|
| 개 | 35건 |
| 고양이 | 30건 |
| **앵무새** | **30건** |
| 종 공통·구분형 | 나머지 |

**필수 포함 항목**

- 조류 특이 항목 — 아보카도, 조리기구 코팅 흄, 중금속, 씨앗 편중 급여
- 개 특이 항목 — 자일리톨, 포도·건포도, 마카다미아, GDV
- **출처 간 기준값이 상충하는 사례** (01 §14) → 복수 근거 제시 동작 평가.
  **코퍼스 실측으로 9건이 이미 확보되어 있다** (D-39 도출 과정). 대표 사례:
  - **발작** — AAHA S-037 *"as soon as the seizure ends, immediately contact"*(`CALL_NOW`)
    vs FOUR PAWS S-030 *"if… convulsing… go immediately to the nearest emergency hospital"*(`EMERGENCY`)
    → **하향 금지 게이트가 `EMERGENCY`를 채택해야 정답**
  - 포도(개) — 같은 종에 3가지 긴급도 · 사과씨(조류) — `NEVER` vs "우발적 1개는 무해"
  - 아보카도 — FDA *"only mildly toxic to dogs and cats"* vs Banfield 무조건 독성 목록

### 2.4 작성 체계

- **작성은 전원 25건씩, 검수는 교차**한다 (2026-08-01 개정 · 07 §3 WS4)
  — 이서은↔오한빈 · 이근준↔권소라
- **넷이 동시에 착수하지 않는다.** 이서은이 10건으로 기준선을 만들고
  팀장이 검수해 등급 판정 기준을 확정한 뒤 나머지가 붙는다.
  이 순서가 없으면 **기준이 넷으로 갈린 채 100건이 쌓인다**
- 각 항목은 **근거 `source_id`를 반드시 명시**한다. 없으면 검색 지표를 계산할 수 없다
- **작성자와 검수자는 반드시 다르다.** 자기가 쓴 정답을 자기가 검수하면
  같은 오해가 두 번 통과한다. `written_by` · `reviewed_by` 를 분리 기록한다
- 검사기가 미기입을 경고한다 — `python scripts/check_goldenset.py`

## 2.5 층 0 — 데이터 파이프라인 검증 (D-38)

**대부분의 자료가 원문이 아니라 우리가 문장화한 형태로 적재된다** (D-37 · 01 §2.1).
따라서 **문장화 자체가 검증 대상**이 된다. 이것이 없으면 라이선스는 지켰는데 사실이 틀어진다.

> **환각 방지 지점이 답변 단계에서 문장화 단계로 이동한다.**
> 축약된 문장을 원문으로 오인하면 그 자체가 환각의 출처가 된다 (D-30과 같은 구조).

### 2.5.1 지표 3종

| 지표 | 정의 | 목표 |
|---|---|---|
| **추출 정확도** | 사실 표의 숫자·단위·종 이름이 원문과 일치하는 비율 | — |
| **문장화 충실도** | 생성 문장에 **원문에 없는 내용**이 포함된 비율 | **0** |
| **역추적 가능성** | 모든 청크가 `source_id` + 원문 위치를 보유한 비율 | **100%** |

### 2.5.2 검사 방법 — 검증 대상은 문장이 아니라 필드다

문장화를 **템플릿 + 코드**로 하므로(D-38), 필드만 맞으면 문장은 자동으로 맞다.

| 층 | 검사 | 방법 |
|---|---|---|
| 자동 | 그 숫자가 원문에 실제로 있는가 | 원문 문자열 검색 |
| 자동 | **단위 변환 오류** | 재계산 — S-074에 실제 사례가 있다 (*"530°F (280°C)"*, 280°C = **536°F**) |
| 자동 | 종 이름이 원문과 일치하는가 | 문자열 대조 |
| 자동 | 필수 필드 결측 | 스키마 검사 |
| 사람 | 템플릿 검수 | **한 번만** |
| 사람 | 표본 대조 | 무작위 N건을 원문과 대조. **작성자·검수자 분리** (§2.4) |

> **원문은 `data_work/`에 남아 채점표 역할을 한다** (D-29).
> §1.1의 *"출처 문서에 명시된 기준을 정확히 인용했는가"* 는 이 원문과 대조해 성립한다.
> **원문은 채점표이지 적재물이 아니다.**

**이 검증은 빌드타임 비용이다.** 런타임마다 도는 것이 아니라 코퍼스 구축 시 한 번이면 끝난다.

### 2.5.3 실측 — 검색 점검 (2026-08-01)

**층 0의 첫 실측치다.** 재현:

```bash
python scripts/build_index.py --store chroma
```

| | |
|---|---|
| 임베딩 | `BAAI/bge-m3` · 1024차원 · cosine |
| 벡터DB | Chroma 0.6.3 (D-44) · 컬렉션 `external` |
| 적재 | 사실 **888행 → 청크 888건** · 171.3s |
| 종별 | dog 311 · cat 241 · bird 159 · mammal 100 · all 77 |
| 설정 | `top_k=5` · `score_threshold=0.50` (D-46) |

**양성 점검 7건 전부 통과.**

| 질의 | 1위 점수 | 물어온 것 |
|---|---|---|
| 강아지가 초콜릿을 먹었어요 | 0.657 | 초콜릿 (S-029) |
| 우리 개가 포도를 먹었는데 괜찮을까요 | 0.703 | 포도·건포도 (S-021) |
| 강아지가 자일리톨 껌을 삼켰어요 | 0.695 | 자일리톨 (S-029) |
| 고양이가 백합을 씹었어요 | **0.728** | 백합 (S-010) |
| 고양이가 양파 들어간 음식을 먹었어요 | 0.711 | 양파 (S-010) |
| 앵무새가 아보카도를 먹었어요 | 0.687 | 아보카도 (S-029) |
| 앵무새 앞에서 프라이팬을 태웠어요 | **0.547** | 논스틱(PTFE) 조리기구 (S-074) |

#### 읽어야 할 것 세 가지

**① 코퍼스가 두 배가 됐는데 점수가 안 떨어졌다.**
433청크 시점 측정도 0.547~0.728 이었다. 비슷한 문서가 늘면 1위가 희석될 것으로 봤으나
그렇지 않았다 — `score_threshold: 0.50` 을 그대로 둔다.

**② PTFE 만 여유가 0.047 이다.**
질의에 *"PTFE"*·*"테플론"* 이 하나도 없고 **"프라이팬을 태웠다"는 상황 서술뿐**이라서다.
골든셋 `G-013` 이 같은 경로를 타므로, 평가에서 이 케이스가 거절로 빠지면 원인은 여기다.

**③ 앵무새 아보카도가 조류 전용 자료를 1위로 물어오지 않는다.**
S-029(FDA, `species=all`)가 이겼고 S-007·S-071(조류 전용)이 밀렸다.
D-39 병합 검색이 도는 증거이긴 하나, **골든셋 `must_cite` 를 조류 자료로 적으면
그 케이스는 상위 5 안에서 근거를 못 찾을 수 있다.**

#### 이 측정으로 드러난 점검 항목의 결함

**점검 7건이 코퍼스를 대표하지 못했다.**

```
nutrition       274청크  ← 프로브 0건   (최대 doc_type 인데 사각지대)
toxicity_food   225        3건
toxicity_plant  225        2건
emergency       131        2건
symptom          22      ← 프로브 0건
recall           11      ← 프로브 0건
```

게다가 **7건 중 6건은 질의에 물질명이 그대로 있어** 어휘 일치만 확인됐다.
진짜 의미 검색은 PTFE 하나였고 그것만 턱걸이였다 — **어려운 것을 하나만 넣었기 때문이다.**
음성 질의도 없어 *"근거가 없을 때 거절하는가"* 는 점검 대상이 아니었다.

→ **양성 16건 + 음성 4건으로 확장했다** (같은 날, `scripts/build_index.py`).
영양·증상·리콜, 물질명 없는 의미 질의 3건, 종 분기(개 백합), 검수 회귀(남천·국화)를 넣고,
음성은 **1위가 임계값 미만이어야 통과**로 뒤집어 판정한다.
### 2.5.4 확장 점검 실측 (2026-08-01, 같은 날)

**양성 16건 중 15건 통과 · 음성 4건 중 1건 통과.**

#### 확장이 곧바로 잡은 것 — 문장화 반전

> ```
> 원문 (S-003 AAV)   앵무새에게 소금 블록은 주지 마라
> 적재된 문장          "앵무새 전 생애단계의 소금 블록(salt block) 권장량이다."
> ```

`NUTRITION` 템플릿이 **`feeding_level`(축 B)을 한 번도 쓰지 않았다.**
`NEVER` 도 `CAUTION` 도 전부 *"권장량이다"* 로 렌더됐다 — **13행** 해당, 그중 1건이 급여 금지.

**§2.5.1의 문장화 충실도 목표 `0` 을 깨는 유일한 종류다.**
원문에 없는 내용이 아니라 **원문과 반대되는 내용**이기 때문이다.

함께 드러난 두 번째 결함 — `max_value` 에 `unit` 이 없으면 절이 통째로 빠졌다.
`"얇은 조각 1~2쪽"` 처럼 값에 단위가 든 경우로, **S-047 과일 6종의 급여량이 소실**돼 있었다.

→ 둘 다 고치고 `tests/test_verbalize.py` 에 회귀 8건을 고정했다.
수정 후 문장:

```
앵무새에게 소금 블록(salt block)은 급여 금지다.
개에게 사과는 조건부 급여다. 1회 권장량은 얇은 조각 1~2쪽까지다.
```

#### 남은 실패 4건 — **고칠 수 있는 것과 아닌 것**

| | 실패 | 성격 |
|---|---|---|
| 양성 1 | 차고의 달콤한 액체 → 1위 `강박 핥기·씹기`(S-080) | **점검 설계가 틀렸다.** 코퍼스에 `달콤`·`단맛`·`차고` 가 **0건**이라 맞힐 방법이 없다 — 맞혔다면 임베딩 사전지식이 답을 만든 것이다. `UNKNOWN_SUBSTANCE_PROBES` 로 옮겼다 (D-49 후속) |
| 음성 3 | 캣타워 0.574 · 미용 0.520 · 보험료 0.564 | **임계값으로 못 고친다** — 아래 |

**음성이 양성보다 높다.**

```
양성 최저   0.547   PTFE
음성 최고   0.574   캣타워 → 트립토판
```

캣타워를 막으려면 0.574 위로 올려야 하는데 그러면 PTFE·개 백합(0.605)·리콜(0.615)·
췌장염(0.616)이 함께 죽는다. **어떤 임계값도 이 둘을 가르지 못한다.**

> **D-46 이 433청크에서 내린 결론이 888청크에서 재확인됐다.**
> *"유사도 임계값은 거절을 만들지 못한다 — 거절은 ①분류·④검증 책임이다."*
> 캣타워·미용·보험료는 **검색 전에** `intent=general` 로 걸러야 한다.
> 골든셋 `G-006`(날씨)·`G-015`(캣타워)가 `refused` 인 것이 같은 근거다.

음성 3건 중 2건이 **영양 청크**를 물어온 것(트립토판·BMR)은 따로 볼 값이다.
`"반려동물 전 생애단계의 기초대사율(BMR) 권장량이다."` 처럼
**수치가 하나도 없는 껍데기 청크가 17건** 있고, 이런 문장이 아무 질의에나 떠오른다.

#### 아직 판정하지 못한 것

- 껍데기 청크를 인덱스에서 뺄지 — **먼저 문장을 고쳤다** (아래 §2.5.5)

### 2.5.5 점검이 **통과시킨** 것 — 증상 질의 (D-49)

```
✓ '고양이가 토하고 밥을 안 먹고 배를 아파해요'
      1위 0.616 · 토마토 (S-016)
```

**초록불이었다.** 기대한 `췌장염` 이 상위 5 안에 있으면 통과하는 기준이라
1위가 엉뚱해도 드러나지 않았다.

처음에는 `토하고`/`토마토` 의 표면 형태가 겹친 줄 알았다. **오진이었다.**
1위 청크의 원문은 이렇다.

> "고양이에게 토마토는 조건부로 분류된다.
>  주요 증상은 과도한 침 흘림, **식욕 부진**, **침울**, **쇠약**, 동공 확대, 서맥이다."

*밥을 안 먹고* → 식욕 부진, *배를 아파해요* → 침울·쇠약.
**검색은 제대로 일했다.** 문제는 검색이 아니라 질문의 방향이었다.

코퍼스는 D-14 로 물질 단위이므로 각 청크가 *"이 물질 → 이런 증상"* 이다.
증상만 주면 그 화살표를 거꾸로 타는데 **역방향은 일대일이 아니다** —
고양이 청크 418건 중 **21건이 같은 증상 조합**을 나열한다.

**여기서 1위를 근거로 답하면 "토마토 중독일 수 있습니다" 가 되고, 그것이 진단이다** (D-11).
같은 이유로 **기대값 `췌장염` 자체가 틀렸다** — 증상에서 질환을 짚는 것도 진단이다.
**통과했어도 틀린 통과였다.**

→ **D-49** 로 기록하고 두 가지를 바꿨다.

| 어디 | 무엇 |
|---|---|
| `build_index.py` | 증상 질의를 양성 프로브에서 빼고 `SYMPTOM_PROBES` 로 옮겨 **판정하지 않고 모호도만 보고**한다 (상위가 몇 종으로 흩어지는지 · 점수 폭) |
| `check_goldenset.py` | `intent=symptom` + `answered` 인데 `must_not_contain` 이 비면 WARN |

**`build_index` 에 초록·빨강을 안 매긴 이유** — 올바른 동작은 ①분류·②되묻기의 몫인데
그 스크립트는 저장소만 들고 있어 검증할 수 없다.
**검증할 수 없는 것에 판정을 찍으면 그 초록불이 곧 거짓 근거가 된다.**

#### 모호도 실측 — 1위는 **잡음 안에서 결정된다**

| 질의 | 상위 5의 물질 | 서로 다른 종 | 점수 폭 |
|---|---|---|---|
| 고양이가 토하고 밥을 안 먹고 배를 아파해요 | 토마토 · 초콜릿 · 췌장염 · 알리움류 · 초콜릿 | **5종** | **0.030** |
| 강아지가 자꾸 침을 흘리고 기운이 없어요 | 가정용 청소용품 · 천식 · 석유증류물 · 울혈성 심부전 · 흉막 질환 | **5종** | **0.019** |
| 앵무새가 깃털을 부풀리고 바닥에 앉아 있어요 | 저체온 · 깃 고르기 · 골절 · 화상 · 페놀계 세정제 | **5종** | **0.042** |

**점수 폭이 0.019~0.042 다.** 양성 프로브의 1위–최저 간격이 0.18(0.547~0.728)인 것과 비교하면
**한 자릿수 배 좁다.** 이 구간 안에서 순위는 사실상 임의이고,
임베딩을 재적재하거나 청크 문장을 한 글자 고치면 1위가 바뀔 수 있다.

내용을 보면 더 분명하다. 개 질의의 상위 5는 **청소용품 · 천식 · 석유증류물 · 심부전 · 흉막 질환** 이다 —
중독과 내과 질환이 뒤섞여 있고, **어느 하나를 골라 답하면 나머지 넷을 배제한 셈**이 된다.
그 배제가 곧 진단이다.

> **이 표가 D-49의 근거다.** "1위가 애매하다"는 인상이 아니라
> **1위와 5위의 차이가 측정 잡음과 같은 크기**라는 사실이다.

### 2.5.6 확장 후 실측 (2026-08-01, 3차 재적재)

**양성 14건 전부 통과 · 음성 4건 중 1건 · 보고 6건.**

빨간불이 없어진 것이 아니라 **판정 대상이 아니게 된 것**이다.
증상 질의와 물질 서술 질의를 통과/실패 채점에서 빼고 보고로 돌렸다 (D-49).

#### 보고가 곧바로 잡은 것 — **검사기 자신의 결함**

```
· '강아지가 차고 바닥에 흘린 달콤한 액체를 핥았어요'
    상위 5: 앞발·다리 강박 핥기 · 표면 강박 핥기 · 강박장애(CCD) · **부동액** · 청소용품
    사람이 아는 정답 '에틸렌글리콜': 상위에 없음 (정상)
```

**"상위에 없음" 이 아니다. 4위에 `부동액`(S-029)이 있다.**
정답을 `에틸렌글리콜` 한 이름으로만 적어 두어 검사기가 못 알아봤다.

> §8과 같은 종류의 실수다 — **검사기가 틀리면 그 초록불이 곧 거짓 근거다.**
> 정답을 별칭 묶음(`에틸렌글리콜`·`부동액`)으로 바꾸고 **몇 위인지**를 함께 찍게 했다.

그래서 D-49 후속의 서술도 정확히는 이렇다. 코퍼스에 `달콤`·`단맛`·`차고` 는 **0건이 맞고**,
1~3위가 `핥기` 표면 일치로 채워진 것도 맞다. 다만 **부동액이 4위로는 올라온다** —
`반려동물과 부동액에 관한 자료다`(S-029)라는 **내용이 거의 없는 청크**다.
근거로 쓰기에는 부족하고, 되묻기가 옳다는 결론은 변하지 않는다.

#### 또 하나 — 같은 물질이 상위를 채운다

```
· '고양이가 베란다에 둔 파란 알갱이를 주워 먹었어요'
    상위 5: 사람 음식 · **양파 · 양파 · 양파** · 토란
```

`양파` 청크가 **8건**이다 (S-010·S-019·S-029·S-034 ×2·S-063·S-098 ×2).
고양이 질의는 D-39 병합(`cat`+`mammal`+`all`)으로 그중 4건을 함께 본다.

**`top_k=5` 가 실질적으로 서로 다른 물질 3종이 된다.**
검색이 틀린 것은 아니지만 **문맥 예산을 같은 말로 채운다** —
`compute/tables/README.md` 가 계산 노드에 대해 적어 둔 *"중복 히트를 하나로 접어야 한다"* 가
검색 단계에도 그대로 필요하다. `retrieval/store.py`·`graph/nodes/retrieve.py` 어디에도 접는 코드가 없다.

> **점검이 통과했다는 것과 검색이 된다는 것은 다르다.**
> 무엇을 점검하지 않았는지를 함께 적지 않으면, 초록불이 곧 근거로 둔갑한다 (§8).
> **이번에는 초록불 자체가 틀린 경우였고, 그다음에는 검사기가 틀린 경우였다.**

### 4.1 과소평가율을 최우선 지표로 선언한다

#### 4.1.0 등급 체계와 계산 정의 (D-39)

등급은 **4단계 순서형**이며 **숫자가 클수록 위험**하다.

| 값 | 정수 | 배지 |
|---|---|---|
| `EMERGENCY` | **4** | 응급 |
| `CALL_NOW` | **3** | 전화 |
| `VISIT_SOON` | **2** | 내원 |
| `MONITOR` | **1** | 관찰 |

| 지표 | 정의 |
|---|---|
| **등급 일치도** | `예측 == 정답` 비율 |
| **인접 오차 허용 일치도** | `|예측 − 정답| ≤ 1` 비율 — 보조 지표 |
| **🔴 과소평가율** | `예측 < 정답` 비율. **최우선 지표** |
| 과대평가율 | `예측 > 정답` 비율 |
| **중대 과소평가율** | **`정답 = EMERGENCY(4)` 인데 `예측 ≤ 2`** — 별도 분리 보고. **0을 목표로 한다** |

> **`MONITOR` 판정은 상승 조건을 함께 출력해야 정답으로 인정한다.**
> D-39의 이 단계는 *"if not resolving"* 이라는 조건부 상승이 본질이므로,
> 조건 없는 "관찰"은 **그 자체가 과소평가**로 채점한다.

**정답 등급은 골든셋 작성 시 근거 문서의 행동 지시어에서 결정한다.**
작성자가 임의로 매기지 않고, `chunk_id`와 함께 **근거 문장을 인용**한다 (§2.4).

> 실제로는 내원이 필요한 사례를 "관찰"로 답한 비율이며,
> 이 도메인에서 **유일하게 생명과 직결되는 오류**다.
>
> **일반 정확도가 높아도 과소평가율이 높으면 실패한 시스템으로 간주한다.**

이 기준을 명시하는 것 자체가 안전 설계를 의식했다는 신호이며, 보고서의 차별화 요소가 된다.

과대평가(over-triage)는 불필요한 병원 방문 비용을 유발하므로 함께 보고하되,
**두 지표가 상충할 때는 과소평가 억제를 우선**한다.

> **아키텍처 차원의 억제 장치가 있다.** 트리아지 **하향 금지 게이트**(02 §7.2 · 05 §5)는
> LLM이 규칙 등급보다 낮은 등급을 제시하면 무시한다.
> 지표로만 관리하는 것이 아니라 **구조로 막는다.** 효과는 실험 E6으로 측정한다.

### 4.2 종별 분리 보고

앵무새 자료는 개·고양이보다 분량이 적을 가능성이 높다.
**전체 평균만 보면 조류 성능 저하가 가려진다.**

>
> **실험을 안 한 것이 아니라 실험 대상이 없어진 것**이고, 그 경위는 D-19 후속에 기록했다.
> 연동돼 있던 **번역 태스크 ⑥도 함께 닫혔다** — 멀티태스크는 5종 확정이다 (D-05).

> **실험 전용 인덱스를 따로 만들어** 비교할 수 있다. 그 인덱스는 제출물·시연에 쓰지 않는다 —
> D-45가 막는 것은 **적재**이지 내부 측정이 아니다.

> **E6은 본 프로젝트 고유의 안전 설계 실험이다.**
> 게이트 적용으로 과소평가율이 얼마나 줄고 과대평가율이 얼마나 늘었는지를 함께 제시하여,
> **의도된 트레이드오프였음을 숫자로 증명**한다.

> **E4가 특히 중요하다.** "① 분류 노드를 제거하면 Recall@5가 얼마나 떨어지는가"를 보여야
> 각 태스크를 왜 채택했는지 근거가 선다 (03 §1.1).

## 7. 실패 분석

보고서에 **실패 사례가 하나도 없으면 오히려 신뢰도가 떨어진다.**

### 7.1 분석 방법

1. 오류를 **검색 실패 / 생성 실패 / 판정 실패**로 분류
2. 각 유형에서 대표 사례 3~5건 선정
3. 원인 → 조치 → 재측정 결과를 함께 기록

### 7.2 중점 관찰 대상

- **과소평가 사례 전수 분석** — 건수가 적더라도 모두 본다
- **종 혼동 사례** — 포유류 기준의 조류 적용
- 되묻기가 필요했는데 추측한 사례
- 거절해야 했는데 답한 사례 (근거 부족 상태에서의 생성)
- 조류 질의에서만 발생하는 실패 패턴
- **문장화 오류로 인한 실패** — 원문은 맞는데 우리 문장이 틀린 경우 (층 0에서 잡히지 않은 것)

### 7.3 개선 사이클

최소 1회의 **개선 전/후 비교**를 보고서에 포함한다.
예: 청킹 변경, 유사도 임계값 조정, 음성 샘플 보강, 소수 클래스 가중.
