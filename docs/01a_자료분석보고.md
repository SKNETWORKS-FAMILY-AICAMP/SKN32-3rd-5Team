### 2.4 출처 Tier 체계 (신설)

이근준·권소라 수집분에 상업 콘텐츠와 출처 불명 자료가 포함되면서 신뢰도 편차가 생겼다. 등급을 도입한다.

| Tier | 대상 | 사용 |
|---|---|---|
| **1** | 학술 논문 · 수의사회(AVMA·AAV·대한수의사회) · 정부(FDA·농진청·주정부) · Merck | **근거로 직접 인용** |
| **2** | 대형 동물병원(VCA·Cornell·AAHA) · 전문기관(ASPCA·Pet Poison Helpline·WPT) | 근거로 인용 |
| **3** | 상업 콘텐츠 (사료회사 블로그 · 앱 서비스) | **인용 금지 / 구조·용어 참고만** |

> **상충 시 Tier가 높은 쪽을 채택한다.** 상충 사례는 골든 셋에 포함하여 복수 근거 제시 동작을 평가한다.

#### ⚠️ 핵심 함의 — 수집 자료의 다수가 재배포 불가다

자유롭게 쓸 수 있는 자료는 **CC BY 2건뿐**이며, 그중 하나가 **정량 임계치의 유일한 소스**(Frontiers)라는 것이 다행이다.

나머지 다수는 *"무료 열람은 가능하나 재배포 불가"* 다. 그렇다면 다음이 문제가 된다.

> 원문을 벡터DB에 저장하고, 사용자에게 **원문 그대로 인용해 출력**하는 것은 재배포에 해당하는가?

내부 처리(교육·연구 목적의 색인·대조)는 인용 범위로 볼 여지가 있으나,
**원문 전문을 그대로 출력하는 것은 위험하다.**

#### → 출력 정책을 설계에 넣는다 (D-26 제안)

다행히 **본 시스템 설계와 자연스럽게 맞물린다.**

| 계층 | 취급 |
|---|---|
| **내부 (색인·검증)** | **원문 유지** — sLLM ④ 근거 검증은 원문과 대조해야 성립 |
| **사용자 출력** | **요약·평이화된 문장 + 출처 표기 + 원문 링크.** 원문 인용은 **짧은 발췌**로 제한 |

이미 존재하는 **sLLM ③(요약)·⑤(평이화)** 노드가 이 역할을 수행한다.
즉 *"원문을 그대로 뱉지 않는다"* 는 것이 **저작권 대응인 동시에 사용자 가독성 개선**이 된다.

**구현 조치**

- `quote` 필드는 **내부 검증용**으로만 사용하고, 출력 시에는 길이 상한을 둔다
- 출처 표기에 **원문 링크를 필수 포함**한다 (사용자가 원본으로 이동)
- `license`가 `불명확`인 자료는 **인덱싱에서 제외**한다 (Psitacídeos)
- WSAVA는 비영리 교육목적 조건에 부합하나, **사용 사실을 문서에 명시**한다

#### 부수 확보

- **Lafeber 조류 계산식이 확인되었다** — `BMR = 73.6 × 체중^0.73`. 계산 노드에 직접 투입 가능
- **Merck 간질환 자료에 구체적 수치(g/kg)** 수록 — 정량 소스가 하나 더 늘었다
- **신규 자료 1건** — 한국소비자원 「반려동물 영양제」 안전실태조사(2024.12). 중금속·유해세균·기능성 원료 함량 조사. **영양제/보조제 카테고리 신설 후보**

#### 미확인 사항

- 국립축산과학원·한국소비자원의 **공공누리 유형 표기 실물 확인**
- WSAVA **비영리 교육목적 재배포 허용 요청** 절차 필요 여부
- PPH는 robots.txt상 크롤링 허용이나 **Crawl-delay 준수 필요** (권소라 확인: 10초)

#### S-068 — 본문은 부적합하나 표 하나는 쓸모가 있다

수집자가 지목한 **p.88 표2 「반려견의 식품 종류」** 는 한국어 분류 체계다.

- **사료**: 전연령견 / 자견용 / 성견용 / 노령견 / 비만견 / 소형견·대형견 / 민감체질 / 피부개선 / 국내알뜰 / 분유이유식
- **간식**: 기능성개껌 / 캔·통조림 / 치즈 / 쿠키·비스킷 / 쇠고기·오리고기 / 사사미

**다이어리 급여 기록의 입력 선택지**로 활용할 수 있고, 생애단계 구분(자견·성견·노령견)은 프로필 `age_months` → 권장 사료 매핑과 연결된다.

> 다만 원 출처가 *권홍규·정병국(2016), p.177* 재인용이므로 **원 출처 확인 후 사용**한다.
> 논문 본문(IPA 소비자 선호 분석)은 RAG 코퍼스에 부적합하므로 `reference_only`를 유지한다.

#### C 경로(계산 노드)의 핵심 데이터를 확보했다

표 구조가 계산 노드에 그대로 투입 가능한 형태다.

**세 가지가 결정적이다.**

1. **단위가 `/1,000 kcal ME`로 정규화**되어 있다 → 급여 기록에서 열량을 계산한 뒤 **바로 대조 가능**
2. **최소·최대를 모두 제시** → **결핍과 과잉을 양방향으로 판정**할 수 있다 (예: 칼슘 0.50~2.5 g, 비타민 A 500~40,000 IU)
3. **FEDIAF·AAFCO와 나란히 배치** → 국제 기준 3개를 한 표에서 비교

**MER 공식도 확인되었다.**

> 성견 유지 에너지 요구량(MER) = **90 ~ 200 kcal ME / kg^0.75** (견종·개체차 범위)
> 임신 4주: 132 kcal/kg 체중^0.75 · 임신 5주: 132 + 26 kcal/kg 체중 …

생애단계별 계수가 표로 제공되어 계산 노드 구현에 필요한 값이 모두 있다.

#### ★ Tier 1 간 상충 사례를 확보했다

같은 표 안에서 세 기관 값이 다르다.

| 영양소 | FEDIAF | AAFCO | NIAS |
|---|---|---|---|
| 셀레늄 (µg) | 18.0/23.0 | **35.0** | 18.0 |
| 철 (mg) | 3.60 | **4.0** | 3.60 |
| 아연 (mg) | 7.20 | **8.0** | 7.20 |
| 비타민 E (IU) | 3.60 | **5.0** | 3.60 |

**04 골든 셋의 "출처 간 기준값 상충" 소재로 이보다 좋은 사례가 없다.**
Tier 1 기관 간 상충이므로 01b §7.1의 "Tier 3 오류는 상충으로 취급하지 않는다" 조건도 충족한다.
→ 시스템은 **복수 근거를 함께 제시**해야 하며, 국내 자료이므로 **NIAS를 기본값**으로 삼는다.

#### 라이선스 — 인용 문구가 명시되어 있다

문서 판권지에 **인용 방법이 직접 제시**되어 있다.

> "인용 문구: 국립축산과학원. 2024. 반려동물 사료 영양표준 (개·고양이): 1판."
> "Suggested citation: National Institute of Animal Science. 2024. *Korean feeding standard for dog and cat: First Edition.* Wanju, Korea."

공공누리 유형 표기는 문서 내에 없으나, **정부간행물이면서 인용 문구를 스스로 제공한다는 것은 출처 표기 인용을 전제한 자료**라는 뜻이다. D-28(사실 추출 + 출처 표기)과 정확히 부합한다.

## 5. 확인된 구조적 과제

### 5.1 한국어 명칭이 전 자료에 없다

세 자료 **모두** 한국어 명칭이 없다. ASPCA는 영문 일반명만, PPH는 `name_ko` 전부 결측.

사용자는 *"백합"* 이라고 하지 *"lilium"* 이라고 하지 않는다.
학명은 다국어 임베딩으로 어느 정도 매칭되겠지만 **한국어 일반명 매칭은 보장할 수 없다.**

→ **`substance_ko` 매핑 사전 구축을 별도 작업으로 세운다.**

| 대상 | 소스 후보 |
|---|---|
| 식물 | 국립수목원 국가표준식물목록 (학명 ↔ 국명) |
| 의약품 | 성분명 한글 표기 |
| 식품 | 일반 명칭 |

D-19(cross-lingual)의 실제 난점이 여기서 드러났다.

### 5.2 파싱 품질이 자료마다 다르다

| 유형 | 이슈 |
|---|---|
| **잡지·회보 (기사 병렬)** | **다른 기사와 본문 혼입 → 영역 분리 파싱 또는 수동 발췌** (S-063) |
| 2단 조판 논문 | 좌우 컬럼 혼입 → **컬럼 분리 파싱 필수** (S-034) |
| 크롤링 CSV | HTML 구조 유실로 공백 소실 → 셀렉터 보정 후 재크롤링 |
| 정형 CSV | 행 단위가 의미 단위와 불일치 → 학명 기준 병합 |

### 5.3 중복

- ASPCA plants(594 학명) ↔ PPH plants(198) — 학명 부재로 이름 기준 매칭 필요
- ASPCA cats/dogs plant list(웹) ↔ 정형 데이터셋 — **데이터셋으로 통합** (웹판은 검증용)
