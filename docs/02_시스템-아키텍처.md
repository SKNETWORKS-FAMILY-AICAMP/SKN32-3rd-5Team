## 1. 개요

본 시스템은 **네 개의 파이프라인**으로 구성된다. 하나의 다이어그램으로 뭉치지 않고 분리하여 제시한다.

| 파이프라인 | 성격 | 절 |
|---|---|---|
| 질의 | 온라인 | 2 |
| 인덱싱 | 오프라인 | 3 |
| 학습 | 오프라인 | 4 (상세는 03) |
| 기록·리포트 | 배치 | 5 |

**설계 원칙**

- 지식은 RAG로, 태스크 수행 능력은 파인튜닝 sLLM으로 (00 §2)
- **결정론은 코드로, 판단·해석만 LLM에게** — 판단 기준은 **05** 문서
- **근거가 없으면 답하지 않는다** — 거절·되묻기를 1급 동작으로 취급
- **종이 확인되지 않으면 답하지 않는다** — 포유류 기준의 조류 오적용 방지
- **안전 관련 조정은 한 방향(위험도 상향)으로만** — 트리아지 하향 금지 게이트 (§7.2)
- **원인을 모르면 좁히지 않고 되묻는다** — 증상·물질 미상 서술을 검색으로 추정하지 않는다 (D-49 · §9)
- **지역에 따라 달라지는 정보는 출력 직전에 코드가 뺀다** — 외국 핫라인 차단 (D-47 · §6.2 `finalize`)
- **저장된 값을 판정에 쓰기 전에 확인을 받는다** — 프로필 체중은 낡는다 (D-52 · §11.1)
- sLLM 노드는 모두 **대형 LLM 폴백 경로**를 가진다 (파인튜닝 실패 시에도 시스템 동작)

### 1.1 미채택 구조와 근거

정지 판정 결과 다음 구조는 **의도적으로 채택하지 않는다** (05 §2).

| 미채택 | 근거 |
|---|---|
| **ReAct 에이전트 루프** | 계산 노드는 있으나 **LLM이 도구를 선택할 필요가 없다.** intent가 정해지면 어떤 계산이 필요한지 코드가 안다 |
| **MCP** | 도구 재사용·표준화 수요 없음. 외부 에이전트에 도구를 노출할 계획 없음 |
| **멀티에이전트 · A2A** | God Object 아님. 도구 5~7개+ 아님. 역할 분리 수요 없음 |

> 계산 노드는 **에이전트가 선택하는 도구가 아니라, 그래프가 조건부로 호출하는 함수**다.

**되묻기 경로가 이 시스템의 특징이다.** 체중과 섭취량 없이는 위험도를 판단할 수 없으므로,
추측하지 않고 되묻는다. 이는 **환각 방지의 직접적 증거**로 시연된다.

> **되묻기는 슬롯이 빈 경우에만 발생하지 않는다 (D-49).** *"토하고 밥을 안 먹어요"* 처럼
> 증상만 있는 질의에 검색을 태우면 **증상 목록이 겹치는 아무 물질이나 1위로 올라온다** —
> 실제로 토마토(S-016)가 0.616으로 올라왔다 (04 §2.5.5). 원인을 검색으로 찾지 않고 되묻는다.
> *"차고 바닥의 달콤한 액체"* 같은 **물질 미상 서술**도 같다. 부동액으로 추정하는 순간
> 아니었을 때 되돌릴 방법이 없다.

### 3.1 경로 ②가 만드는 새 검증 층

**벡터DB에 들어가는 것이 우리가 쓴 문장이므로, 문장화 자체가 검증 대상이 된다.**
환각 방지 지점이 답변 단계에서 **문장화 단계로 이동**한다 (D-38).

```
[런타임]  답변 ↔ 검색된 청크        → sLLM ④ 근거 검증
[빌드타임] 우리 문장 ↔ 원문          → 04 §2.5 층 0
```

문장화를 **템플릿 + 코드**로 하므로 검증 대상이 문장이 아니라 **필드**로 축소된다.
지표 3종(추출 정확도 / 문장화 충실도 / 역추적 가능성)은 **04 §2.5** 참조.

> **부수 효과**: 임계값 필드가 비면 정량 문장이 생성되지 않는다.
> 조류는 정량 임계치가 0건이므로 **조류 청크는 자동으로 정성 문장만 나온다** —
> §7.2 하향 금지 게이트의 종별 분기가 **데이터 단계에서 강제**된다.
>
> **실측 확인 (2026-08-02)**: `species = bird` 159행 중 `dose` 또는 `max_value` 를 가진 행은 **0건**이다.
>
> ⚠️ **단, `species = all` 은 예외다.** 77행 중 **32행이 정량을 가지고 있고**, §8.1 필터가
> 조류 질의에도 `all` 을 포함시킨다. 따라서 *"데이터 단계에서 강제"* 는 `bird` 청크에만 성립한다.
> 조류 정량 판정을 막는 것은 데이터가 아니라 **`triage.quantitative_species: [dog, cat]`**
> (`configs/default.yaml`) 이며, `rule_level_for()` 가 조류에 대해 `None` 을 돌려주는 것으로 확인했다.

파싱·청킹·스키마의 상세 근거는 **01 §2.1·§2.2 및 9~12장**에서 관리한다.

## 5. 기록·리포트 파이프라인 (배치)

```
[Chroma internal]  누적 일일 기록        ← ❌ 아직 RecordStore(메모리)다
        │
        ├─ pandas ──► 집계 (급여 이력 · 증상 빈도 · 체중 추이)
        │              여기는 NaN 이 편하다 — 판정이 아니라 집계다 (D-52)
        │
        ├─ ③ 요약 (기간 단위)  ← sLLM
        │
        ▼
   기간 리포트 ──► 이상 징후 탐지 ──► 내원 권고 알림
        │
        └─ [MySQL pets]  이름·종·품종을 붙인다 (표지용 · 판정 근거 아님)

**병원 방문용 요약 리포트**가 이 파이프라인의 최종 산출물이며, 시연 하이라이트에 해당한다 (00 §3.3 구현 3단계).

> **여기가 pandas 의 제자리다** (D-52). *"30일치 급여 이력에서 특정 성분 빈도"* 같은 것은
> DataFrame 이 훨씬 낫다. §11.1 이 금지한 것은 **판정 경로의 프로필 조회**이지 집계가 아니다.

## 6. LangGraph 상태 그래프 설계

### 6.1 상태(State)

> ⚠️ **아래는 설계 표기다. 구현의 단일 출처는 `src/pettriage/graph/state.py` 의 `GraphState` 다.**
> 이름이 다른 곳이 있고, 그 경우 **코드가 맞다** — 아래 §6.1.1 대조표를 본다.
> 문서 이름으로 코드를 짜면 `AttributeError` 가 난다.

```python
class QAState(TypedDict):
    # 입력
    query: str
    pet_id: str | None
    user_role: Literal["owner", "admin"]

    # ① 분류
    intent: str                    # intoxication | symptom | nutrition | general
                                   # 어휘의 단일 출처는 04a §스키마 · check_goldenset.py
    risk_category: list[str]

    # ② 슬롯
    slots: dict                    # species, weight_kg, substance, amount_g, elapsed_h, symptoms
    missing_slots: list[str]
    clarify_count: int             # 되묻기 횟수 (상한 2회)
    weight_source: str | None      # user | profile_confirmed — 감사용 (D-52).
                                   # 프로필 값을 확인 없이 쓴 적이 없음을 증명한다

    # 검색 — 호출 순서는 search → filter_by_threshold → dedupe_by_substance (§8.3)
    filters: dict                  # species, source_type, date_range
    retrieved: list[Hit]           # Hit.merged_sources — 같은 물질을 접었을 때 합쳐진 출처
    computed: dict                 # 계산 노드 결과

    # 생성
    compressed_context: str
    draft_answer: str

    # 트리아지 — 규칙과 LLM 판정을 분리 보관 (§7.2 · D-39)
    # 값: EMERGENCY(4) > CALL_NOW(3) > VISIT_SOON(2) > MONITOR(1) — 클수록 위험
    rule_triage_level: int | None   # 규칙이 보장하는 **바닥**. 확정 판정이 아니다 (D-50)
    llm_triage_level: int | None    # LLM 판정 (규칙 미적용 시에도, 적용 시에도 받는다)
    triage_level: int               # 최종 = max(rule, llm) — 하향 금지
    escalation_conditions: list[str]  # MONITOR일 때 필수 — 조건 없으면 과소평가
                                      # 규칙(RuleVerdict)과 LLM 양쪽에서 채워질 수 있다
    feeding_level: str | None       # 축 B: NEVER / CAUTION / SAFE (급여 가부, 긴급도와 별개)

    # ④ 검증
    verification: list[dict]       # 문장별 판정
    retry_count: int               # 재검색 횟수 (상한 1회)

    # 출력
    final_answer: str
    citations: list[dict]
    refused: bool
    removed_contacts: list[str]    # finalize 가 뺀 문장 (D-47 · 감사용). 비면 아무것도 안 뺐다
```

> **`rule_triage_level` 을 `triage_level` 과 분리해 두는 이유가 D-50에서 하나 더 늘었다.**
> 규칙이 낸 값은 **판정이 아니라 바닥**이므로, 최종 등급이 규칙보다 높아도 그것은 모순이 아니다.
> 두 값을 함께 보관해야 §12.1의 감사 정보(`rule_level` · `llm_level` · `overridden`)가 만들어진다.

### 6.2 노드와 조건부 엣지

| 노드 | 역할 | 분기 조건 |
|---|---|---|
| `classify` | ① 의도·위험 분류 | intent에 따라 필요 슬롯 집합 결정. **`symptom` 은 검색으로 원인을 찾지 않고 `clarify`** (D-49) |
| `load_profile` | **프로필 조회 (ORM · 코드)** | `pet_id` 가 있으면 MySQL `pets` 조회 → **확인 되묻기**. 없으면 통과 (D-52) |
| `extract_slots` | ② 슬롯 추출 | 결측 → `clarify` / 충족 → `retrieve`. **물질이 미상 서술이면 `clarify`** (D-49) |
| `clarify` | 되묻기 질문 생성 | 사용자 응답 후 `extract_slots` 재진입. **상한 2회 초과 시 거절** |
| `retrieve` | 벡터 검색 (+ 프로필·기록 조회) | **search → filter_by_threshold → dedupe_by_substance** 순서 고정. 결과 0건 → `refuse` |
| `compute` | 계산 노드 (비-RAG) → `RuleVerdict` | intent가 `nutrition`·`intoxication` 일 때만 실행 |
| `compress` | ③ 컨텍스트 압축 | 컨텍스트 길이 임계 초과 시에만 실행 |
| `rule_triage` | **규칙이 보장하는 바닥 등급 (코드)** | 적중해도 **확정이 아니다** — 항상 LLM 판정도 받아 `triage_gate` 로 (D-50) |
| `generate` | 답변 생성 + LLM 트리아지 판정 | |
| `triage_gate` | **하향 금지 게이트** — `max(rule, llm)` | 항상 `verify`로 |
| `verify` | ④ 근거 검증 | 근거 부족 → `retrieve` 재진입(1회) → 여전히 부족하면 `refuse` |
| `simplify` | ⑤ 평이화 | 전문 용어 포함 시 |
| `finalize` | **연락처 제거 (코드, D-47)** | `answered`·`refused` **양쪽 모두** 통과. 종료 직전 마지막 관문 |
| `refuse` | 거절 응답 생성 | `finalize` 로 |
| `respond` | 최종 응답 조립 (등급·출처·고지) | `finalize` 로 |

> **루프 상한을 반드시 둔다** — 되묻기 2회, 재검색 1회.
> 상한이 없으면 무한 루프가 발생하고 지연·비용이 폭증한다.

> **`finalize` 를 `respond` 안에 넣지 않고 노드로 분리한 이유** — 거절 응답에도 연락처가 실린다.
> *"가까운 동물병원에 연락하세요"* 를 LLM이 쓰면서 **Pet Poison Helpline 번호를 같이 붙인다.**
> 국내 사용자에게는 걸 수 없는 번호이고, 응급 상황에서 잘못된 번호를 주는 것은
> 아무것도 안 주는 것보다 나쁘다. `safety/contacts.py::scrub_contacts()` 가 **문장 단위로** 지운다 —
> 번호만 지우면 *"ASPCA APCC에 연락하세요"* 가 남는다.

## 7. RAG / 비-RAG 역할 분리

### 7.1 무엇을 코드가, 무엇을 검색이 하는가

영양·용량 평가는 상당 부분이 **정형 계산**이며, 벡터 검색으로 처리하면
*"그냥 계산식 아닌가"* 라는 반박을 받는다.

| 담당 | 처리 내용 |
|---|---|
| **계산 노드 (비-RAG)** | 체중·연령 기반 권장 열량, 급여량 대비 비율, **섭취량 대비 독성 임계치** |
| **RAG** | 특정 음식이 해당 종·품종·연령에 적합한지, 조합이 위험한지, 관찰 증상과 관련 있는지 |

이 분리를 명시하는 것 자체가 **설계 성숙도**로 평가된다.

### 7.2 트리아지 판정 — 하이브리드 + 하향 금지 게이트

트리아지 등급은 **규칙이 1차, LLM은 보조**다.

**등급 값 (D-39 · 코퍼스에서 도출)** — 숫자가 클수록 위험하므로 `max()`가 그대로 성립한다.

| 값 | 정수 | 배지 | 사용자 문장 |
|---|---|---|---|
| `EMERGENCY` | **4** | 응급 | 지금 바로 동물병원으로 가세요 |
| `CALL_NOW` | **3** | 전화 | 지금 수의사에게 전화해 상태를 알리세요 |
| `VISIT_SOON` | **2** | 내원 | 오늘 중 진료를 받으세요 |
| `MONITOR` | **1** | 관찰 | 집에서 지켜보고, 아래 증상이 나타나면 연락하세요 |

> **`MONITOR`는 `escalation_conditions`가 비면 출력하지 않는다.**
> 이 단계의 본질은 *"if not resolving"* 이라는 조건부 상승이므로,
> 조건 없는 "관찰"은 그 자체가 과소평가다 (04 §4.1.0).

```
[1차] 규칙 테이블 (코드)  ── ⚠️ 입력이 종별로 다르다 (D-09 개정)
      개·고양이 : 물질 × 체중당 섭취량   (정량)
      조류      : 물질 × 증상            (정성 — 체중당 용량 자료 0건)
                          │  →  RuleVerdict(level · crossed · conditions · conflict)
        ├─ 적중     → **바닥** 등급 확보. 확정이 아니다 (D-50)
        └─ 미적용   → level = None. 바닥이 없을 뿐, 거절이 아니다
                          │
[2차] LLM 판정 → llm_triage_level      ← 규칙 적중 여부와 무관하게 **항상** 받는다
                          │
[게이트] triage_level = max(rule_triage_level, llm_triage_level)   ← 클수록 위험
```

#### `rule_level` 은 판정이 아니라 바닥이다 (D-50)

규칙 테이블은 **역치를 넘었는가**만 안다. *"얼마나 위험한가"* 는 모른다.
초콜릿 20 mg/kg 과 200 mg/kg 은 같은 역치를 넘지만 같은 상황이 아니다.
그래서 규칙이 낸 값을 확정으로 쓰면 **상향할 자리가 사라진다.**

**역치 종류 → 바닥 등급 매핑** (`compute/rules.py`)

| `threshold_type` | 바닥 등급 | 행 수 |
|---|---|---|
| `임상징후 발현` | `CALL_NOW` — **상향 여지를 남기는 자리** | 11 |
| `중증` | `EMERGENCY` | 3 |
| `치사` | `EMERGENCY` | 1 |
| 역치 미달 | `MONITOR` | — |

> 실측: 초콜릿·개 10 mg/kg → `MONITOR` · 25 → `CALL_NOW` · 45 → `EMERGENCY` · 조류 → `None`.
> 회귀 테스트로 고정되어 있다.

**출처 상충 10배 룰** — 같은 물질·같은 역치 종류인데 출처 간 용량이 **10배 이상** 벌어지면
`conflict = True` 로 표시하고 **낮은 쪽을 믿지 않는다.** 안전 방향으로만 틀린다.
단위는 `to_mg_per_kg()` 로 통일한 뒤 비교하며(`mg/kg` · `g/kg` · `%`),
**역치 종류를 넘어서는 비교하지 않는다** — "임상징후 발현"과 "치사"가 10배 차이 나는 것은 정상이다.

> 이 정규화가 **교차 검증**도 만들어 냈다. 알리움 `0.5%` 와 양파 `5 g/kg` 이
> 둘 다 **5,000 mg/kg** 으로 수렴한다 — 서로 다른 출처가 같은 값을 다른 단위로 말하고 있었다.

> **조류 질의에 체중·섭취량 수치를 요구하는 슬롯·프롬프트를 두지 않는다.**
> 근거 자료에 없는 값이라 LLM이 지어낸다. 조류는 질적 조건으로만 판정한다.

**축 B — 급여 가부는 별개다.** `NEVER` / `CAUTION` / `SAFE` (조류는 `NEVER`/`CAUTION` 2단계).
*"포도는 개에게 금지"*(축 B)와 *"포도를 먹었으니 EMERGENCY"*(축 A)는 다른 판정이다.

> ### 🔒 LLM은 등급을 낮출 수 없다
> 규칙 등급보다 **낮은 LLM 판정은 무시**하고, **상향(안전 방향)만 수용**한다.

| 규칙 판정 | LLM 판정 | 최종 |
|---|---|---|
| 응급 | 관찰 | **응급** (하향 무시) |
| 관찰 | 응급 | **응급** (상향 수용) |
| 미적용 | 조기 내원 | 조기 내원 |

**이 게이트가 과소평가율(under-triage)을 구조적으로 억제한다.**
과대평가가 늘 수 있으나 **의도된 트레이드오프**이며, 04에서 두 지표를 함께 보고하되 과소평가 억제를 우선한다.

## 8. 검색 설계

### 8.1 필터 정책

| 필터 | 규칙 |
|---|---|
| `species` | **필수.** 질의 종과 `species` ∈ {해당 종, `mammal`(개·고양이만), `all`} 인 청크만 검색. **종 미확인 시 검색 자체를 수행하지 않는다** |
| `source_type` | `owner` → 본인 `pet_id` 기록 + external / `admin` → 전체 |
| `record_date` | 기록 참조형 질의에서 기간 한정 |
| `doc_type` | intent에 따라 우선 검색 대상 조정 (`intoxication` → `toxicity_*`, `nutrition` → `nutrition`) |

### 8.2 cross-lingual 검색 — **전제가 사라졌다** (2026-08-02 개정)

이 절은 *"외부 자료의 약 90%가 영문인데 사용자는 한국어로 질의한다"* 는 전제 위에 서 있었다.
**경로 ②가 그 전제를 없앴다.** 벡터DB에 들어간 **888청크는 전부 우리가 한국어로 쓴 문장**이다.
영문은 원문에만 남아 `data_work/` 에서 골든셋 채점 기준으로 쓰인다 (D-29). 검색 대상이 아니다.

| 방식 | 이전 | 현재 |
|---|---|---|
| (a) 사전 번역 인덱싱 | 비교군 | **불필요** — 번역할 영문 청크가 0건 |
| (b) 다국어 임베딩 | 기본안 | 유지하되 **근거가 바뀌었다** (아래) |
| (c) 질의 번역 | 예비 | **미채택** — 번역할 대상이 없다 |

**bge-m3 는 그대로 쓴다. 다만 "다국어라서" 가 아니다.** 남은 근거는 **한국어 검색 성능**이다.
청크와 질의가 둘 다 한국어이므로 cross-lingual 능력은 이 시스템에서 쓰이지 않는다.
번역 태스크(⑥)를 멀티태스크 학습에 넣지 않기로 한 것도 같은 이유다 (03 · D-19 후속).

> **(a)/(b) Recall@k 비교 실험은 수행하지 않는다.** 비교군 (a)를 만들 수 없어 실험이 성립하지 않는다.
> 04의 임베딩 실험은 **청킹 전략(E1)** 비교로 대체되었다.

### 8.3 검색 파라미터 — **실측 확정** (D-46)

`configs/default.yaml` 이 단일 출처다 (D-41).

| 파라미터 | 값 | 근거 |
|---|---|---|
| `top_k` | **5** | 물질 단위 청킹이라 한 물질에 필요한 청크가 적다 |
| `score_threshold` | **0.50** | 아래 — 낮게 잡는 것이 의도다 |
| `rerank` | `false` | 구현 2단계 이후 선택 적용 |
| `embedding_model` | `BAAI/bge-m3` | §8.2 |

> ### ⚠️ 임계값은 거절을 만들지 못한다 (D-46)
> 초안은 *"임계값 미만이면 검색 실패로 간주하고 거절한다"* 였다. **실측이 이를 뒤집었다.**
>
> | | 유사도 범위 |
> |---|---|
> | 근거 **있는** 질의 | 0.547 ~ 0.733 |
> | 근거 **없는** 질의 | 0.494 ~ 0.659 |
>
> **두 분포가 겹친다.** 어떤 값을 잘라도 한쪽이 틀린다. 0.66 으로 올리면 근거 있는 질의를
> 대량으로 거절하고, 0.49 로 내리면 근거 없는 질의를 통과시킨다.
>
> 그래서 **임계값은 명백한 잡음만 걷어내는 하한(0.50)으로 두고, 거절은 노드가 책임진다** —
> **①분류**가 답할 수 없는 질의를 앞에서 되묻기로 보내고(D-49), **④검증**이 근거 없는 문장을 뒤에서 지운다.
> 재현: `python scripts/calibrate_threshold.py`

**호출 순서는 고정이다** — `search` → `filter_by_threshold` → `dedupe_by_substance`.

`dedupe_by_substance` 는 같은 `(substance, species)` 청크를 하나로 접고 출처를 `merged_sources`
로 합친다. 접지 않으면 **한 물질의 출처 3건이 top-5 중 3칸을 먹어** 다른 물질이 밀려난다.
순서를 바꾸면 안 된다 — 임계값보다 먼저 접으면 잡음 청크가 좋은 출처를 흡수한다.

## 9. 거절·되묻기 정책

| 상황 | 동작 | 근거 |
|---|---|---|
| 종 미확인 | **되묻기 (강제)** | D-09 |
| 필수 슬롯 결측 (체중·섭취량 등) | 되묻기 (최대 2회) | |
| **증상만 서술 — 원인 물질 없음** | **되묻기** "무엇을 먹었는지 아시나요?" | **D-49** |
| **물질을 미상으로 서술** ("달콤한 액체") | **되묻기** "어떤 것이었는지 확인되나요?" | **D-49** |
| 검색 결과 0건 | 거절 — "제공된 자료에서 근거를 찾을 수 없습니다" | |
| 근거 검증 실패 | 재검색 1회 → 여전히 실패 시 해당 문장 제거 또는 거절 | |
| 되묻기 상한 초과 | 거절 + 수의사 상담 권고 | |
| 판단 회색지대 | **단정하지 않고 "관찰 필요 / 내원 권장"** 으로 응답 | |
| **연락처를 물음** | 지역별 안내 불가 고지 + 가까운 동물병원 안내 | **D-47** |

> **유사도 임계 미만은 더 이상 거절 사유가 아니다 (D-46).** §8.3 참조 —
> 근거 있음/없음 분포가 겹쳐 임계값이 두 경우를 가르지 못한다.
> 거절은 **①분류(앞)** 와 **④검증(뒤)** 이 만든다.

> **되묻기가 늘어난 것은 후퇴가 아니다.** 증상 질의에 검색을 태우면 답은 나오지만
> **증상 목록이 겹치는 아무 물질이나** 근거로 붙는다 (04 §2.5.5의 토마토 사례).
> 이 도메인에서 그럴듯한 오답은 무응답보다 나쁘다.

**모든 응답에 고지 문구를 노출한다.**

> "본 안내는 참고용이며 수의학적 진단이 아닙니다. 이상이 의심되면 수의사와 상담하세요."

**출력은 존댓말로 통일한다 (D-47).** 응급 상황의 사용자에게 반말·명령형은 쓰지 않는다.
등급별 행동 문장(§7.2)과 거절·되묻기 문구가 모두 같은 어투를 쓴다.

## 11. 벡터DB — **Chroma 확정** (D-44)

| 후보 | 장점 | 단점 | |
|---|---|---|---|
| **Chroma** | 서버 없이 파일 기반. `pip install` 만으로 돈다 | 정형 데이터 조인에 약함 | **채택** |
| pgvector | 메타데이터 필터를 SQL로 처리. 정형 기준표를 같은 DB에서 관리 | Docker·서버 기동 부담 | 보류 |
| Qdrant | 하이브리드 검색 내장, 필터 성능 우수 | 별도 서버 운영 | 미검토 |

**초안은 pgvector를 우선 검토로 두고 있었다.** 근거가 *"정형 기준표를 같은 DB에서 관리해
계산 노드와 통합"* 이었는데, **그 전제가 D-38에서 사라졌다** — 문장화도 계산도 코드가 하고,
정량 임계치는 `compute/tables/*.csv` 를 코드가 직접 읽는다. 조인할 대상이 없다.

실제로 필요한 필터는 `species` · `doc_type` · `substance` 의 **동등 비교와 목록 포함**뿐이며,
Chroma의 `where` 로 충분함을 실측했다 — D-39의 고양이 병합 검색
(`species` 를 `["cat","mammal","all"]` 로 넘기는 경로)까지 동작한다.

> **교체 비용은 한 파일이다.** `VectorStore` Protocol 뒤에 있어서
> 갈아야 할 때 다시 쓰는 것은 `retrieval/store.py` 하나이고 **그래프 노드는 손대지 않는다.**
> `compose.yaml` 의 pgvector 서비스는 **걷어냈다** (2026-08-01, D-48).
> 남겨 두면 `docker compose up` 이 쓰지도 않는 Postgres 를 띄운다.
> 지금 `db` 서비스는 **계정·프로필 전용 MySQL** 이고 벡터와 무관하다.

**텔레메트리는 끈다** — 개인 기록을 다루는 시스템이 외부로 사용 신호를 내보내면 안 된다 (D-36).

### 11.1 데이터 저장소는 **셋**이다 — 담는 것이 다르다

세 저장소가 한 그림에 나온 적이 없어 *"MySQL 이 내부 문서 저장소인가"* 라는 오해가 생겼다.
**아니다.** 각자 담는 것과 접근 방식이 다르다.

```
                    ┌──────────────────────────────────────────────┐
  질의 ─────────────┤  ① 분류 → ② 슬롯                             │
                    │        │                                     │
                    │   load_profile ──ORM──► MySQL  `pets`        │  누가 · 무엇을 기르나
                    │        │  (D-52 · 확인을 받는다)   `users`    │  🟡 판정 근거 아님
                    │        │                        `chat_*`     │
                    │   retrieve ──벡터──► Chroma `external` 888청크│  공적 지식  ✅
                    │        │        └──► Chroma `internal`       │  일일 기록  ❌ 미구현
                    │        ▼                                     │
                    │   compute ──파일──► compute/tables/*.csv      │  정량 임계치 (생성물)
                    └──────────────────────────────────────────────┘

  배치 ─────────────► 누적 일일 기록 ──pandas──► 기간 리포트 (§5)
```

| 저장소 | 담는 것 | 읽는 법 | 상태 |
|---|---|---|---|
| **MySQL** | 계정 · **반려동물 프로필**(`weight_kg`) · 대화 이력 | **ORM** (D-52) | ✅ D-48 |
| **Chroma `external`** | 공적 자료 문장화 청크 **888** | 벡터 검색 | ✅ |
| **MySQL `records`** | **일일 기록의 원본** (D-53) | ORM | ❌ 아직 없다 |
| **Chroma `internal`** | 일일 기록 **인덱스** — 원본에서 재생성 | 벡터 검색 | ❌ `RecordStore` 가 아직 메모리다 |
| `compute/tables/*.csv` | 정량 임계치 | 파일 (생성물) | ✅ |

> **일일 기록은 양쪽에 다 있다** (D-53). MySQL 이 **원본**, Chroma 가 **인덱스**다.
>
> ```
> data/facts/facts_ohb.csv 888행 ──build_index──► Chroma external 888청크
> MySQL records            (원본) ──재인덱싱────► Chroma internal
>                                  record_id 단건 upsert/delete
> ```
>
> **벡터DB만 쓰면 안 되는 이유** — 기록은 **자주 수정된다.** 지우다 빠뜨린 청크가
> 유령처럼 검색되고(*"사료 300g"* 과 *"150g"* 이 둘 다 뜬다), 삭제 요청에도
> 벡터DB에 남으면 **삭제가 안 된 것**이다 (D-36 삭제권).
>
> **MySQL 만 쓰면 안 되는 이유** — 검색 대상이 아니게 된다.
> 05 §3 이 *"일일 기록은 조각 3(기억)이 아니라 **조각 4(RAG)**"* 로 못박은 이유이고,
> *"내 기록 × 공적 기준 → 판정"* 이 성립하려면 공적 지식과 같은 검색 공간에 있어야 한다.
>
> **비용은 문제가 아니다** — 실측 청크당 **193ms**, 기록 1건이 **0.2초**다 (D-53).
> 저장은 동기, 인덱싱은 비동기이고 `RecordCreated.indexed` 가 그 상태를 나른다.

#### 프로필은 **자동으로 채우지 않는다** (D-52)

`pet_id` 가 계약에 있고 `Pet.weight_kg` 가 DB 에 있지만, **둘을 잇는 코드가 없었다** —
`routes/ask.py` 가 `get_db` 를 주입받지 않는다. 잇되 이렇게 잇는다.

```
등록된 코코(말티즈)의 체중이 5.2kg 으로 되어 있습니다. 지금도 맞나요?
  → 예     : 그 값으로 판정 · 감사 정보 weight_source=profile_confirmed
  → 아니오 : 현재 체중을 되묻는다
```

**등록 체중은 낡는다.** 강아지는 몇 달 만에 두 배가 된다 — 낡은 값으로 mg/kg 을 계산하면
등급이 통째로 어긋난다. **되묻기를 없애는 것이 아니라 확인으로 바꾼다.**

> ⚠️ **판정 경로의 DB 조회에 pandas 를 쓰지 않는다** (D-52).
> `weight_kg` 는 `nullable` 이고, `pd.read_sql` 은 `NULL` 을 **`NaN`** 으로 바꾼다.
> `NaN` 은 `float` 이라 `is None` 검사를 통과하고, **어떤 비교에도 `False`** 를 돌려준다 —
> 역치를 하나도 안 넘긴 것으로 판정되어 **조용히 `MONITOR`** 가 된다.
> 에러도 로그도 남지 않는다. *"미정"* 은 값이 아니므로 `NULL` 로 저장한다.
>
> **pandas 는 §5 기간 리포트에서 쓴다** — 집계는 `NaN` 이 오히려 편하다.
> 경계는 **"`NULL` 이 판정에 흘러드는가"** 다.

## 12. 배달 계층 — API 계약과 데모 UI (WS5)

**구현 방식 확정 (D-40)**: FastAPI가 API와 정적 프론트를 **같은 출처에서** 서빙한다.
빌드 도구·node 의존성·CORS 설정이 없고, 시연 재현이 `make serve` 한 줄로 끝난다 (04 §8).

```
app/web/index.html ──HTTP──> FastAPI ──Protocol──> QAEngine
                          (계약)      │           ├─ StubEngine   ← 현재
                                      │           └─ GraphEngine  ← §6 그래프 완성 후
                                      │
                                      ├─ auth · pets ──ORM──► MySQL   (D-48)
                                      │    JWT · bcrypt        users · pets · chat_*
                                      │
                                      └─ SessionStore (메모리)  되묻기 슬롯. 휘발성이 의도다
                                                                다중 워커면 교체 필요 (§13)
```

> **기동 시 엔진을 만들고 임베딩 모델을 미리 올린다** (`lifespan` · D-53).
>
> | 순서 | 무엇 | 왜 |
> |---|---|---|
> | ① | `get_engine()` | **실패를 첫 요청까지 미루지 않는다.** `engine=graph` 인데 노드가 비면 여기서 크게 실패한다 (04 §8) |
> | ② | `engine.name == "stub"` 이면 생략 | **설정이 아니라 실제 엔진**을 본다 — 폴백(`ALLOW_ENGINE_FALLBACK=1`)까지 잡힌다 |
> | ③ | `serve.warmup=false` 면 생략 | 재시작이 잦은 개발용 스위치 (D-41) |
> | ④ | `warm_up(embedding_model)` | 서버가 로딩을 내고 **사용자는 안 낸다** |
>
> 워밍업 **실패는 기동을 막지 않는다** — 모델 없는 환경에서도 계약과 화면은 돌아야 한다.
> 대신 `/api/health` 의 `model_loaded=false` 로 드러낸다. 조용히 넘어가지 않는다.

> **엔진은 DB 를 모른다.** 프로필을 슬롯에 넣는 일은 `QAEngine` 안쪽의
> `load_profile` 노드가 하고(D-52), 라우터에만 넣지 않는다 —
> **라우터에 넣으면 평가 하네스가 같은 경로를 못 타** 지표와 실서비스가 갈린다.

> **화면보다 계약이 먼저다.** D-21이 *"UI는 가드레일 뒤"* 로 정한 것은 **화면**이고,
> 00 §9.3이 *"WS2와 사전 합의"* 를 요구한 것은 **계약**이다. 둘은 충돌하지 않는다.

### 12.1 API 계약

계약의 단일 출처는 `src/pettriage/app/contracts.py` 이며, OpenAPI 스펙은 `/docs` 에 노출된다.

| 엔드포인트 | 용도 |
|---|---|
| `POST /api/ask` | 질의응답. **항상 200**, `status` 로 분기 |
| `POST /api/records` | 다이어리 기록 저장 (조류는 배설물 상태 필드 별도) |
| `GET /api/report` | 기간 리포트 (구현 3단계) |
| `GET /api/triage-levels` | **등급 정의 + 도출 근거 원문** — 프론트가 등급 표현을 복사하지 않게 한다 |
| `GET /api/health` | 현재 엔진 (`stub` / `graph`) + **`model_loaded`** — 시연 전 콜드 여부 확인 (D-53) |

**`/api/ask` 의 3상태가 §9 정책을 그대로 반영한다.**

| `status` | 의미 | 필수 필드 | 화면 |
|---|---|---|---|
| `answered` | 근거를 찾아 판정했다 | `answer` · `triage` · **`citations` (비면 안 됨)** | 등급 배지 + 근거 + 감사 정보 |
| `clarify` | 슬롯이 비어 되묻는다 | `clarify` (`missing` · `turn` / **상한 2**) | 되묻기 대화 |
| `refused` | 근거없음 · 판정불가 | `refusal` (`reason` · `advice`) | 거절 + 수의사 상담 권고 |

> **거절을 4xx로 내보내지 않는다.** 거절은 장애가 아니라 §9가 정의한 정상 경로다.
> 4xx로 만들면 프론트가 에러 핸들러에서 처리해 **거절 화면이 장애 화면처럼 그려진다.**

### 12.2 계약이 강제하는 정책 — 지키기로 한 것이 아니라 못 어기는 것

| 불변식 | 위반하면 | 근거 |
|---|---|---|
| `answered` 인데 근거가 비었다 | **응답 객체가 만들어지지 않는다** | §9 · D-11 |
| `MONITOR` 인데 상승 조건이 없다 | **응답 객체가 만들어지지 않는다** | D-39 |
| 경로 ② 근거에 원문 인용이 실렸다 | **응답 객체가 만들어지지 않는다** | D-37 · §3 |

세 항목 모두 타입 수준 검증이며 회귀 테스트로 고정되어 있다.

**타입으로 막을 수 없는 것 하나 — 연락처 (D-47).** 문장 안에 섞여 나오는 전화번호·외국 기관명은
스키마가 잡지 못한다. 그래서 **`finalize` 노드가 출력 직전에 코드로 지운다** (§6.2).
`answered` 든 `refused` 든 예외 없이 통과하며, 지웠다는 사실은 `scrubbed` 로 남는다.

**감사 정보** — `answered` 응답은 `rule_level` · `llm_level` · `overridden` 을 함께 싣는다.
화면에 띄우지 않더라도 **하향 금지 게이트(§7.2)가 실제로 작동했다는 증거**가 로그와 데모에 남는다.

**`full_text`** — `answer` 만 읽는 클라이언트(챗봇·음성)를 위해 상승 조건과 고지 문구까지
붙인 완성 문장을 함께 내보낸다. **조건 누락은 이 도메인에서 과소평가와 같다.**

### 12.3 화면

| 화면 | 요소 | 상태 |
|---|---|---|
| 질의응답 | 질문 입력, **트리아지 등급 배지**, 상승 조건, 감사 정보 | ✅ 계약 + 데모 |
| 근거 보기 | 출처 기관·`source_id`·위치. **경로 ②는 인용문 대신 그 사실을 명시** | ✅ 계약 + 데모 |
| 되묻기 | 되묻기 회차(`n/2`)와 부족한 슬롯을 함께 표시 | ✅ 계약 + 데모 |
| 거절 화면 | 사유 + 수의사 상담 권고. **장애 화면과 구분되는 표현** | ✅ 계약 + 데모 |
| 기록 입력 | 자유서술 + 급여·증상. **조류는 배설물 상태 필드 별도** | ✅ 계약 · 적재는 WS1 대기 |
| 등급 기준 | 등급 4단계 + **도출 근거 원문** 노출 | ✅ 계약 + 데모 |
| 기간 리포트 | 타임라인, 급여 이력, 증상 추이, **병원 제출용 요약** | 계약만 (구현 3단계) |

**공통**: 고지 문구는 `status` 와 무관하게 응답에 항상 실리고, 화면 하단에 상시 노출된다.

### 12.4 미채택 — SSE 스트리밍

토큰이 흘러나오는 체감은 좋으나, **등급이 확정되기 전에 문장이 먼저 나가면
근거 검증 실패 시 이미 뱉은 문장을 회수할 수 없다.** 04 §4.1.0의 중대 과소평가율 0 목표와 충돌한다.
축② *"통제가 먼저, 배달이 나중"* 이 문장 단위에도 적용된다.

## 15. 2026-07-31 오후 개정 요약 — WS2·WS5 확인 필수

**배달 계층의 계약이 확정되었다 (D-40).** 화면보다 계약을 먼저 고정했으므로,
§6 그래프가 완성되기 전에도 WS5는 착수할 수 있다.

| | 이전 | 현재 |
|---|---|---|
| WS5 구현 방식 | 미정 (Streamlit / 웹) | **FastAPI + 정적 HTML, 같은 출처 서빙** |
| 계약 위치 | 없음 (화면 합의 예정) | `app/contracts.py` · OpenAPI `/docs` |
| 거절의 HTTP 상태 | — | **200** (`status="refused"`). 4xx 아님 |
| 정책 준수 방식 | 문서 합의 | **스키마 불변식** — 어기면 응답 생성 실패 |
| 엔진 결합 | — | `QAEngine` 프로토콜. 교체는 **주입 한 줄** |
| 등급 표현 출처 | 각자 하드코딩 | **`GET /api/triage-levels`** 단일 출처 |

> **WS2가 반드시 알아야 할 것**
> ① §6 그래프는 `QAEngine` 프로토콜(`ask(req, session) -> AskResponse`)에 맞춘다.
>   라우터·프론트·테스트를 고칠 필요가 없다
> ② `answered` 를 반환하려면 **근거가 반드시 있어야 한다.** 비면 응답 객체가 만들어지지 않으므로
>   근거가 없을 때는 `refused` 로 보낸다 (§9)
> ③ `MONITOR` 로 판정하면 **상승 조건을 함께 채운다.** 조건 없는 관찰은 과소평가로 채점된다 (D-39)

> **WS5가 반드시 알아야 할 것**
> ① 등급 이름·배지·행동 문장을 화면 코드에 적지 않는다. `/api/triage-levels` 에서 받는다
> ② 거절 화면을 **에러 스타일로 그리지 않는다.** 정상 경로다
> ③ 경로 ② 근거는 인용문이 없는 것이 정상이다 — 출처·위치로 역추적한다는 안내를 대신 띄운다

## 16. 2026-08-01~02 개정 요약 — **전원 확인 필수**

인덱싱과 배달 계층이 실제로 돌면서 **설계 문서가 예상하지 못한 것 세 가지**가 드러났고,
그 결과 §8.3(검색 파라미터)·§7.2(트리아지)·§9(되묻기)의 정책이 바뀌었다.

| | 이전 (7-31) | 현재 (8-02) | 결정 |
|---|---|---|---|
| 유사도 임계값의 역할 | **거절을 만든다** | **잡음 하한일 뿐.** 거절은 ①분류·④검증이 만든다 | **D-46** |
| `top_k` · `score_threshold` | 골든셋 튜닝 후 결정 | **5 · 0.50** (실측 확정) | D-46 |
| `rule_level` | 규칙 적중 → **등급 확정** | **바닥.** 적중해도 LLM 판정을 항상 받는다 | **D-50** |
| 되묻기 조건 | 슬롯 결측 · 종 미확인 | **+ 증상만 서술 · 물질 미상 서술** | **D-49** |
| 출력 마지막 단계 | ⑤ 평이화 → 응답 | **⑤ → `finalize`(연락처 제거) → 응답** | **D-47** |
| 검색 호출 | `search` → 임계값 | **+ `dedupe_by_substance`** (물질 중복 접기) | D-46 후속 |
| cross-lingual | (a)/(b) Recall@k 비교 예정 | **전제 소멸** — 청크가 전부 한국어 | §8.2 |
| 벡터DB | 후보 비교 중 | **Chroma 확정.** 계정·프로필은 별도 MySQL | D-44 · D-48 |
| 인덱스 | 미적재 | **888청크 적재 완료** (45출처 · 사실 표 888행) | §3.0 |
| `intent` 어휘 | `poison` | **`intoxication`** — 골든셋 27건이 이미 이 값이다 | 04a |
| 프로필 참조 | 그림에만 있었다 | **`load_profile` 노드 + 확인 되묻기.** pandas 금지 | **D-52** |

### 16.1 구현자가 반드시 알아야 할 것

> **① 유사도 점수로 거절 분기를 만들지 마라.**
> `score < threshold` 를 거절 조건으로 쓰는 코드를 넣으면 **근거 있는 질의를 대량으로 거절한다.**
> 실측에서 근거 있음(0.547~0.733)과 없음(0.494~0.659) 분포가 겹쳤다. 임계값은 하한일 뿐이다.
>
> **② 규칙이 등급을 냈다고 LLM 판정을 건너뛰지 마라.**
> `if rule_level: return rule_level` 은 D-50 위반이다. 규칙은 바닥만 안다.
> 항상 `max(rule, llm)` 으로 간다.
>
> **③ 증상 질의에 검색을 태우지 마라.**
> 답은 나오지만 **증상 목록이 겹치는 아무 물질이나** 근거로 붙는다.
> `intent == symptom` 이고 물질 슬롯이 비었으면 `clarify` 로 보낸다.
>
> **④ 연락처는 `finalize` 가 지운다. 프롬프트로 막았다고 생각하지 마라.**
> LLM은 *"Pet Poison Helpline 에 전화하세요"* 를 계속 쓴다. `answered`·`refused` 양쪽 모두
> `scrub_contacts()` 를 통과시킨다. **번호만 지우면 기관명이 남으므로 문장 단위로 지운다.**

### 16.2 아직 안 바뀐 것 — 오해 방지

- **하향 금지 게이트(§7.2)는 그대로다.** D-50은 게이트를 바꾼 게 아니라 `rule_level` 의 **의미**를 바꿨다
- **§12의 API 계약은 그대로다.** `status` 3상태·불변식·`/api/triage-levels` 모두 유효하다
- **경로 ①은 여전히 꺼져 있다** (D-45). 원문 청크 적재 0건
