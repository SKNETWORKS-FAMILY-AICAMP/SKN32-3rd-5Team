| 순서 | 작업 | 데이터 필요 여부 |
|---|---|---|
| 1 | 태스크별 프롬프트(`models/prompts.py`) 검토 — 실제 라벨링 프롬프트 설계 시 그대로 재사용할 수 있도록 다듬기 | ✕ |
| 2 | LoRA 하이퍼파라미터 후보군 정리 (r/alpha/dropout 탐색 범위) — `03` §9 미해결 항목 | ✕ |
| 3 | RTX 3080(10GB) 기준 `configs/train.yaml` 배치 설정 재산정 (batch_size·grad_accum·max_seq_len 조합별 예상 VRAM) | ✕ |
| 4 | 대형 LLM 라벨링 프롬프트 초안 작성 (①분류 태스크부터) | ✕ (설계는 가능, 호출 테스트는 API 키 필요) |
| 5 | zip 도착 → `scripts/verify_corpus.py`로 검증, 원문 확인 | ○ |
| 6 | ① 분류 태스크 라벨링 → 사람 검수 → `data/train/samples.jsonl` 작성 | ○ |
| 7 | 분류 태스크만으로 1차 학습 → 어댑터 산출 (`03` §8: "분류만 붙어도 시스템은 동작") | ○ |

> **단계적 접근 원칙**: 5개 태스크를 한 번에 만들지 않는다. 분류(①) 하나로 데이터 생성→학습→검증 파이프라인을 먼저 완주하고, 이후 태스크는 같은 파이프라인을 반복 적용한다.

## 4. 리스크 / 확인 필요 사항

- **RTX 3080 = 10GB VRAM.** `configs/train.yaml` 주석은 16GB 기준. 실 데이터로 `max_seq_len: 4096` · `batch_size: 2` 그대로 돌리면 OOM 가능성 있음 — 실 데이터 학습 착수 시 배치를 낮추거나 gradient checkpointing 적용 검토
- **대형 LLM API 키 미확보** — 라벨링 자체가 API 호출 기반이라, 키 없이는 6번 단계(라벨링) 진행 불가. 팀 내 확인 필요
- **`03` §9 잔여 미해결 사항**: ⑥ 번역 채택 여부, 4bit vs bf16 대조군, 태스크별 종별 데이터 비중, 검수 인력 분담 — 데이터 도착 후 결정 필요
