# 계산 노드 참조 테이블

**벡터DB에 넣지 않는다.** 정형 수치는 코드가 조회한다 (D-16).

| 파일 | 내용 | 어떻게 만드나 |
|---|---|---|
| `정량임계치.csv` | 트리아지 규칙 테이블 15행 | **생성물** — `python scripts/build_rule_table.py --write` |

---

## ⚠️ 이 파일은 손으로 고치지 않는다

```bash
# 틀린 값을 발견하면
vi data/facts/facts_ohb.csv                   # ← 여기를 고치고
python scripts/check_facts.py                 # ← 검사한 뒤
python scripts/build_rule_table.py --write    # ← 다시 만든다
```

**왜 이렇게 바꿨나** — 이전에는 `사실표_초안_정량임계치.csv` 를 사람이 따로 유지했고,
**마카다미아 0.7 g/kg 이 `임상징후 발현` 으로 잘못 적혀 있었다.**

> 원문은 *"the dose required to induce toxicity **has not been established precisely**"* 다.
> *"has been associated with"* 는 증례 서술이지 역치가 아니다.

사실 표에서는 `증례 보고 범위` 로 고쳤는데 초안 CSV는 그대로여서
**어느 쪽이 진짜인지 알 수 없는 상태**가 됐다. D-22의 단일 출처 원칙을 데이터에도 적용한다 —
사람이 쓰는 것은 `data/facts/facts_*.csv` 하나뿐이다.

편입 기준은 `ingest.templates.THRESHOLD_TYPES` 를 **그대로 가져다 쓴다.**
문장에 *"N 이상 섭취 시"* 로 나가는 것과 규칙 테이블에 들어가는 것이 어긋나면 안 된다.

## 읽을 때는 `compute.rules` 를 통한다

```python
from pettriage.compute.rules import computable_for, qualitative_for, has_quantitative

computable_for("초콜릿", "dog")   # 체중과 곱해 판정할 수 있는 행만
qualitative_for("백합", "cat")    # 정성 문장으로만 말할 수 있는 행
has_quantitative("초콜릿", "bird")  # False — 조류는 이 표에 0건이다 (D-09)
```

**이 CSV를 `csv.reader` 로 직접 열지 않는다.** 읽는 규칙이 네 가지 있는데
산문으로만 적어 두면 지나치기 때문이다 — 아래가 그 네 가지다.

| 지켜지는 것 | 안 지키면 |
|---|---|
| `computable=N` 을 계산에서 뺀다 | 잎 한 장의 무게를 우리가 정하게 된다 = 환각 |
| 범위·부등호를 **낮은 쪽**으로 읽는다 | `40-50` 을 50으로 읽으면 40 먹은 개가 "안전"이 된다 |
| 종을 넓혀 본다 (`dog` → `dog`·`mammal`·`all`) | 마늘(`mammal`)이 개 질의에서 안 걸린다 |
| 값이 같고 출처만 다른 행을 접는다 | 양파가 S-034·S-098 에 있어 근거를 두 번 센다 |

`tests/test_rules.py` 가 이 네 가지를 고정한다.

## `computable` 열을 반드시 볼 것

| 값 | 뜻 |
|---|---|
| `Y` (12행) | 단위가 `mg/kg`·`g/kg`·`%` — **체중과 곱해 판정할 수 있다** |
| `N` (3행) | 단위가 개수·비정형 — **계산 노드가 건너뛰어야 한다** |

```
⚠ F-098-008  백합          cat   1-2 leaves
⚠ F-098-006  소철(사고팜)    dog   2 seeds
⚠ F-030-010  주목          dog   2.3 g leaves/kg
```

원문이 *"one or two leaves"* · *"as few as 2 seeds"* 로만 말했으므로
**체중당으로 환산할 방법이 없다.** 잎 한 장의 무게를 우리가 정하면 그게 곧 환각이다.

> **`N` 행은 정량 판정을 하지 않고 정성 문장으로만 답한다.**
> *"백합 잎 1-2장으로 중독이 보고되었다"* 는 말할 수 있고,
> *"체중 4kg 고양이가 X g 먹었으니 위험"* 은 말할 수 없다.

주목은 단위가 `g leaves/kg` 라 체중당이긴 하나 **잎 기준**이다.
`g/kg` 로 읽으면 식물 전체 무게로 오독되므로 `N` 으로 뒀다.

## 역치를 넘으면 어느 등급인가 (D-50)

| 조건 | 바닥 등급 |
|---|---|
| `치사` 초과 | `EMERGENCY` |
| `중증` 초과 | `EMERGENCY` |
| **`임상징후 발현` 초과** | **`CALL_NOW`** ← 상향 여지를 남긴다 |
| 역치 미만 | `MONITOR` + `signs` 를 상승 조건으로 |

**`rule_level` 은 정밀한 판정이 아니라 바닥이다** — `final = max(rule, llm)` 이므로
LLM 은 올릴 수만 있다 (D-09). 그래서 `임상징후 발현`(9행, 75%)을 `CALL_NOW` 로 두어
**게이트가 작동할 여지**를 남겼다. `signs` 열이 있는 이유도 여기다 —
없으면 역치 미만이 전부 거절로 나간다.

```python
from pettriage.compute.rules import rule_level_for, to_mg_per_kg
rule_level_for("초콜릿", "dog", to_mg_per_kg(30, "mg/kg"))   # → CALL_NOW
```

**출처가 어긋나면** — 같은 (물질 × 종 × 역치종류)에서 최대/최소가 **10배 이상** 벌어지면
정량 판정을 포기하고 `level=None` 을 돌려준다. 건포도가 본문 `2.8 mg/kg` ·
표 `2.8-36.4 g/kg` 로 1,000배 어긋나는 사례가 실재한다.

## `threshold_type` — 편입되는 것과 아닌 것

| 편입 | 안 됨 |
|---|---|
| `임상징후 발현` · `중증` · `치사` | `증례 보고 범위` · `성분 함량` · `역치 없음` · `기타` |

**`증례 보고 범위` 는 역치가 아니다.** S-034 Table 1의 캡션이
*"Range of doses … **reported to cause**"* 이고, 실제로 용량-반응이 역전한다
(포도 3 g/kg 사망 vs 20.6 g/kg 회복).

**`역치 없음`** 은 원문이 용량-반응 미성립을 명시한 경우다 — 포도가 여기 해당한다.
이 물질은 정량 판정을 하지 않는다.

## 알려진 함정

- **건포도 단위** — S-034 본문은 `2.8 mg/kg`, 같은 논문 Table 1은 **같은 참고문헌**을
  `2.8–36.4 g/kg` 으로 적는다. **1,000배 차이**다. 환산·선택하지 않고 두 행 모두 남겼다
- **HCN 기준 수치** — 남천·체리로렐의 `2-2.5 mg/kg` 은 **시안화수소 치사량**이지
  식물의 체중당 섭취량이 아니다. 식물 내 HCN 함량을 모르면 환산할 수 없어
  `threshold_type=기타` 로 내려 편입에서 뺐다 (2026-08-01 검수)
- **양파가 두 출처에 중복** — `F-034-001/002`(S-034)와 `F-098-001/002`(S-098)가 같은 값이다.
  계산 노드가 **중복 히트를 하나로 접어야** 한다
- **조류는 이 테이블에 한 행도 없다.** 코퍼스에 쓸 수 있는 조류 체중당 역치가 없다 (D-09)
